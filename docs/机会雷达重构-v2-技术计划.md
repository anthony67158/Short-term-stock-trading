# 机会雷达重构 V2 技术计划

> 依赖：`docs/机会雷达重构-v2-规格.md`
> 状态：Implemented

## 架构

保留现有板块、盘中公式、收盘公式和尾盘公式生产器，只重构确定性聚合层与前端信息架构：

```text
板块快照 ────────> 方向校验/标签
盘中公式 ────────> 盘中机会
尾盘公式 ────────> 盘中机会 / 尾盘反转区
收盘公式 ────────> 次日关注计划
```

选股能力按独立层演进：

```text
召回层：确定性公式，多策略并行，不互相覆盖
  -> 特征层：市场、板块、量价、资金、流动性、拥挤度
  -> 排序层：pFill / pWinGivenFill / expectedNetR
  -> 风控层：价格合同、T+1、涨跌停、账户与组合预算
  -> 结算层：所有候选按真实可成交路径成熟结算
```

## 实施顺序

### 1. 聚合合同

- 将 `intraday` lane 限制为当前交易日盘中公式与当前交易日尾盘结果。
- 将 `next` lane 限制为当日收盘公式。
- 停止从板块成分股直接创建 `SECTOR_WATCH` 候选。
- 保留板块映射用于方向资格、排名和展示标签。
- 交易时段拒绝昨日收盘/尾盘结果；盘前允许上一交易日计划。
- 今日手动尾盘结果优先于昨日正式版，今日正式版生成后再覆盖手动结果。

验证：`test/opportunity-radar.test.js`

### 2. 客户端调度

- 盘中主刷新只并行运行板块盘中快照与盘中公式。
- 尾盘区使用独立手动扫描动作。
- 次日计划仅在收盘后允许手动运行板块收盘版与收盘公式。
- 根据来源的 `refreshAt / refreshAfterMs` 在关键时点自动重新读取。

验证：`test/opportunity-radar-ui.test.js`

### 3. 前端重组

- 顶层页签从三个收敛为两个。
- 盘中页拆为三个无嵌套区段：
  - 可立即买入
  - 今日提前布局
  - 尾盘反转
- 次日页只展示收盘公式计划和收盘后生成入口。
- 删除“方向观察”区和相关计数。
- 尾盘严格结果为空时默认展示接近公式列表与明确限制。

验证：源码契约测试、桌面与移动端浏览器截图。

### 4. 定时器

- 保留 `tail-pick-1450-timer` 与 14:52 失败重试。
- 从 `s.yaml` 移除 `formula-selection-close-timer`。
- 保留服务端定时事件解析函数，避免兼容路径突然失效；生产部署不再挂载该触发器。

验证：`test/fc-alert-schedule.test.js`、`test/advice-timer.test.js` 及配置源码断言。

### 5. 回归与部署

- 运行全量单元测试。
- 运行全部离线 Harness。
- 完成 Vite 构建。
- 部署 Vercel 与阿里云 FC。
- 使用测试账号只读检查：
  - 盘中页不含昨日候选。
  - 尾盘结果日期为今天。
  - 次日计划只含当日收盘后手动结果。

### 6. 策略能力增强

不在 UI 重构中直接上线未经验证的新策略。按以下顺序进入影子链路：

1. 新增 5–30 分钟订单失衡延续特征。
2. 新增 60–120 分钟过热反转风险特征。
3. 增加流动性复合特征：成交额分位、换手分位、Amihud 类代理、日内量能持续性。
4. 增加板块与同业相对强度差，作为公式候选条件变量。
5. 增加涨停频率、封板失败和临近涨停拥挤惩罚。
6. 公告与事件催化只进入证据和排序特征，不直接生成候选。

每个新增策略先进入全候选账本和影子评分，不改变线上排序。达到样本门槛后按独立 ablation 比较：

- 规则基线。
- 规则 + 单一新策略。
- 规则 + 全部新特征的 LightGBM。
- 规则 + DoubleEnsemble 候选。

晋级按 `Precision@3/5`、NDCG、Brier、LogLoss、扣费后期望 R、最大回撤共同决定，不以训练集准确率或单次最优回测决定。

## 风险

| 风险 | 处理 |
| --- | --- |
| 删除方向候选后列表变少 | 空结果如实展示，不用无价格合同股票凑数 |
| 尾盘严格命中为 0 | 独立显示接近公式，但明确不可直接买入 |
| 收盘后用户忘记生成 | 显示醒目的“尚未生成”状态，不自动产生付费或重任务 |
| 页面挂后台错过 14:50 | 使用绝对时点定时刷新，不依赖 `document.hidden` |
| 老数据跨日污染 | 聚合层按 lane 校验 source tradeDate 后再进入列表 |

## 回滚

- 原生产器和 OSS 路径不变。
- 旧 `layout` lane 可暂时保留在 API 中用于兼容，但 V2 UI 不再展示。
- 如需回滚，仅恢复前端三页签与原 lane 组合，不涉及数据迁移。
