# 短线作战系统升级方案

日期：2026-09-08

状态：用户已确认整体产品规格，剩余改造实施中；已完成纠错，见最后一节。
本文是完整方案，不是已交付声明。既有三工作区升级记录保留在
`docs/system-upgrade-20260908.md`，不覆盖历史验收结果。

## 1. 产品目标

从“你阅读多个模块后自行拼出操作”变为“系统整理成唯一指令，你核对后执行”。
“无脑辅助”的含义是低认知负担，不是无条件买入、自动下单或保证盈利。

你日常只需要完成三个动作：

1. 看作战页，知道今天是否可以新增风险、现在最该处理什么。
2. 提醒出现时核对股票、价格、手数和最大计划损失，到券商手动下单。
3. 将实际成交价和数量记回系统，由系统接续持仓管理与费后复盘。

系统承担选股排序、账户预算、条件监控、时机判断、状态同步和证据整理。
不要求用户理解模型角色、任务队列、策略枚举、多个置信度或反复点生成。
没有合格机会时明确“今天没有可执行买点”，不为了产出动作而放松风险规则。

## 2. 已核实的问题

| 问题 | 证据位置 | 影响与处理 |
| --- | --- | --- |
| 主入口虽为三个工作区，默认首页仍是市场盘面、情绪、雷达、涨停池 | `src/components/TodayTab.jsx` | 用户先读背景再找动作；改为待办指令优先，背景按需展开 |
| “今日作战指令”计算函数没有任何调用点 | `src/planStore.js:todayCommandList` | 上一轮没有真正接通首页；建立由现有决策生成的共享指令投影 |
| 待执行队列、持仓卡、自选卡、仓位诊断各自表达动作 | `ExecutionQueue.jsx`、`PlanTab.jsx`、`AccountTab.jsx` | 同股可能出现不同文案与操作入口；统一计划版本与主动作 |
| 整十手数被识别成零手 | `shared/adviceActionView.js:quantityText` | `/0\\s*手/` 会误匹配 10/20/30/100 手；已用最小用例复现并修复 |
| 策略估算覆盖服务端核定手数 | `shared/adviceActionView.js:buildAdviceActionView` | 核定 3 手可显示成 21 手；已改为核定计划优先 |
| 前端与战术层仍有独立手数计算和默认 3% 止损 | `adviceActionView.js`、`shortHorizonTactical.js` | 可能绕过组合预留与仓位约束；整体升级中取消前端定价定量 |
| 降低确认阈值没有通过系统级回归 | `shared/confirmPolicy.js`、Harness | 低置信度买入被错误确认；恢复既定分级，禁止按“多出信号”调门槛 |
| 普通后台巡检和到价确认对用户都表现为复核 | `adviceUiState.js`、`cron_advice.js` | 用户误以为系统一直犹豫；区分静默检查、一次判断、明确终态 |
| 快速模式失败仍存在构造兜底建议的出口 | `api/ai.js:shouldBuildAdvisorFallback` | 服务失败与投资结论混淆；新生成失败保留上一版，展示失败，不制造新建议 |
| 实时分析仍多处截断 | `_zh_reason.js` 20 条/320 字，`_jobs.js` 6000 字 | 扩大长度不等于完整展示；摘要与供应商提供的可见分析分开保存和展示 |
| 既有验收偏重局部测试或 HTTP 200 | 本轮全量测试与生产检查 | 200 可能只是授权页；必须验证真实 UI、任务、OSS 结果和人工成交链路 |
| 本地 UI 夹具建议已过期，原检查仍能在无建议状态通过 | `test/ui/system-upgrade-preview.jsx` | 本轮更新测试时点与必要字段，加入真实卡片数量断言 |

基线：本轮修改前 Node 测试 2019/2022 通过，Harness 51/52 通过。
3 项失败中 1 项是卡片旧文本断言，2 项与确认策略回归有关。
不存在“模型通常达不到 78 分”的已验证统计证据，不能据此降低门槛。

## 3. 信息架构

保留三个主入口，不再新增业务大页：

| 入口 | 默认内容 | 收起的次级内容 |
| --- | --- | --- |
| 作战 | 账户与市场边界、现在处理、到价等待、今日精选 | 大盘全景、情绪、行业、涨停池、日报、完整雷达 |
| 持仓 | 全部持仓与自选、同源当前指令、真实成交记录 | 仓位诊断、做 T、批量生成、复核名单、成本维护 |
| 复盘 | 当日真实费后盈亏、执行偏差、未完成计划 | 历史预警、模型效果、来源统计、长期图表 |

模型配置、搜索设置和量化报告留在账号工具中。不会删除自选、历史交易或研究能力。
旧 URL、预警深链接和移动返回保持兼容。

### 作战页固定顺序

1. **一条状态带**：交易时段、数据时点、可用现金、已预留现金、当前仓位、
   当前是否允许新增风险。任一关键证据异常直接点名。
2. **现在处理**：已确认止损/退出优先，其次已确认减仓，再是已确认买入/加仓。
   所有持仓风险必须完整展示，不受精选数量限制。
3. **到价等待**：已纳入作战的计划，展示触发价、估算手数、离触发条件还差什么。
   后台检查不作为红色待办，不抢占“现在处理”。
4. **今日精选**：默认最多展示 3 个可解释的候选，允许 0 个。
   全量市场仍完整扫描，3 个只是界面展示限制，不截断参与筛选的股票。

进入页面不自动调用付费模型。新候选只提供发现依据，不冒充账户已获准买入。
选择“纳入作战”时明确本次授权范围：生成该股计划并跟踪该计划的到价事件。
不自动为全部自选开启持续 LLM 复核，不重写用户已有名单。

### 单条指令

主行固定回答：**哪只股票、现在做什么、什么价、多少手**。
第二行：计划止损损失、到期时间或剩余条件。
一个主要动作：“记录实际成交”或“查看触发条件”；“不执行本次计划”为次操作。
展开后才看依据、压力情景、资金序列、概率含义和完整历史。
不执行或被阻断状态不突出“手动建仓”作为推荐按钮；记录已经发生的自主成交
仍从交易记录入口可达，不能把记账能力误包装成系统建议买入。

示例只作界面合同，不是投资建议：

```text
演示股票  买入 2 手  10.00-10.05 元
计划止损 9.70 元 / 含费计划损失 约 X 元 / 有效至 10:35
为什么：触价后已站稳均价线，主力资金未转弱
记录实际成交
```

条件计划必须写“预案最多 X 手，尚未授权执行”，不能写成“现在买 X 手”。
缺少真实账户或止损等必要输入时显示明确缺项，不使用假默认价凑手数。

## 4. 唯一决策与责任边界

继续使用 `decision-plan.v2`、`advice-price-contract.v1`、
`execution-plan.v1` 和现有证据快照，不新增第二套决策引擎或数据库。

```text
市场与机会证据
    -> 用户纳入作战
    -> 一次军师判断
    -> 服务端价格、数量、费后期望和账户约束编译
    -> 保存成功的当前计划
    -> 规则盯价
    -> 一次到价确认
    -> 人工真实成交
    -> 持仓接续与费后复盘
```

职责必须唯一：

- 雷达回答“值得关注谁”，不直接发布账户交易指令。
- 军师解释事实并提出计划，不拥有现金、手数或交易状态的最终决定权。
- 服务端确定性编译器校验价格、账户、费用、风险和有效期。
- 到价验证只回答“原计划此刻执行还是结束”，不重跑完整选股逻辑。
- 前端只将权威合同转为中文视图，不重新估算交易价格或放大手数。
- 人工成交是改变实际持仓和已实现收益的唯一事实来源。

同股主指令优先级：
真实成交/已完成状态 > 当前版本的有效退出风险 > 当前版本执行决定 >
当前有效条件计划 > 无有效建议。过期、失败或旧版本任务不得覆盖当前结果。
同股存在买卖冲突时进入一个明确“计划冲突”状态并解释，不同时给两条可执行指令。

## 5. 状态与复核

用户只看到六种过程状态：待机会、待触发、到价确认中、可执行、已结束、数据异常。
“继续持有”和“不买入”是动作结论，不冒充正在进行的模型任务。

| 状态 | 进入条件 | 离开条件 |
| --- | --- | --- |
| 待机会 | 无完整可执行合同 | 用户生成，或明确新事件形成计划 |
| 待触发 | 有效条件计划，尚未满足触发条件 | 到价/到期/取消/交易事实改变 |
| 到价确认中 | 当前计划首次触发 | 最多一次模型判断，或硬截止 |
| 可执行 | 条件、账户和终局判断通过 | 真实成交、用户放弃、计划过期或新硬风险 |
| 已结束 | 不执行/失效/已完成/已取消 | 新计划版本或新实质事件，不按原价无限重开 |
| 数据异常 | 行情、账户、模型、存储故障 | 明确恢复；失败本身不是投资结论 |

### 减少“永远复核”

- 普通定时检查先做确定性证据比较。没有实质变化时不调用模型，不弹提示，
  只更新“最近检查时间”。现有 `evaluateScheduledReview` 已有基础，继续收敛而非另造调度器。
- 观察价首次命中保留约 60 秒路径观察，唯一一次模型预算最多 45 秒，
  触发总窗口最多 120 秒；硬止损使用现有确定性保护，不等待普通买入分析。
- 复核终态只能是执行、不执行或计划失效。超时显示“本次确认失败，未授权新增风险”，
  不伪装成模型成功作出的保守建议。
- 两条观察路径属于同一计划，先触发的一条获得处理权；同版本不并发循环生成。
- 再入场需要新的实质事件和稳定事件标识：价格重新穿越并站稳、资金关系变化、
  交易事实变化等；单纯过了 N 分钟或在同价附近抖动不是新事件。
- 页面刷新、设备切换、FC Worker 重启不增加同事件的模型调用次数。
- 复核结束直接发布可执行区间与最终手数，不能要求用户再点一次生成来获知数量。

LLM 的自报置信度不是经校准的胜率。保留现有 78/70/65 分级和强止损覆盖。
未来阈值变动必须有独立时段的可成交率、费后净 R、回撤和基线对照，不以动作数量为指标。

## 6. 数量、期望与风险

把 `decisionPlan.js` 的已有限额计算作为服务端唯一执行数量口径。
`shortHorizonTactical.js` 只表达方向和风险档，不再独立向前端发布另一套权威手数。
条件计划可增加只读的预算预览字段，但必须复用同一计算器，不能由 UI 另算。

最终手数取下列约束的最小值，并按 100 股一手取整：

- 当前可用现金扣除现金储备、费用和未成交买入预留。
- 单票、行业/题材、总仓位的剩余空间。
- 含费止损损失与账户剩余风险预算。
- 当前试仓档位上限，试仓最多总资产 5%。
- 加仓已有持仓的市值和风险占用。
- 卖出只使用今日可卖数量，遵守 T+1。

未成交卖出不释放现金。同批候选按确定顺序消耗同一预算，不能每只都用全账户现金。
预案预算不是现金预留；进入有效执行队列的买入计划按既有语义预留，
包括 ARMED、ALERTED、USER_CONFIRMED 和 PARTIALLY_RECORDED 的剩余未成交部分。
触价后账户改变时重编译数量；数量减到 0 必须说明具体不足项。

新增风险必须有可核验的价格、正确方向的止损与目标、至少 1.8:1 的盈亏比，
并通过现有费后正期望、关键证据与账户约束。未知、估计、已校准分别标记，
不能用 LLM 置信度替代成功概率，也不能将缺失数值当作 0。
减仓、退出不受新增风险门槛反向阻挡。

止损价不保证成交。默认显示计划损失，详情同时给出压力情景损失及 T+1/跳空/跌停限制。
“已确认人工计划”与“已在券商成交”必须保持分离，但界面只保留一处成交记录入口。

## 7. 可追溯与失败处理

每条指令串联已有标识：选股来源、证据快照、计划 ID/版本、触发事件、
复核任务、执行计划、人工成交 ID、归因记录。详情用时间轴查看，不新增主导航。
只有真实完整且已核验的费后结果进入效果学习。

每次变化记录：何时、发生了什么事实、原动作、新动作、原因、价格数量变化。
旧证据不得被新价格覆盖成“当时已经知道”。

服务错误统一分层：

| 故障 | 用户可见结果 | 系统行为 |
| --- | --- | --- |
| 行情/资金缺失 | 点名缺少数据和数据时点 | 停止新增风险判断，保留有效硬防守 |
| 模型超时/限流/不完整 | 本次生成失败 + 可读原因 | 不制造新成功建议，不重跑已经开始的完整题目 |
| OSS 保存失败 | 本次结果未保存 | 不把未持久化结果升为当前计划 |
| Worker 失联 | 明确任务失败/可恢复准备阶段 | 按是否已开始模型区分，不假排队、不重复推理 |
| 旧建议过期 | 已过期，不执行旧买点 | 保留历史依据和仍需执行的硬防守事实 |

实时进度只展示真实阶段与供应商提供的可见分析。
“摘要”与完整可见分析分开，截断必须标记；不声称取得供应商未提供的内部思维链。
无需为了中文翻译或整理正文再调用第二个模型。

## 8. 代码与性能

保持 React 18 + 当前 Vite 8、Node ES modules、OSS、FC 单后端和双前端入口。
不迁移 Next.js，不增加微服务、消息总线、新状态管理或模型角色。

| 层 | 收敛方式 |
| --- | --- |
| `shared/decisionPlan.js`、账户预算 | 唯一价格/数量/风险编译，条件预算和执行预算同源 |
| `shared/adviceActionView.js` | 纯展示投影，取消前端定价定量；接入到期、终态和核定手数 |
| `src/planStore.js` | 交易事实与执行状态；指令选择器可注入时间和行情 |
| `api/ai.js`、`cron_advice.js` | 一次生成、真实失败、角色隔离、保存后发布 |
| `shared/adviceIntelligence.js`、`_jobs.js` | 静默检查和实质事件分离；稳定幂等标识 |
| `TodayTab.jsx`、`PlanTab.jsx`、`ExecutionQueue.jsx` | 复用一个指令呈现与成交入口，主链不显示两套队列 |
| `App.jsx`、`appShell.js` | 三入口语义调整，旧路径兼容；研究按需加载 |

不按文件长度机械拆代码。只拆重复决策、跨层状态判断和可独立测试的视图，
不做全仓库改名或格式重写。日常页面不加载无关研究图表和大型表格。
行情轮询复用当前订阅，不为新首页再开一组相同请求。

代码风格沿用现有具名导出、纯函数、可注入时间和空值防护，例如：

```js
export function currentCommand({ plan, event, now = Date.now() }) {
  if (!plan) return { state: 'EMPTY', planId: null }
  return projectCurrentPlan(plan, event, now)
}
```

该示例只说明边界，不要求新增同名抽象。

性能目标分开计量，不作未测试的保证：

- 页面使用已有数据时，指令排序和状态更新不等待任何模型。
- 关键操作 100ms 内呈现受理状态；网络受理超时明确报错且不重复提交。
- 快速生成沿用 55 秒目标；到价窗口沿用 120 秒硬截止。
- 深度模式退出主按钮，不在本轮盲改现有 300 秒模型/360 秒总预算。
- 收集各阶段耗时、失败率、模型调用次数，再决定性能优化；不靠假成功降低延迟。

## 9. 分段实施

规格确认后按以下依赖顺序执行，每段保持可构建、可回退，不一次性全站重写。
任务拆成最多约 5 个实现文件的可验证小段，测试文件随各段提交。

| 阶段 | 工作包 | 验收条件 |
| --- | --- | --- |
| P0-A | 修复整十手数、核定手数优先与确认阈值回归 | 本轮已开始；新增反例先失败再通过，原 Harness 基线不修改 |
| P0-B | 服务端统一条件预算，前端取消假默认价与独立手数 | 卡片/详情/预警/成交入口数量一致；缺项不造价；0 手原因明确 |
| P0-C | 新生成失败与投资结论分离 | 快速与深度失败均不覆盖上一版，不出现虚假 done |
| P1-A | 当前指令投影及优先级 | 同股同版本唯一主动作；交易时段、到期、T+1 和冲突正确 |
| P1-B | 接入作战首页，研究下沉 | 首屏先看到待办；零机会可用；紧急退出不被 Top-3 隐藏 |
| P1-C | 持仓和执行队列共用指令入口 | 一处记录真实成交；部分成交、余量、预留和跨设备状态一致 |
| P2-A | 静默检查与新事件识别 | 无变化不调用 LLM；无效触价结束；新实质事件可再次评估 |

## 12. 2026-09-09 核心决策改造与验收

### 核心规则

- 风控核定结果回写操作正文、手数、金额、触发价和复核终态，模型申请量不再与执行量并存。
- 条件预算与执行预算同源；扣除待买预留、费用、滑点、账户及行业剩余容量后核定。
- 除毛盈亏比外检查净盈亏比至少 1.8；明确目标触及概率不得冒充止损前盈利概率。
- 风险拦截基于结构化字段，不依赖中文解释中是否出现固定词语。
- 账本止损不能被模型下移；确认深破与第五交易日时间退出受 T+1 可卖数量限制。
- 即时指令不跨午休，隔夜预案按交易日历到期；过期/完成计划不得从缓存恢复为可执行。
- 同计划双路径触价只进入一次复核；结果保存后才能推终局通知，无法核验最新账本则不发布。
- 模拟账户成交不能进入真实收益学习。
- 当前风险变化阻断旧买入，仍保留同状态下已核定的弱市小仓例外，不阻断退出与成交补录。
- 刷新缓存首屏发生编辑后，延迟云端快照不再整份覆盖本地，保存仍受真实账本版本检查。
