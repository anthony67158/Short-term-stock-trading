# 原系统恢复与模型/Agent 增量接入方案

状态：`In Review`
决策者：平台所有者
最后更新：2026-09-17
适用范围：`www.tedixtf.cn` 原交易工作台、当前仓库与现有模型/Agent 实验代码
事实基线：旧系统固定提交 `d6d5d5c^`；当前工作树 `rebuild/platform-v1`
替代：`docs/rebuild/` 中“全面重建、旧系统不再接入”的产品与架构决策

## 执行结论

恢复原有“短线操盘台”作为用户产品和交易工作流基线，不再以当前 Python/PostgreSQL
重建工作台替换原前端、原账户、原交易录入、原预警和原复盘链路。

当前模型训练、量化评估、联合决策和 Agent 研究能力保留为独立计算能力，但只能通过
稳定适配层向原系统输出结构化建议、证据、置信度和不可用状态。它们不得重写原系统
的账户快照、成交、计划、T+1 批次或手工执行流程。

本次恢复不是把删除前约 1,300 个文件无差别回灌，也不是让两套产品 UI 同时存在。
恢复以原系统提交中的运行入口、账户合同、交易流程和对应测试为准；当前重建 UI 和
没有消费者的重复运行时会在替代验收后删除。

## 问题定义与当前状态与证据

### 当前情况

- `d6d5d5c` 将原 Node/React/FC/OSS 工作台、量化服务、任务与测试整体移出工作树；
  删除规模约 1,300 个文件、37 万行。
- 当前产品改为 React/TypeScript + FastAPI + PostgreSQL 工作台，一级导航、账户模型、
  登录、部署方式和用户操作路径均已改变。
- 当前仓库同时保留了可复用的模型训练、分钟数据、联合包、Agent 研究与持仓动作实验；
  这些能力尚未以原系统合同对外提供。
- `www.tedixtf.cn` 已恢复原工作台入口；按产品决策移除独立设备授权，仅保留账户登录。

## 目标与非目标

### 目标状态

用户继续使用原有“市场与选股、交易与持仓、复盘与改进”的页面、账户与人工成交
流程；模型与 Agent 在原有候选、个股详情、持仓建议、预警复核和复盘位置提供额外
指导，而不是把用户迁移到另一套工作台。

### 核心约束与不变量

- 不自动下单；用户仍在券商端人工确认成交。
- 原账户、持仓、已平仓、计划、预警、执行归因和 OSS 历史快照不得被新服务覆盖。
- 计划不等于成交；T+1、费用、批次和人工成交逻辑保持原业务语义。
- 模型或 Agent 不可用时明确显示不可用，不以公式或旧分数伪装新预测。
- 模型、Agent、市场事实和人工交易事实分开保存；新计算服务只读原交易账户数据。
- 密钥、会话及生产账户密码不进入仓库、文档、浏览器日志或测试夹具。

### 非目标

- 不把旧 OSS 账户快照批量迁移为当前 PostgreSQL 账户事实。
- 不立即启用当前重建平台的真实账户写入或让两套系统双写同一账户。
- 不恢复已经确认无消费者、重复部署包、缓存、模型二进制或历史构建产物。
- 不把尚未通过样本外门禁的联合模型发布为交易动作。

## 用户/场景与产品设计：原系统产品基线

以下结论来自旧系统 `README.md`、`src/App.jsx`、`api/account.js`、`api/ai.js` 与
旧部署配置，属于已核验的恢复范围。

| 用户工作区 | 原有关键能力 | 恢复要求 |
|---|---|---|
| 市场与选股 | 市场概览、机会雷达、板块/个股研究、候选来源 | 原页面和导航恢复；新模型只补充候选排序与预测卡片 |
| 交易与持仓 | 建仓/加减仓/清仓/做 T、持仓、执行队列、预警、T+1、费用、FIFO | 原账户合同与页面优先；新服务只提交建议草案和复核结果 |
| 复盘与改进 | 真实交易归因、策略日报、持仓复盘、结果沉淀 | 原复盘对象保留；新服务补充模型版本、Agent 证据和对照指标 |
| 账户与设备 | 昵称密码、OSS 快照、跨设备同步、主题/PWA | 移除设备授权；旧账户认证和账户同步保持唯一日常身份入口 |
| 研究助手 | 个股/板块/市场检索与后置解释 | Agent 继续使用有界输出，引用模型和市场快照，不直接改变动作 |

原系统的主业务对象是 `plan`、`holding`、`closed`、`account`、`alerts`、
`executionPlans`、`executionAttributions`、`reviews` 与 `settings`。这些对象以
OSS 当前快照和版本/指纹控制为事实源。当前重建系统的 PostgreSQL 账户仅是一次迁移
验证的副本，不是原系统恢复后的账户写入目标。

## 目标架构

```text
原 React 工作台 (src/)
  ├─ 原 Node/FC API (server.js + api/)
  │    ├─ OSS：账户、设置、执行、历史快照 [唯一交易事实写入方]
  │    ├─ 市场数据与原预警/任务流程
  │    └─ Model-Agent Adapter
  │          ├─ 读取只读账户/行情快照
  │          ├─ 调用 Python 模型/Agent 服务
  │          └─ 写入带版本的建议、证据和不可用状态
  └─ 原页面在既有位置展示指导结果

Python model-agent service (保留并收敛)
  ├─ 市场数据、特征、训练、回测、模型包
  ├─ 联合模型 + Agent 评估
  └─ 仅输出 versioned recommendation contract
```

### 适配合同

原系统向模型/Agent 服务发送：

- `accountSnapshot`：只读、脱敏的现金、持仓批次、未完成计划和风险约束；
- `marketSnapshot`：带 `asOf` 的价格、分钟/日线、市场及板块状态；
- `requestScope`：`candidate`、`holding`、`review` 或 `explain`；
- `idempotencyKey` 和原系统对象版本。

模型/Agent 服务返回：

- `availability`：`READY`、`UNAVAILABLE`、`STALE`、`FAILED`；
- `modelVersion`、`agentRunId`、输入时间与证据水位；
- `rank`、`pWin`、`pFill`、`q10/q50/q90`、风险和建议动作；
- `rationale`、`counterCase`、`evidenceRefs`；
- `validUntil`、`limitations` 和不可用原因。

适配层负责把结果映射到原 `advice`、`decisionLog`、`executionPlans` 或预警复核的
展示字段。只有原系统既有人工确认/成交流程可以写入 `holding`、`closed` 和现金。

## 备选方案与决策：恢复与清理

### 必须恢复

1. 根目录 Node/Vite 工程、`src/`、`api/`、`shared/`、`server.js`、`s.yaml`、
   `vercel.json` 和原测试/Harness。
2. OSS 账户认证、账号快照读写、交易记录、执行计划、预警、复盘与跨设备同步。
3. 原部署双入口：`www.tedixtf.cn` 与 Vercel 静态入口使用同一前端构建版本。
4. 原量化服务中的可复用模型服务接口，但不恢复历史模型二进制和重复部署产物。

### 保留并改造为服务

- 当前 `backend/src/platform_app/modules/experiments/` 的数据集、训练、回测和联合包；
- 当前 Agent 研究、联合仲裁、持仓动作实验；
- 当前可靠的市场数据适配、分钟数据审计和 Python 交易规则实现。

它们迁入或暴露为 `services/model-agent/` 的单向计算服务。迁移前不删除原代码。

### 候选删除项

仅在恢复后的工作台通过对应回归用例、并确认没有生产调用后删除：

| 类别 | 候选 | 删除门禁 |
|---|---|---|
| 重建 UI | `apps/web/` | 原 UI 在两条生产入口加载、登录和三工作区验收通过 |
| 重建 API 外壳 | 当前 FastAPI 路由和 PostgreSQL 账户 API | 原 OSS 账户和人工成交流程恢复，模型适配服务已替代其仅有消费者 |
| 重建部署外壳 | `infra/deploy/`、新 FC/Vercel 转发配置 | 原 `s.yaml` 双入口部署、健康检查和回滚演练通过 |
| 重复实验代码 | 与最终 `services/model-agent/` 重复的实验入口 | 固定服务合同、回测与训练命令迁移并通过 |
| 生成物 | `.runtime/`、临时包、缓存、模型副本 | 可从源码/受控模型仓库重建，且无运行实例引用 |

不把“大文件”“旧文件”“当前未打开”作为删除依据。

## 优先级

1. P0 与 P1优先恢复原用户工作台、OSS账户合同和人工交易事实。
2. P2仅在原工作台通过关键合同后接入只读模型/Agent适配器。
3. P3最后切换生产入口，并以零消费者证据清理重复运行时。

## 里程碑：分阶段实施

### P0：冻结与盘点

- 禁止继续对重建 UI、生产账户和部署做不可逆删除。
- 固定旧系统提交、导出文件清单、记录当前未提交模型实验改动。
- 将本文件和新的工程规则设为后续开发唯一依据。

退出条件：可复现旧系统源代码；当前模型实验工作未丢失。

### P1：原系统可运行恢复

- 从 `d6d5d5c^` 恢复 Node/Vite/FC/OSS 工作台和测试。
- 不覆盖现有 Python 实验目录；将其保持为未接入的计算候选。
- 在本地使用合成账户启动原页面与 API，验证登录、行情、交易录入、持仓、复盘。

退出条件：原工作台本地运行，关键合同测试通过；不接入真实账户写入验收。

#### 2026-09-17 恢复验证记录

- 已恢复 Node/Vite/FC/OSS 工作台、共享交易合同、Harness 与原测试入口；当前
  Python/PostgreSQL 实验目录仍保留，未作为账户事实写入方。
- `npm run test:ci` 通过 `2441/2441`，`npm run build` 通过。高波动突破路径的

### P2：模型/Agent 适配器

- 定义并测试 `recommendation.v1` 合同。
- 实现原 Node API 到 Python 服务的只读调用及结果缓存。
- 在候选、持仓与复盘页面以“新模型/Agent 指导”并列展示，默认影子模式。
- “生成决策”“更新决策”、批量更新与触价复核统一进入同一联合链路；训练模型和
  Agent 任一不可用时均返回不可用，不保存旧结果或公式替代结果。
- Agent 只补充依据、最强反方、复核逻辑、失效条件和证据局限，不得改写组合引擎
  已核定的动作、价格、手数和风险边界。
- 选股公式、质量底线和官方事件只负责召回候选；候选进入可执行状态前，必须由
  `opportunity-agent-selection.v1`在同一候选批次内比较量化费后期望、市场资金、
  板块资金、个股资金、官方公告与新闻线索。Agent 只能返回候选代码、已有价格路径、
  排名和证据引用，不能新增股票或重写价格与手数。
- 候选池 Agent 快照按账户哈希隔离，并绑定来源时间、模型版本、价格路径和账户容量
  生成的批次指纹。任一输入变化即判过期；Agent 未运行、失败、证据不完整或未选择
  时，规则候选只能显示为等待/不买，禁止回退为纯规则买入。

退出条件：同一输入可回放；不可用明确呈现；模型结果未写入交易事实。

### P3：业务验收与清理

- 对比原系统与恢复版本的账户、T+1、费用、部分成交、预警和复盘行为。
- 逐项切换生产入口；先停止新重建平台的调度，再切换原工作台。
- 逐项删除已被替代且零消费者的重建 UI、路由、部署包和重复实验入口。

退出条件：原系统成为唯一用户工作台和交易事实写入方；模型/Agent 服务可独立回滚；
删除清单逐项具备零引用和验收证据。

## 验收与指标

| 场景 | 预期 |
|---|---|
| 入口访问 | `www.tedixtf.cn` 无设备授权页，未登录时进入原账户登录 |
| 账户恢复 | 原 OSS 快照可读取；错误密码、过期会话和跨设备冲突保持原行为 |
| 交易事实 | 建仓、部分成交、做 T、T+1、费用、计划取消和复盘不被模型结果改写 |
| 模型不可用 | 页面显示不可用及原因，不产生买卖指令 |
| Agent 失败 | 解释/研究失败不撤销已有人工交易事实或原系统建议 |
| 联合模型影子 | 输出带版本、时间、水位和证据；与原行情快照可复放 |
| 删除 | 每个删除项有消费者搜索、测试和生产部署回读证据 |

## 风险与回滚

- 最大风险是恢复时覆盖当前用户工作区中的未提交模型实验。恢复操作必须只新增旧文件，
  对同路径文件先创建差异清单，不能使用 `reset --hard` 或整体 checkout。
- 最大业务风险是两套账户系统同时写入。切换前新 PostgreSQL 写入保持关闭，原 OSS
  是唯一账户写入方。
- 模型服务不可用或合同不兼容时，适配器只返回 `UNAVAILABLE`；原工作台继续提供
  行情、账户、人工成交和复盘。
- 原系统恢复未通过时，保留当前生产服务作为只读回退，不使用数据库快照覆盖 OSS。

## 开放问题

- 旧 FC、Vercel 和自定义域名的当前部署权限与回滚路径需要在恢复构建通过后逐项复核。
- 旧 OSS 快照与当前 PostgreSQL迁移副本的最终水位需要只读对账；在此之前不允许双写或切换账户事实源。
- Python模型服务的可调用地址、认证方式和可验证联合结果仍未知；适配器默认返回`UNAVAILABLE`，不得生成替代性交易建议。

## 决策记录

**ADR-L01：恢复原系统作为产品基线**

- 状态：`accepted`
- 决定：恢复 `d6d5d5c^` 的用户工作台与 OSS 交易合同。
- 依据：用户明确要求原系统上增量接入模型/Agent；当前重建改变了产品架构与操作逻辑。
- 代价：需要重新维护 Node/FC/OSS 运行时，并处理旧系统技术债。
- 重新评估条件：原系统无法在安全、可靠或关键交易合同上恢复，且存在可验证的最小兼容替代。

**ADR-L02：模型/Agent 通过单向适配器接入**

- 状态：`accepted`
- 决定：Python 计算服务只读原系统事实，输出版本化建议合同。
- 依据：防止双写、保持人工执行和账户语义，允许独立训练与回滚。
- 代价：需要维护跨运行时合同与回放测试。
- 重新评估条件：模型服务需要直接拥有交易事实才能证明必要能力，且完成数据所有权迁移设计与验收。

**ADR-L03：每日学习使用不可变脱敏事件与 challenger 门禁**

- 状态：`accepted`
- 决定：生产 Node/FC 只向 `learning/v1/` 追加选股预测、持仓预测、人工执行和成熟
  结果；GitHub Actions 只能下载 `learning/v1/views/` 的脱敏训练视图。训练输出写入
  `learning/v1/training-runs/`，不直接修改现役模型指针。
- 数据边界：账户仅保存不可逆哈希；计划、模拟成交、未完成归因不得作为真实结果；
  原 OSS `account`、`holding`、`closed` 继续由原工作台单写。
- 成熟口径：选股使用预测后 5 个交易日的收益、MFE/MAE 和方向命中；持仓仅接收
  `validationComplete=true` 且 `learningEligible=true` 的人工成交归因。
- 训练门禁：选股至少 60 个成熟样本且覆盖 12 个交易日；持仓至少 30 个真实成熟
  样本且覆盖 10 个交易日。均采用时间外切分和 3 个随机种子，平均与最差种子必须
  同时优于现役基线，否则记录 `CHALLENGER_REJECTED`；样本不足记录
  `SKIPPED_INSUFFICIENT_MATURED_DATA`。
- 发布边界：当前流水线只生成 challenger 和报告，`productionPointerChanged`
  固定为 `false`。生产晋级必须增加独立人工批准步骤并复核费后、容量和回撤门禁。
