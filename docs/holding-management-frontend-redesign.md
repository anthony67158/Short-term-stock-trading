# 自适应短线决策引擎：持仓与自选前端落地

> 状态：Draft，待确认
> 最后更新：2026-09-09
> 事实基线：`stock-dashboard@9ebfa2d`
> 上位合同：[自适应短线决策引擎](./adaptive-trading-engine.md)
> 配套后端章节：[持仓与自选后端落地](./holding-management-backend-redesign.md)

## 一、执行摘要

本文不单独设计一套“持仓管理产品”。前端只是自适应总引擎的执行界面：

```text
今日作战发现全市场机会并安排账户优先级
  -> 自选承接未持仓机会及三条价格路径
  -> 持仓承接买入后的加仓 / 持有 / 减仓 / 退出
  -> 系统持续观察和复核
  -> 用户只执行并记录真实成交
```

用户不需要理解六打法、模型路由或资金公式，也不需要持续盯盘。界面必须把复杂判断压缩成：

- 现在做什么；
- 多少手、什么价、什么时候做；
- 系统正在等待什么；
- 什么情况会改变决定；
- 用户执行后在哪里记录。

今日作战、自选和持仓不能各自给一套结论。它们展示同一个 `decision-plan.v2`，区别只在
用户任务：今日作战负责排序，持仓与自选负责跟踪、执行和记录。

## 二、问题定义

### 2.1 当前状态与证据

| 已确认事实 | 用户影响 |
| --- | --- |
| `App.jsx` 已将生产 `TodayTab` 指向 `AdaptiveWorkbench` | 今日作战已切换，但持仓和自选仍未完整消费同一排序与动作价值 |
| 持仓和自选在同一长页面上下堆叠 | 用户要滚动寻找重要动作 |
| 自选卡可编辑系统买价和手数 | 前端可能制造与服务端不同的计划 |
| 持仓卡同时提供加仓、做 T、减仓/清仓 | 系统给出结论后仍让用户重新决策 |
| 卡片混合动作、量化、资金、计划、来源和备注 | 关键指令被证据淹没 |
| 批量生成和刷新设置占据主界面 | 用户需要管理系统，而不是系统管理交易 |
| 旧本地口诀仍可改变持仓展示 | 前后端可能出现不同动作 |
| 监控、复核、通知和执行已经具备基础能力 | 应重组主流程，而不是再增加入口 |

### 2.2 核心问题

用户面对的不是“信息不够”，而是系统没有把全市场机会、账户资金、自选路径和持仓状态
压缩为唯一行动队列。当前界面仍要求用户自己完成排序、复核、风险判断和动作选择。

## 三、目标与非目标

### 3.1 目标

- 今日作战成为自适应总引擎的生产唯一入口；
- 用户在持仓管理首屏立即看到账户最优先动作；
- 自选卡直接展示三路径竞争后的唯一买入或等待结论；
- 持仓卡直接展示加仓、持有、减仓、退出竞争后的唯一动作；
- 系统自动观察价格、资金、板块和相对强弱，事件发生后自动复核；
- 卡片只保留执行所需信息，完整证据渐进披露；
- 实际成交记录后，今日作战、自选和持仓同步更新。

### 3.2 非目标

- 不做第二个机会雷达；
- 不在前端计算动作价值、仓位、价格或风险许可；
- 不展示影子建议或新旧方案对比；
- 不连接券商和自动下单；
- 不把所有模型字段塞进卡片；
- 不删除人工自主交易入口，但它必须是次级操作；
- 不恢复固定口诀、统一赔率或市场红绿灯决定买卖。

## 四、核心约束

- 所有动作、价格和手数来自服务端 `decision-plan.v2`；
- 今日作战、自选和持仓必须显示相同 `decisionId`；
- 用户确认计划不等于真实成交；
- 只有真实成交可以改变现金、持仓、T+1 和执行进度；
- 持续复核必须由用户明确授权并写入白名单；
- 旧建议、过期计划和错版监控不能显示成可执行；
- 内部枚举、公式和字段名不得出现在用户界面；
- 关键阻断必须展示具体数值，不得只写“风险较高”；
- 交易卡继续使用固定骨架；移动端同组卡片保持等高横向吸附；
- 所有紧急动作必须另有纵向行动队列，不能藏在横向卡组中。

## 五、产品设计：一条资金动线

### 5.1 用户任务

目标用户是不理解专业理论、也无法持续盯盘的个人投资者。系统承担：

- 全市场扫描和机会排序；
- 判断自选的现价、回踩或突破路径；
- 比较持仓继续持有和换出机会；
- 观察触发条件；
- 触发后自动复核；
- 提醒唯一动作；
- 记录后重新计算。

用户只承担：

- 明确哪些自选或持仓交给系统持续跟踪；
- 去券商人工执行；
- 回到系统记录真实成交；
- 必要时记录自主交易。

### 5.2 端到端动线

```text
今日作战看到机会
  -> 加入自选并选择“纳入作战”
  -> 自选卡显示唯一价格路径
  -> 系统持续观察
  -> 条件到达后自动复核
  -> 提醒“买入X手”
  -> 用户记录实际买入
  -> 同一股票自动进入持仓管理
  -> 系统比较加仓 / 持有 / 减仓 / 退出
  -> 风险或机会事件触发新动作
  -> 用户记录卖出或做T
  -> 结果进入复盘与学习
```

## 六、今日作战与持仓管理的边界

### 6.1 今日作战

生产“作战计划”视图直接使用 `AdaptiveWorkbench`，固定顺序：

1. 当前市场机会环境和风险预算；
2. 账户首要动作；
3. 全市场按动作价值排序的机会；
4. 盘中与次日机会切换。

今日作战负责“先做哪件事、资金优先给谁”，不承载完整持仓编辑和成交表单。

### 6.2 持仓管理

持仓管理负责：

- 展示全部账户动作；
- 查看每只持仓和已纳入作战自选的当前状态；
- 查看系统正在跟踪的条件；
- 记录实际买卖和做 T；
- 管理跟踪授权；
- 查看完整证据和历史决策。

它不重新排序全市场，也不根据页面本地行情覆盖今日作战结论。

### 6.3 同源规则

- 今日作战的首要动作与持仓管理“现在处理”首项必须相同；
- 从今日作战点击动作，直接打开持仓管理对应执行面板；
- 从今日作战加入机会时保留打法、路径、来源和有效期；
- 自选成交后复用同一股票生命周期，不重新创建平行建议；
- 任一页面记录成交后，两边都按新账户版本刷新。

## 七、持仓管理信息架构

### 7.1 首屏结构

```text
账户行动状态带
现在处理
持仓卡组
待买卡组
```

顶部只保留一个分段控件：

- 全部；
- 需处理；
- 观察中。

概念、行业、置顶和批量选择进入筛选抽屉，不与首要任务并列。

### 7.2 账户行动状态带

只显示与执行有关的信息：

```text
现在处理 2项 · 系统跟踪 7只 · 观察中 1只
当前仓位 42% · 剩余风险 860元 · 更新于 10:21
```

完整资产、当日收益、行业分布和风险归因继续位于“资金与仓位”，不在主页面重复。

### 7.3 “现在处理”行动队列

这是纵向列表，任何屏幕都不能横向隐藏。排序固定：

1. 硬止损、清仓和 T+1 解锁退出；
2. 已确认减仓；
3. 待记录实际成交；
4. 已确认买入或加仓；
5. 到价观察和复核中；
6. 计划冲突或数据异常。

每条只显示：

```text
泰坦股份
卖出 1 手
现价跌破 11.42 元且资金继续转弱
今日可卖 1 手                         [记录卖出]
```

无待办时显示：

```text
现在不用操作
系统正在跟踪 7 只股票，最近一次计划更新于 10:21
```

## 八、自选卡片：总引擎的未持仓投影

### 8.1 两类自选

**普通收藏**

- 只有股票身份、现价和来源；
- 不生成持续建议；
- 不进入自动复核；
- 主操作为“纳入作战”。

**已纳入作战**

- 已完成六打法和三路径比较；
- 已有唯一决策和监控条件；
- 系统自动观察与复核；
- 用户不需要手动选择生成频率。

### 8.2 固定卡片骨架

自选卡从上到下固定为：

1. 股票身份、现价、涨跌；
2. 账户优先级和当前唯一动作；
3. 成交概率、成功概率、费后净 R；
4. 唯一价格路径、计划手数、止损；
5. 最多三条系统观察条件；
6. 状态和唯一主操作。

示例：

```text
比亚迪 002594                         108.36 +3.24%
账户机会第 1 · 现在买入 1 手
预计成交 88% · 成交后成功 64% · 费后期望 +0.42R
参考 108.36 · 止损 105.72 · 目标 112.48
系统在盯：分时均价承接 / 板块扩散 / 主力资金
有效至 10:45                              [记录买入]
```

### 8.3 等待路径

等待不能只显示“观望”：

```text
宁德时代
本次不买，系统等待回踩 292.60 元后重新站稳
到价后观察约 60 秒，并核对量能与资金
系统盯盘中
```

回踩和突破只能有一个主路径。另一路及未选原因放入详情。

### 8.4 自选排序

卡片顺序直接使用总引擎结果：

- 可执行动作价值；
- 复核状态；
- 条件路径价值；
- 触发距离；
- 有效期。

不得再用前端量化分、置顶或加入顺序覆盖资本竞争结果。置顶只影响用户收藏分组，不改变
“账户机会第几”的排序事实。

### 8.5 自选操作

| 当前状态 | 唯一主操作 |
| --- | --- |
| 普通收藏 | 纳入作战 |
| 现在买入 | 记录买入 |
| 等回踩/突破 | 系统盯盘中，无交易按钮 |
| 观察中 | 显示真实倒计时 |
| 复核中 | 显示服务端阶段 |
| 放弃本轮 | 查看原因 |
| 计划过期 | 重新评估 |

置顶、备注、取消跟踪、手动预警和删除进入更多菜单。

## 九、持仓卡片：总引擎的已持仓投影

### 9.1 主动作

卡片只显示 `holdingActionValue` 的最终动作：

- 加仓；
- 继续持有；
- 减仓；
- 清仓。

当主动作是继续持有且存在合法 `tPlan` 时，显示“继续持有，当前可做 T 一腿”，但做 T
不得覆盖主持仓动作。

### 9.2 固定卡片骨架

持仓卡从上到下固定为：

1. 股票身份、现价、费后浮盈亏；
2. 当前唯一动作和手数；
3. 持仓、今日可卖、含费成本；
4. 当前动作相对继续持有的关键原因；
5. 最多三条系统跟踪条件；
6. 下一复核事件和唯一主操作。

示例：

```text
泰坦股份 003036                         11.36 -1.20%
减仓 1 手
持仓 2 手 · 今日可卖 1 手 · 含费成本 10.98
板块转弱且主力连续流出；释放风险后再比较新机会
系统在盯：11.42元结构 / 主力流出 / 板块是否继续退潮
10:21 已复核                              [记录减仓]
```

### 9.3 持仓卡不再出现

- “踏 5 不破 10”信号灯；
- 固定 -8%/+10% 计划；
- 固定时段口诀；
- 量化、换手、量比、主力、小单四联指标；
- 加仓、做 T、减仓/清仓三个平级按钮；
- 卡片内止盈止损编辑；
- 卡片内生成、深度生成和刷新设置。

这些信息不是全部删除：

- 当日与五日资金、量价和板块证据进入详情；
- 手动保护价进入详情中的“手动保护设置”；
- 自主交易进入更多菜单；
- 模型生成过程进入统一任务中心。

### 9.4 动作与按钮

| 最终动作 | 主按钮 |
| --- | --- |
| 加仓 | 记录加仓 |
| 继续持有 | 无交易按钮，显示系统跟踪状态 |
| 减仓 | 记录减仓 |
| 清仓 | 记录清仓 |
| T+1 锁定退出 | 无按钮，显示下一可卖时段 |
| 继续持有 + 做 T | 记录当前一腿 |

## 十、做 T 交互

用户不再先选“稳健、均衡、激进”。系统只在主动作允许时提供一条当前腿：

```text
当前腿：高抛 1 手，参考 12.20 元
完成后：系统等待回落承接，再提醒是否接回
预计完整价差已覆盖双边费用和滑点
```

记录第一腿后：

- 卡片只显示待完成第二腿；
- 不允许开启相反方向的新一轮；
- 第二腿条件由系统继续监控；
- 用户可选择“停止本轮”，但必须看到当前净仓位和风险影响。

## 十一、系统盯盘

### 11.1 显式授权

从今日作战或普通收藏进入持续管理时，只询问一次：

```text
纳入作战并让系统持续跟踪？

系统会观察价格、资金、板块和量价变化，
条件成熟或风险出现时自动复核并提醒。

[纳入作战] [仅收藏]
```

记录买入时再次明确持仓跟踪范围：

```text
[x] 将这笔持仓加入系统持续管理
```

确认后写入对应白名单。后续新增股票不能自动加入。

### 11.2 用户可见状态

- 系统跟踪中；
- 条件接近；
- 到价观察，剩余 38 秒；
- 正在复核；
- 现在需要操作；
- 今日受 T+1 锁定；
- 数据暂缺，保护计划仍有效；
- 本轮已结束。

页面不显示 `ARMED`、`REVIEWING`、`RISK_OFF` 等内部枚举。

### 11.3 监控条件

卡片最多显示三条，观察中的规则置顶：

```text
系统在盯
· 跌破 11.42 元后是否重新站回均价线
· 主力净流出是否扩大到 0.80 亿元
· 板块由领涨转为分化时重新判断
```

条件必须带实际数值或明确事件，不显示空泛的“等待量价确认”。

## 十二、提醒与恢复

### 12.1 提醒分级

| 级别 | 事件 | 通道 |
| --- | --- | --- |
| 必须处理 | 止损、清仓、减仓、已确认买入/加仓、T+1 解锁退出 | 横幅、声音、系统通知、通知中心 |
| 正在确认 | 到价观察、资金反转、板块退潮、复核开始 | 轻提示、通知中心 |
| 普通更新 | 继续持有、等待条件、计划刷新 | 通知中心 |

同一结构化事件驱动全部通道。横幅短时自动消失，多条按队列展示。

### 12.2 刷新与跨设备

- 页面刷新后恢复服务端 `decisionId`、监控事件和任务阶段；
- 历史通知静默进入通知中心，不重新弹横幅或响铃；
- 手机触发的观察状态可在桌面继续显示同一倒计时；
- 旧设备不得把完成计划恢复为待执行；
- 快照过期时禁用交易主按钮，但保留明确的旧保护价和更新时间。

## 十三、执行与真实成交

### 13.1 系统建议成交

```text
点击“记录买入/减仓/清仓”
  -> 执行 Sheet 预填系统参考价和手数
  -> 用户填写券商实际成交
  -> 展示费用、现金和 T+1 影响
  -> 用户确认
  -> 写入真实成交
  -> 服务端重算账户与单股动作
```

### 13.2 自主成交

更多菜单保留“记录自主交易”。必须明确：

- 这是用户已经完成的事实记录；
- 不代表系统建议；
- 仍需通过现金、持仓、T+1 和数量校验；
- 记录后系统按新账本重新计算。

### 13.3 部分成交

系统建议 2 手但实际只成交 1 手时：

- 执行计划进入 `PARTIALLY_RECORDED`；
- 卡片显示剩余计划手数；
- 新账户风险立即重算；
- 不自动把剩余 1 手标记完成；
- 最新决策与旧执行计划冲突时先提示处理冲突。

## 十四、证据详情

点击卡片进入抽屉，移动端使用全屏 Sheet。顺序固定：

1. 当前动作、手数、价格和时点；
2. 系统正在跟踪什么；
3. 为什么现在这样做；
4. 什么会推翻决定；
5. 当日与五日主力/小单资金；
6. 市场环境、板块阶段和相对强弱；
7. 成交概率、成功概率、费后净 R、尾损；
8. 未选路径或最强替代机会；
9. 公告、新闻、量化和审计信息。

模型、打法和理论可以在详情中解释，但不能替代真实数值。所有资金描述必须注明数据日期；
不足五日时明确写“近 N 日”，不能显示“近五日持续”。

## 十五、白话文案

### 15.1 当前动作

错误：

- 观望；
- 保持谨慎；
- 维持持有；
- 等待确认。

正确：

- `本次不买，系统等待回踩 10.20 元后重新站稳。`
- `继续持有 2 手；跌破 18.60 元且主力流出扩大时自动复核减仓。`
- `减仓 1 手，参考 23.40 元；剩余 1 手继续由 22.70 元保护。`

### 15.2 具体问题具体解释

错误：

- 市场偏弱，禁止买入；
- 资金不支持；
- 风险较高。

正确：

- `市场整体偏弱，但该股属于独立催化且逆势走强；仓位缩小到 1 手，不按普通跟风股处理。`
- `近5日主力累计流出 3.20 亿元，今日小单净流入 0.86 亿元，且价格跌破均价线，按派发风险处理。`
- `当前可用风险 74 元，低于买入1手所需的 126 元，本次不买。`

## 十八、响应式与视觉约束

### 18.1 桌面

- 点击卡片打开右侧详情抽屉；
- 不使用嵌套卡片和大面积指标仪表；
- 同类操作控件等高，纯图标按钮保持正方形。

### 18.2 移动端

- “现在处理”仍为纵向列表，保证风险动作全部可见；
- 持仓卡组、自选卡组使用现有等高横向吸附，并露出下一张；

- 详情使用全屏 Sheet；
- 触屏目标至少 44px；

### 18.3 颜色与可访问性

- 买入/加仓使用交易红；
- 减仓/止盈使用交易绿；
- 硬止损/清仓使用危险红；
- 条件等待使用品牌蓝，观察中使用警示金；
- 颜色必须同时配文字和图标；
- 动态状态使用 `aria-live`；
- 真实进度使用 `role="progressbar"`；
- 支持键盘、`prefers-reduced-motion` 和明暗主题。

## 十九、方案对比与决策

| 方案 | 结果 | 决策 |
| --- | --- | --- |
| 只精简现有卡片 | 无法消除多决策源和手动生成依赖 | 拒绝 |
| 改成纯纵向表格 | 扫描快，但违背现有交易卡固定骨架和移动浏览习惯 | 拒绝 |
| 今日作战与持仓各自实现动作 | 会再次产生不同结论 | 拒绝 |
| 全局行动队列 + 同源固定骨架卡片 | 紧急动作不隐藏，持仓/自选仍易浏览 | 采用 |

最强反方是固定卡片会占用移动端空间。通过“行动队列纵向、卡组横向、详情下沉”解决；
不能因此回到长卡片堆满指标，也不能把紧急动作藏进横向卡组。

## 二十、优先级与里程碑

### M1：今日作战与持仓完成同源

Outcome：用户真实入口展示六打法、三路径和账户动作价值结果。

退出条件：

- `AdaptiveWorkbench` 与持仓管理消费同一决策投影；
- 未引用的旧 `TodayTab` 退出生产代码；
- 今日作战与持仓管理的首要动作一致。

### M2：自选落地

Outcome：普通收藏与纳入作战分离，已纳入作战自选展示唯一价格路径。

退出条件：

- 雷达加入和手动加入都能进入同一总引擎；
- 三路径只显示一个主动作；
- 卡片不再编辑系统买价和手数；
- 等待路径自动创建可复核监控。

### M3：持仓落地

Outcome：持仓卡只展示总引擎的唯一主动作，并考虑全市场替代机会。

退出条件：

- 删除前端口诀和固定止盈止损；
- 不再同时显示三个平级交易按钮；
- 做 T 只作为持有动作下的附属计划；
- 部分成交后剩余仓位与动作正确。

### M4：自动盯盘闭环

Outcome：授权股票无需用户管理刷新和生成。

退出条件：

- 到价观察、复核、通知和成交回读完整；
- 同一事件不重复响铃或弹窗；
- 刷新、跨设备和离线 FC 兜底状态一致。

### M5：一次性生产替换

Outcome：生产只保留新持仓与自选交互。

退出条件：

- 旧界面和旧裁决已删除；
- 320、768、1024、1440 真实渲染无溢出或遮挡；
- 全量测试、Harness 和构建通过；
- 测试账号完成全链路；
- Vercel 与 FC 使用同一构建产物；
- 发布前版本可整体回滚。

## 二十一、验收与指标

### 21.1 核心场景

**弱市独立机会**

Given：市场整体偏弱，但股票属于独立催化且资金、相对强弱成立。
Then：今日作战与自选卡显示同一小仓路径，不被前端改成全局禁买。

**持仓与新机会竞争**

Given：现持仓延续价值下降，全市场存在费后增量价值更高的合法候选。
Then：卡片显示减仓/退出及替代机会；只有覆盖费用、滑点和 T+1 后才建议轮动。

**无需用户盯盘**

Given：股票已明确纳入白名单。
When：价格或五分钟结构发生实质变化。
Then：系统自动观察、复核和提醒，用户不需要打开页面或点击重新生成。

**部分成交**

Given：系统建议减仓 2 手。
When：用户实际记录卖出 1 手。
Then：剩余 1 手不被误标完成，账户动作立即重算。

**数据缺失**

Given：只取得近 3 日资金。
Then：详情显示近 3 日真实序列，不写近五日持续性；若不满足新增风险证据则不显示买入按钮。

### 21.2 产品指标

- 首屏 10 秒内识别首要动作；
- 系统建议成交记录不超过 3 步；
- 同股跨页面动作、价格和手数冲突率 `0`；
- 过期计划仍可执行次数 `0`；
- 授权股票跟踪状态可见率 `100%`；
- 紧急动作在移动端无需横向滑动即可全部看到；
- 320px 至 1440px 无页面横向溢出；
- 文案不出现内部枚举或无条件的“观望”。

### 21.3 工程验证

- 单元测试覆盖所有卡片状态和成交转换；
- `harness:portfolio` 验证持仓与替代机会；
- `harness:execution` 验证人工成交、T+1 和做 T；
- `harness:lifecycle` 验证建议、触价、复核和通知；
- Playwright 检查 DOM 坐标、文本换行、滚动宽度和控制台错误；
- 线上有副作用验收仅使用测试账号。

## 二十二、风险、发布与回滚

- 不展示影子建议，不做账号灰度，不保留新旧 UI 切换开关；
- 机会模型内部影子评估不进入界面；
- 前端和 FC 在同一发布窗口一次性切换；
- 旧账户和真实成交数据继续兼容，旧建议正文只读；
- 出现动作冲突、错误手数、过期动作可执行或跨设备回滚时整版本回滚；
- 回滚部署不能覆盖发布后新增的真实成交。

## 二十五、UI Handoff

**用户任务与结果**：用户只需核对唯一指令、人工执行并记录成交；系统承担筛选、排序、
观察、复核和提醒。
**范围**：生产今日作战、自选卡、持仓卡、行动队列、系统盯盘、通知、执行记录。
**非目标**：独立选股入口、前端决策、券商下单、理论教学。
**产品对象**：市场机会、价格路径、持仓动作、监控事件、执行计划、真实成交。
**业务状态**：收藏、已纳入作战、等待、观察、复核、需执行、T+1锁定、待记录、完成。
**权限**：持续复核必须显式授权；生产个人账号自动化只读。
**信息架构**：全局行动队列优先，持仓和自选使用固定骨架卡片，证据进入详情。
**术语**：买入、加仓、继续持有、减仓、清仓、做 T、系统跟踪、正在复核。
**产品验收**：同源、无冲突、少步骤、自动跟踪、跨设备恢复、全端可访问。
**开放未知**：只允许调整视觉密度，不得改变服务端唯一动作合同。

## 二十六、决策记录

**决定**：把持仓和自选设计为自适应总引擎的执行投影，而不是独立产品和决策中心。
**主要依据**：用户要的是全市场资金最优配置和无脑执行，不是更精致的持仓看板。
**最强反方**：高度自动化可能降低用户对依据的感知。
**回应**：首层保持唯一动作，详情完整保留数字、证据、未选路径和失效条件。
**接受代价**：需要接通生产 `AdaptiveWorkbench`，拆分 `PlanTab`，重写卡片和执行动线。
**翻转条件**：若前端仍需自行计算动作或同股跨页面不一致，则本方案未成立。
**状态**：Proposed。
