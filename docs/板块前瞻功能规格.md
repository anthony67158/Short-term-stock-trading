# 板块前瞻功能规格

> 状态：Draft，等待产品确认
> 日期：2026-08-20
> 目标版本：`sector-forecast.v1`

## 一、前置假设

1. 功能名称采用“板块前瞻”，而不是暗示确定收益的“板块预测”。
2. 第一版只覆盖东方财富概念板块；行业板块用于交叉验证，不与概念榜混排。
3. 输出是研究与纪律工具，不自动下单，不自动修改持仓或自选。
4. 收盘后生成正式版；盘中手动生成只能标记为“盘中预估”，不能冒充收盘结论。
5. “次日前瞻”预测下一交易日板块相对强弱；“一周布局”预测从下一交易日开盘到未来第 5 个交易日收盘的相对收益和风险。
6. LLM 不直接制造预测分数。确定性因子或量化模型负责排名，LLM 只解释资金进入原因、催化、反方证据与风险。
7. 个股只能来自所选概念板块的真实成分股，并继续通过现有五层过滤：
   `产业方向 → 真实成分股 → 公司质量 → 资金 → 量化与策略闸门`。
8. 新功能全局共享市场结果，不保存到个人账户快照；生产账号与测试账号数据继续严格隔离。

如以上假设不符合预期，应先修改本规格，再进入实施计划。

## 二、目标

### 2.1 用户问题

面向 A 股短线及 T+1 用户，解决三个问题：

1. 今天的资金为什么进入某些概念，哪些流入可能具有次日或一周持续性。
2. 区分“尚可提前布局”与“市场已经高潮、现在追入太晚”。
3. 从值得关注的概念中找出真实、有质量、具备资金和量化确认的具体股票。

### 2.2 产品目标

在“盘面研究”首屏提供一个全宽的“板块前瞻”模块，输出：

- 下一交易日相对强度榜。
- 未来 5 个交易日布局价值榜。
- 每个板块的阶段：潜伏、启动、加速、分歧、退潮。
- 操作级别：可布局、等回踩、只观察、回避。
- 资金依据、价格位置、板块扩散、核心股结构、催化和反方风险。
- 每个入选板块最多 3 只真实成分股：总龙头、趋势中军、潜伏核心。
- 历史命中、超额收益、最大回撤与样本数。

### 2.3 非目标

- 不预测精确指数点位。
- 不承诺板块或个股上涨。
- 不因为新闻热度、涨停或 LLM 主观判断直接升级为“可布局”。
- 不修改现有量化 `/predict` 的 36 维 OHLCV 口径。
- 第一版不引入强化学习自动配置仓位，不接券商交易。

## 三、核心定义

### 3.1 信号时间

| 状态 | 生成时间 | 数据口径 | UI 标识 |
| --- | --- | --- | --- |
| 盘中预估 | 交易时段手动请求 | 截至当前时点的资金、涨跌、分时快照 | `盘中预估` |
| 收盘正式版 | 交易日 15:10 后 | 当日完整板块资金和收盘数据 | `收盘定稿` |
| 盘前复核 | 下一交易日 08:50 | 只更新隔夜催化与风险，不改确定性排名 | `盘前复核` |
| 过期 | 已跨过下一个交易日收盘 | 旧信号 | `已过期` |

### 3.2 预测目标

#### 次日前瞻

- 目标：预测板块在 `T+1` 收盘时的横截面相对强度。
- 正样本：`T+1` 板块涨跌幅位于当日全部可比概念的前 20%。
- 用途：决定 `T+1` 开盘后优先观察哪些方向。
- 约束：A 股 T+1 下，当日买入不能当日卖，因此该指标不是可兑现的“次日收益承诺”。

#### 一周布局

- 目标：预测从 `T+1` 开盘到 `T+5` 收盘的板块超额收益。
- 基准：同期全部可比概念等权收益；后续可增加中证全指或沪深 300。
- 同时预测：
  - 5 日超额收益方向。
  - 5 日内最大回撤。
  - 资金持续性。
- 正样本：5 日超额收益位于横截面前 20%，且最大回撤未超过策略护栏。

### 3.3 板块生命周期

| 阶段 | 确定性特征 | 默认动作 |
| --- | --- | --- |
| 潜伏 | 资金连续改善，板块涨幅尚未扩张，价格与成交未过热 | 可布局 |
| 启动 | 资金与价格共振，成分股扩散改善，仍有合理赔率 | 可布局或等回踩 |
| 加速 | 板块涨幅、换手、涨停扩散处于高分位 | 只观察，禁止追涨 |
| 分歧 | 价格仍强但资金流出，或龙头强而多数成分股走弱 | 等回踩或回避 |
| 退潮 | 资金、价格、扩散和龙头结构同步走弱 | 回避 |

### 3.4 操作级别

确定性引擎给出以下枚举，LLM 无权升级：

```js
const actionability = [
  'LAYOUT',        // 可布局
  'WAIT_PULLBACK', // 等回踩/分歧
  'WATCH_ONLY',    // 只观察
  'AVOID',         // 回避
]
```

### 4.2 需新增的数据资产

1. 每日全量概念收盘快照：
   `market/sector-forecast/v1/features/YYYY-MM-DD.json`
2. 每次正式预测：
   `market/sector-forecast/v1/predictions/YYYY-MM-DD/close.json`
3. 盘前证据复核：
   `market/sector-forecast/v1/predictions/YYYY-MM-DD/preopen.json`
4. 预测结算结果：
   `market/sector-forecast/v1/outcomes/YYYY-MM-DD.json`
5. 回测与模型基线：
   `market/sector-forecast/v1/metrics/current.json`

所有市场预测均为全局数据，不进入 `accounts/**`。

### 4.3 可选历史回填

优先使用现有东方财富数据链；如果生产环境已具备 Tushare 6000 积分权限，可用于一次性历史回填：

- `moneyflow_ind_dc`：每日概念/行业板块资金流。
- `ths_daily`：板块指数 OHLCV。

没有 Tushare 权限时，系统仍可上线确定性影子版，但学习模型必须等自有快照积累到最低样本量后再启用。

## 五、预测与评分

### 5.1 两阶段候选收敛

#### 第一阶段：全量概念快速初筛

对全部概念进行横截面排序，只保留前 20 个进入深度分析。因子包括：

- 当日主力净流入和净占比。
- 成交额与流动性。
- 当日涨幅和拥挤度。
- 领涨股强度。
- 盘中资金排名稳定性。

#### 第二阶段：历史、扩散和催化复核

对前 20 个概念补充：

- 3/5/10/20 日资金连续性、斜率和加速度。
- 价格位置、波动、回撤、相对动量。
- 价资关系：价资共振、逆势承接、上涨流出、同步走弱。
- 成分股上涨家数、资金流入家数、涨停扩散、龙头/中军健康度。
- 豆包搜索和理论 RAG 证据。
- 市场风险偏好。

### 5.2 V1 确定性评分

V1 使用可解释的横截面百分位评分，不依赖 LLM：

| 因子 | 权重 |
| --- | ---: |
| 资金持续与加速度 | 25% |
| 资金净占比与超大单结构 | 15% |
| 价资关系与相对动量 | 15% |
| 成分股扩散 | 15% |
| 龙头/中军结构 | 10% |
| 流动性与成交稳定性 | 10% |
| 市场环境适配 | 10% |

另外施加独立惩罚，不允许正权重抵消：

- 当日涨幅处于全概念前 10%：过热惩罚。
- 涨停扩散过高且次日可买性差：追高惩罚。
- 价格上涨但资金流出：背离惩罚。
- 单一龙头拉动、板块多数成分股走弱：结构惩罚。
- 数据缺失或时点不一致：置信度降级。

### 5.3 V2 学习模型

积累足够的 point-in-time 样本后，在 `qlib-service` 增加独立板块模型：

- 新端点：`/sector-predict`。
- 不修改现有 `/predict` 和 36 维个股因子。
- 基线模型：LightGBM Ranker / 分类器。
- 双预测头：
  - `nextSessionTopQuintileProb`
  - `weekTopQuintileProb`
- 风险头：
  - `weekMaxDrawdownEstimate`
- 校准：仅在样本外完成概率校准后，UI 才展示“概率”；否则只展示 0-100 前瞻分。

### 5.4 防泄漏训练

- 严禁随机切分。
- 按交易日 walk-forward。
- 所有特征只允许使用信号时点之前的数据。
- 概念新增、改名和退市必须保留当时可见状态。
- 搜索证据只保存信号时已经发布的内容和发布时间。
- 对照基线：
  - 当日资金净流入排名。
  - 5 日动量排名。
  - V1 确定性前瞻分。

## 六、LLM 职责

### 6.1 新角色

建议新增 `sector` 角色，与 `advisor`、`agent` 解耦：

- 首选：GPT-5.6。
- 备选：Claude Opus 5 / Claude Sonnet 5。
- 自动收盘任务默认不开深度思考；手动“深度解释”可开。
- LLM 输出失败时仍返回确定性榜单，不允许整页失败。

### 6.2 LLM 可做

- 解释资金进入可能对应的政策、供需、订单、涨价和事件催化。
- 将搜索证据分类为：政策、产业、供需、公司事件、风险。
- 给出反方观点、失效条件和需要继续观察的数据。
- 解释为何某板块虽强但已经过热、不可追。
- 为确定性筛出的真实股票解释角色和关注逻辑。

### 6.3 LLM 不可做

- 不得新增确定性候选之外的板块。
- 不得修改板块排名、前瞻分、生命周期或操作级别。
- 不得把豆包搜索摘要写成已核实事实。
- 不得把静态国家战略主题写成当天新政策。
- 不得把涨停或热搜直接转化为买入建议。
- 不得生成不存在于真实成分股列表的股票。

## 七、豆包搜索与成本

每次正式预测最多产生 2 次计费搜索：

1. 对确定性前 6 个概念做一次合并催化查询。
2. 对前 6 个概念做一次合并风险/利空查询。

策略：

- 同一预测版本 single-flight。
- 收盘正式版缓存至下一次正式生成。
- 盘前复核只读已有板块查询缓存；确有隔夜重大事件时才允许 1 次新增查询。
- 预测失败冷却 15 分钟。
- 搜索内容全部标记“待核验”。
- LLM 失败不重复触发搜索。

## 八、板块到个股

每个入选概念最多展示 3 只股票：

| 角色 | 目的 | 主要条件 |
| --- | --- | --- |
| 总龙头 | 判断板块号召力 | 真实领涨、资金、成交、板块强度 |
| 趋势中军 | 提供更可交易的容量核心 | 流动性、公司质量、资金连续性、位置不过热 |
| 潜伏核心 | 寻找尚未大涨的提前布局候选 | 板块强、个股资金改善、涨幅低、量化未转弱 |

硬规则：

- 必须来自 `/api/stocks?code=BKxxxx` 返回的真实成分股。
- 排除 ST、退市、停牌和低流动性。
- 当日涨停或显著过热只能标“只观察”。
- 产业逻辑不能替代资金和量化确认。
- `strategySignal.passed=false` 不得标记“可执行”。
- 页面只提供“加入自选”和“查看详情”，不自动建仓。

## 九、界面

### 9.1 位置

放在“盘面研究”第一屏，位于现有“概念走势”之前。原因：

- 它是研究页的结论层。
- 现有概念走势、资金热力图、成分股、龙虎榜是证据和下钻层。
- 用户先看“明天/一周看什么”，再向下验证资金和走势。

### 9.2 布局

使用一个全宽、非嵌套卡片的工作面板：

1. 顶部：
   - `次日` / `一周` 分段控件。
   - `盘中预估` / `收盘定稿` 状态。
   - 更新时间、数据截至时间、模型版本。
   - 刷新图标按钮。
2. 主表：
   - 排名、概念、阶段、操作级别、前瞻分。
   - 资金连续性、价资关系、拥挤度。
   - 次日/一周历史命中。
3. 点击行原位展开：
   - 资金为什么进入。
   - 催化与风险证据。
   - 反方观点和失效信号。
   - 3 只真实成分股及其角色。
4. 底部折叠区：
   - 历史预测和结算。
   - Top5 命中率、超额收益、最大回撤、样本数。

不使用 Tooltip 承载核心信息，不创建卡片嵌套卡片。

```http
GET /api/sector_forecast?view=latest&horizon=next
```

`horizon`：`next | week`

### 10.2 读取历史

```http
GET /api/sector_forecast?view=history&limit=20
```

### 10.3 生成预测

```http
POST /api/sector_forecast
Content-Type: application/json

{
  "action": "generate",
  "session": "intraday | close | preopen",
  "refresh": false,
  "deepExplanation": false
```

- 付费调用必须鉴权。

## 十一、定时任务

建议：

- 交易日 15:10：生成收盘正式版。
- 交易日 08:50：只做盘前证据复核，不改确定性排名。
- 用户手动：允许盘中预估，但必须明确标识。
- 结算任务：T+1 收盘和 T+5 收盘后写入 outcome。

## 十二、模型晋级

学习模型先影子运行，不直接覆盖 V1：

1. 最少 60 个可结算交易日才展示初步统计。
2. 最少 120 个可结算交易日才允许申请生产晋级。
3. 三个连续 walk-forward 窗口均需满足：
   - `NDCG@5` 高于“当日资金排名”基线至少 5%。
   - Top5 次日相对强势命中率高于基线。
   - Top5 一周平均超额收益为正。
   - 最大回撤不劣于基线。
   - 无数据泄漏或样本选择错误。
4. 晋级继续采用冠军-挑战者和人工批准。

阈值在获得真实基线前不得伪造为固定“高胜率”。

## 十四、代码风格

确定性评分必须是纯函数、可回放、可测试：

```js
export function scoreSectorForecast(feature = {}) {
  const score = weightedPercentileScore(feature)
  const crowdingPenalty = crowdingPenaltyOf(feature)
  return {
    score: clamp(score - crowdingPenalty, 0, 100),
    phase: sectorLifecycleOf(feature),
    actionability: actionabilityOf(feature),
    factors: explainableFactorsOf(feature),
  }
}
```

- 外部响应在 API 边界解析。
- 缺失数据保持 `null`，不得伪装成 0。
- 时间全部带 `signalDate`、`dataAsOf` 和 `generatedAt`。
- LLM 结果只能填解释字段，不能覆盖确定性字段。

## 十六、测试策略

### 单元测试

- 因子计算、百分位、缺失值。
- 生命周期分类。
- 追高惩罚。
- 次日和一周标签。
- 真实成分股约束。
- LLM 不得覆盖排名。

### API 测试

- 输入校验。
- 幂等和 single-flight。
- 缓存命中不重复调用豆包或 LLM。
- 盘中/收盘/盘前状态。
- OSS 读写失败降级。
- 外部文本清洗和来源标记。

### Harness

至少覆盖：

1. 资金连续流入但涨幅尚低，应进入“可布局”。
2. 当日暴涨且涨停扩散，应降为“只观察”。
3. 价格上涨但资金流出，应识别分歧。
4. LLM 试图新增板块或股票，必须过滤。
5. 产业逻辑强但资金未确认，只能观察。
6. 数据缺失时不得输出概率。

### 浏览器测试

- 桌面和移动端。
- 次日/一周切换不改变布局尺寸。
- 行内展开无溢出、无遮挡。
- 无核心 Tooltip。
- 加入自选只写测试账号。

## 十七、边界

### 始终执行

- point-in-time 数据。
- walk-forward 验证。
- 所有结论显示数据截至时间。
- 搜索证据标记待核验。
- 个股来自真实成分股。
- 测试只用“测试账号”。
- 前端改动双部署。

### 需要确认

- 是否具备 Tushare 6000 积分板块数据权限。
- 是否新增独立 `sector` LLM 角色。
- 是否启用盘前 08:50 自动复核。
- 学习模型达到晋级条件后是否允许替代 V1 排名。

### 禁止

- 修改现有 36 维个股模型口径。
- 使用生产个人账号做生成或交互测试。
- LLM 直接给出不可回测的预测分。
- 训练集随机切分。
- 用当天收盘后才知道的数据回填当天信号。
- 只改 Prompt 而不建立结算和回归样本。

## 十八、成功标准

1. 研究页首屏可查看次日和一周榜单。
2. 每个板块都有生命周期、操作级别、因子分解、数据截至时间和失效条件。
3. “可布局”板块必须未触发追高惩罚。
4. 当日过热板块即使排名高也不得标记“可布局”。
5. 推荐股票 100% 来自该板块真实成分股。
6. 无量化或策略确认的股票不得标记可执行。
7. LLM/豆包不可用时，确定性榜单仍可展示。
8. 同一正式预测只产生一次 LLM 和最多两次豆包计费请求。
9. 历史页能展示预测与实际结算，不只展示成功案例。
10. 概率只在校准完成后展示。
11. 默认离线测试不联网、不付费、不读取生产账号。
12. 全量测试、Sector Harness、构建和双端浏览器验收通过。
