# 机会雷达融合规格

> 状态：Approved，进入实施
> 日期：2026-09-02
> 目标版本：`opportunity-radar.v1`

## 一、前置假设

1. 新模块命名为“机会雷达”，在“今日决策”中替代现有“板块前瞻”和“公式选股”两个独立面板。
2. 板块前瞻负责回答“做什么方向、处于什么阶段”；公式选股负责回答“哪只股票、什么价格介入、何时退出”。任一来源不得越权。
3. “可以买入”只表示满足确定性研究条件并可加入人工计划，不自动下单。
4. 红色继续只用于 A 股上涨、买入和硬风险；加载、弹窗、普通容器不使用红色。
5. 现有板块、公式、尾盘任务及 OSS 快照继续作为权威数据源，第一版不修改量化 `/predict` 的 36 维口径。
6. 原接口保持兼容，避免影响定时任务、个股详情公式价位和历史数据。
7. 数据源局部失败时展示最近有效结果并标记缺失，不让整个机会雷达失败。

## 二、目标

把分散的方向判断和个股公式合成一个可执行的短线决策入口，固定回答三个问题：

1. **提前布局**：哪些方向仍在潜伏或启动早期，哪些股票已有低风险入场条件。
2. **盘中机会**：当前有哪些股票满足板块、价格、量能和资金条件，可以立即观察介入或等待触发。
3. **次日计划**：收盘后哪些股票值得次日开盘重点关注，开盘满足什么条件才买，买入后何时止损、止盈或时间退出。

成功标准不是每天都给股票，而是每条展示结果都能明确回答：

- 为什么进入名单。
- 当前能不能操作。
- 在什么价格与条件下操作。
- 最大仓位是多少。
- 买入后什么条件卖出。
- 结论何时失效或重新计算。

## 三、信息架构

### 3.1 唯一模块

“今日决策”中的结构调整为：

```text
大盘盘面
市场情绪
机会雷达
今日精选候选池
涨停连板池
```

移除页面上独立的“板块前瞻”和“公式选股”入口，保留其底层数据能力。

### 3.2 三个决策视图

| 视图 | 默认时段 | 核心数据 | 用户得到的答案 |
| --- | --- | --- | --- |
| 提前布局 | 全天可看 | 板块布局阶段 + 当前可用公式结果 | 哪些方向尚未拥挤，哪些个股已有低风险计划 |
| 盘中机会 | 09:30–11:30、13:00–15:00 | 盘中板块动态 + 盘中公式 | 现在可关注什么，等待哪个触发价 |
| 次日计划 | 收盘后及次日盘前 | 收盘板块正式版 + 收盘公式 + 尾盘反转 | 次日优先看什么，开盘如何确认，买后如何退出 |

默认视图：

- 盘前：`次日计划`
- 连续竞价：`盘中机会`
- 午间：`盘中机会`，明确显示暂停刷新
- 收盘后、周末及休市日：`次日计划`

用户切换视图时不触发重算，只读取最近有效快照。

### 3.3 单层布局

模块只使用一个外层面板，内部按连续信息带组织：

1. 标题、当前交易阶段、唯一刷新按钮、设置入口。
2. 三段式视图切换。
3. 当前结论摘要：可操作、等待触发、仅看方向的数量。
4. 板块方向带：最多 5 个方向，展示阶段、排序和资金依据。
5. 个股机会列表：默认最多 8 只，可展开查看全部证据。
6. 数据来源与时点：板块、公式、尾盘分别标明新鲜度和失败状态。

禁止在主面板内再嵌套三个大卡片。

## 四、统一决策模型

### 4.1 数据职责

| 来源 | 决策职责 | 不允许做 |
| --- | --- | --- |
| 板块前瞻 | 决定方向资格、生命周期、拥挤度和优先级 | 单独生成个股买卖价 |
| 盘中/收盘公式 | 决定个股是否命中、入场类型、入场价、止损、目标和赔率 | 绕过板块与市场风险直接升级买入 |
| 尾盘反转 | 提供 14:50–14:55 的特殊入场和 T+1/T+3 退出节奏 | 冒充全天有效信号 |
| 市场环境 | 限制新增风险并给出仓位上限 | 删除研究结果 |

### 4.2 合并键与去重

- 个股以六位股票代码为唯一键。
- 板块优先按 `sector.code` 匹配，名称与动态概念标签只作为兼容回退。
- 同一股票命中多个来源时只展示一行，并保留全部 `sourceSignals`。
- 当前时段的公式优先于旧时段公式；14:50–15:00 内严格尾盘公式优先于普通盘中公式。
- 严格命中优先于接近公式；接近公式永远不能显示为“可以买入”。

### 4.3 行动分层

统一输出四类用户状态：

| 状态 | 含义 |
| --- | --- |
| `READY` | 板块方向有效、公式命中、价格合同完整且市场允许新增风险 |
| `WAIT_TRIGGER` | 方向有效，但尚未到回踩/突破价，或开盘确认尚未完成 |
| `SECTOR_WATCH` | 板块值得跟踪，但个股尚无完整价格合同 |
| `AVOID` | 数据过期、赔率不足、方向失效或风险条件不允许执行 |

硬规则：

1. 没有合法入场价、止损价、目标价或至少 `1.8:1` 盈亏比，不得进入 `READY`。
2. 板块只有方向价值，没有个股公式确认时，只能进入 `SECTOR_WATCH`。
3. 市场风险或账户限制只将结果降级并说明原因，不删除研究结果。
4. 数据过期时清除可执行动作，但保留历史证据用于复盘。

### 4.4 排序规则

使用可解释的分层排序，不创建新的黑盒总分：

1. `READY`
2. `WAIT_TRIGGER`
3. `SECTOR_WATCH`
4. `AVOID`
5. 同层内风险提示更少者优先。
6. 再按公式分数降序、板块布局排名升序、成交额降序、股票代码升序。

### 4.5 买入计划

每个可操作或待触发候选固定输出：

- `entryType`：回踩、突破、尾盘反转或开盘确认。
- `entryPrice`：唯一主价位。
- `entryWindow`：允许观察/执行的时段。
- `trigger`：必须满足的价格、量能和资金条件。
- `maxPositionPct`：最大仓位；观察结果不得超过 5%。
- `validUntil`：过期后自动降级，不沿用旧价格。

### 4.6 卖出计划

每个 `READY` 或 `WAIT_TRIGGER` 候选必须同时输出：

- `hardStopPrice`：跌破后的风险退出价。
- `takeProfitPrice` 或明确的分批止盈规则。
- `timeStopDate`：到期仍未走强时退出或重新评估。
- `t1Constraint`：当日买入不可当日卖；止损在下一可卖时段优先执行。

默认持有窗口：

- 尾盘反转：沿用现有规则，次日冲高分批止盈，最晚第 3 个交易日退出。
- 盘中回踩/资金先行：目标价或止损先到先执行，第 3 个交易日未脱离成本区则减仓，第 5 个交易日仍未走强则退出。
- 收盘趋势回踩/蓄势突破：次日开盘确认后生效，目标价或止损先到先执行，最晚第 5 个交易日重新评估。

## 六、刷新与任务策略

统一模块只有一个主刷新按钮，按当前视图执行：

- `提前布局`：刷新当前时段板块快照；公式结果只在过期或缺失时补算。
- `盘中机会`：板块盘中版和盘中公式独立并行，任一路失败不取消另一路。
- `次日计划`：
  - 收盘后：并行生成板块正式版和收盘公式；尾盘正式版存在时直接复用。
  - 盘前：只复核隔夜板块证据，复用上一交易日收盘公式和尾盘结果。
  - 非交易日：读取最近交易日结果，不创建周末信号日。

前端聚合进度显示各来源真实状态，不用虚假的单一百分比。刷新结束后只更新产生新版本的来源。

## 七、错误与降级

- 三个来源使用 `Promise.allSettled` 并行读取。
- 某来源失败时保留其它来源，并在底部显示“哪项数据缺失、结果受到什么影响”。
- 板块缺失：公式结果保留，但最高只能 `WAIT_TRIGGER`。
- 公式缺失：板块方向保留为 `SECTOR_WATCH`，不显示买入价。
- 尾盘缺失：不影响盘中和收盘公式。
- 全部缺失：展示明确空态和重试入口。
- 旧结果必须携带 `stale`，不得继续展示为可执行。

## 八、非目标

- 不新增券商交易能力。
- 不让 LLM 决定候选、排名、仓位或价格。
- 不改变原 36 维量化模型。
- 不合并或覆盖现有 OSS 原始快照。
- 不删除旧 API；待统一模块稳定后再单独评估下线旧 UI 组件。

## 九、命令与工程边界

技术栈：

- React 18 + Vite 8 前端。
- Node.js ES Modules 后端与共享纯函数。
- 阿里云 OSS 保存原始结果，阿里云 FC 承载 API。
- Node 原生测试运行器。

```bash
npm test
npm run harness:sector
npm run build
npm run package:fc
```

- 源码：`src/components/`、`src/opportunityRadarClient.js`
- 纯逻辑：`shared/opportunityRadar.js`
- 聚合 API：`api/opportunity_radar.js`
- 测试：`test/opportunity-radar-*.test.js`
- 设计约束：`docs/DESIGN.md`

代码风格：

```js
export function buildOpportunityRadar(input = {}) {
  return {
    schemaVersion: 'opportunity-radar.v1',
    lanes: buildOpportunityLanes(input),
    sourceStatus: buildSourceStatus(input),
  }
}
```

- 纯函数使用命名导出，输入缺失时安全降级。
- React 容器负责请求，展示组件只消费结构化 props。
- 用户可见文案使用中文；内部字段使用英文枚举。
- 不新增依赖，不把聚合逻辑散落在 JSX 中。

必须：

- 全市场公式扫描保持完整读取校验。
- 所有网络请求有超时。
- 所有任务状态可恢复，局部失败可降级。
- 变更通过全量测试、板块 Harness 和生产构建。
- 前端同时部署 Vercel 与阿里云 FC。

禁止：

- 为融合重复调用 LLM。
- 让板块分数覆盖个股价格合同。
- 把接近公式包装为可买。
- 把旧结果当成当前可执行机会。
- 自动修改持仓、现金或创建交易记录。

## 十、验收标准

1. “今日决策”只出现一个“机会雷达”主模块。
2. 用户可在“提前布局 / 盘中机会 / 次日计划”之间切换。
3. 同一股票跨来源只出现一次，并能看到全部来源标签。
4. 可操作股票同时展示入场条件、仓位、止损、止盈和时间退出。
5. 板块有机会但个股未确认时明确显示“方向可看，尚无买点”。
6. 数据源局部失败不清空其它有效结果。
7. 盘前、盘中、午间、收盘后和休市日默认视图正确。
8. 320px、768px、1024px、1440px 均无横向溢出或文字遮挡。
9. 明暗主题下加载、弹窗和普通背景均为中性冷灰蓝。
10. 原公式、尾盘和板块定时任务继续按原规则运行。
