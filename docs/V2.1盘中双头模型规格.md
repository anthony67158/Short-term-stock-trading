# V2.1 盘中双头模型规格

## 目标

新增独立的 V2.1 盘中分钟模型，使用截至当前最近一根已完成 5 分钟 K 线的数据，
同时预测：

1. 未来 30 分钟交易时间的三重障碍结果。
2. 从下一根 5 分钟 K 线开盘到当日收盘的三重障碍结果。

盘中军师只消费 V2.1；盘后继续消费现有 V2 日终模型。V2.1 不修改现有 V2
训练集、模型文件、接口、正确率或 OSS 记录。

## 用户与使用场景

- 早盘和午后连续竞价：以最近一根已完成 5 分钟 K 线为信号时点。
- 午间休市：以 11:30 最后一根完整 K 线为信号，预测下午前 30 分钟和下午收盘。
- 14:30 后：只消费“截至收盘”预测头；不展示不足 6 根未来 K 线的 30 分钟预测。
- 盘后、周末和节假日：使用现有 V2 预测下一交易日，不调用 V2.1。
- V2.1 不可用或输出不合法：明确回退 V2 日终信号，并标注“上一收盘信号”。

## 训练与标签契约

### 样本时点

- 每个交易日从 10:00 至 14:30，每根已完成 5 分钟 K 线均可形成样本。
- 11:30 是午间样本；下一根交易 K 线为下午 13:05。
- 输入固定为信号时点之前最近 60 根完整 5 分钟 K 线，可跨交易日，但禁止使用信号时点后的数据。
- 所有样本携带 `signal_date`、`as_of`、`session_bucket` 和股票代码。

### 特征

首轮 6 维候选未通过离线平衡准确率门槛。V2.1 使用以下 12 个因果、
尺度无关特征，训练与推理共用同一实现：

- `log_return`
- `range_pct`
- `body_pct`
- `volume_log_ratio`
- `time_sin`
- `time_cos`
- `momentum_30m`
- `realized_vol_30m`
- `session_return`
- `session_vwap_deviation`
- `session_range_position`
- `minutes_to_close`

不得把未来成交量、未来最高最低价、全日收盘统计或后验标签写入输入。
新增盘中特征只能使用当前及历史完整 K 线；测试必须证明修改未来 K 线不会改变
`asOf` 及之前的特征。

### 30 分钟预测头

- 入场价：信号时点之后第一根 5 分钟 K 线开盘价。
- 路径：之后最多 6 根真实交易 K 线。
- 止盈障碍：`+0.45%`。
- 止损障碍：`-0.30%`。
- 同一根同时触及时按止损优先。
- 类别：`STOP_LOSS / TIMEOUT / TAKE_PROFIT`。

### 收盘预测头

- 入场价：信号时点之后第一根 5 分钟 K 线开盘价。
- 路径：从入场到当日 15:00。
- 止盈障碍：`+0.80%`。
- 止损障碍：`-0.50%`。
- 同一根同时触及时按止损优先。
- 类别：`STOP_LOSS / TIMEOUT / TAKE_PROFIT`。

### 数据切分

- 按交易日期做严格时序留出，禁止随机打散日期。
- 留出集不少于最近 15% 交易日。
- 训练、概率校准、最终留出三个分区必须严格按日期递增。
- 训练与校准、校准与最终留出之间分别净化至少 1 个完整交易日。
- 同一交易日、同一股票的高度重叠样本只能落在同一分区。
- 指标同时按总体、预测头和 `morning / noon / afternoon` 时段输出。

## 模型结构

- 模型名称：`V2.1 Intraday Dual-Head Transformer`。
- 共享 3 层、96 维的 5 分钟序列 Transformer 编码器。
- 编码结果拼接最后时点、全窗均值和全窗最大值。
- 两个独立 MLP 三分类输出头：`next30m` 和 `sessionClose`。
- 两个头分别计算仅由训练分区拟合的全局类别权重交叉熵。
- 训练损失为两个预测头损失的等权平均。
- 训练日期之后、最终留出日期之前设置独立概率校准分区；可按时段拟合类别
  logit 偏置，但不得读取最终留出集。
- 校准分区再次按时间前后拆分；只有前半拟合的偏置在后半同时改善整体平衡
  准确率、且不显著损害 Macro F1 和分时准确率时，才允许用全校准分区重拟合。
- 最终留出集只用于一次离线闸门评价，检查点必须保存概率校准参数。
- 检查点必须包含特征名、序列长度、双头标签定义、归一化参数、训练指标和模型版本。
- 模型文件、SHA-256 和运行 ID 与 V2 完全隔离。

## 离线上线闸门

用户选择“离线达标即上线”。为降低直接上线风险，两个预测头必须同时满足：

- 留出集平衡准确率 `>= 0.58`。
- 留出集 Macro F1 `>= 0.48`。
- 留出集 Log Loss `< 1.05`。
- 每个类别在留出集至少 100 个样本。
- 早盘、午间、午后各时段平衡准确率均不得低于 `0.52`。
- 推理契约、模型 SHA-256、输入时点和输出概率校验全部通过。

任一条件未通过则 V2.1 保持不可用，系统继续使用 V2 日终模型，不允许降低门槛或混用两版概率。

### 真实训练结果

以下候选均使用相同日期净化留出集，且均被硬闸门拒绝，未部署：

| 候选 | 30 分钟平衡准确率 | 收盘平衡准确率 | 结论 |
|---|---:|---:|---|
| 6 维基础 Transformer | 0.5404 | 0.5535 | 拒绝 |
| 12 维特征 + 时段类别平衡 | 0.5308 | 0.5246 | 拒绝 |
| 独立日期校准 Transformer | 0.5169 | 0.5330 | 拒绝 |
| 3 层池化 Transformer | 0.5392 | 0.5458 | 拒绝 |
| LightGBM 序列汇总基准 | 0.5365 | 0.5484 | 拒绝 |
| LightGBM + 同时点横截面市场上下文 | 0.5287 | 0.5391 | 拒绝 |

当前单股 OHLCV 与派生横截面特征不足以达到 `0.58` 双头门槛。继续训练必须引入
独立的新信息，例如可回放的指数/行业分钟序列、逐笔或盘口数据、资金流和事件特征；
不得在同一数据口径上继续搜索留出集阈值，也不得把任何已拒绝候选部署到 EAS。

## API 契约

### 请求

`POST /predict-v2-intraday`

```json
{
  "requestId": "v21_20260812_1030_600519",
  "code": "600519.SH",
  "asOf": "2026-08-12 10:30:00",
  "bars": []
}
```

边界要求：

- `asOf` 必须等于最后一根 K 线时间。
- 最后一根必须是已完成的合法 5 分钟交易 K 线。
- 输入 60 至 240 根，严格升序。
- 只接受 A 股连续竞价或 11:30 午间时点。
- 沿用 EAS 外层 Token + `X-Shadow-Key` 双层鉴权。

### 响应

```json
{
  "ok": true,
  "modelVersion": "v2.1-intraday",
  "asOf": "2026-08-12 10:30:00",
  "session": "morning",
  "heads": {
    "next30m": {
      "horizon": "未来30分钟",
      "probabilities": {
        "stopLoss": 0.2,
        "timeout": 0.3,
        "takeProfit": 0.5
      },
      "predictedClass": "TAKE_PROFIT"
    },
    "sessionClose": {
      "horizon": "截至今日收盘",
      "probabilities": {
        "stopLoss": 0.25,
        "timeout": 0.45,
        "takeProfit": 0.3
      },
      "predictedClass": "TIMEOUT"
    }
  },
  "model": {
    "runId": "",
    "architecture": "transformer-dual-head",
    "sha256": ""
  }
}
```

响应概率必须非负且每个头独立和为 1。服务端不得把两个头合并成一个伪概率。

## 军师路由

- 盘中：V2.1 为量化预测主输入。
- 10:00 前：样本窗口不足时使用 V2 日终信号，并叠加实时执行参考。
- 10:00 至 14:30：同时给军师 `next30m` 与 `sessionClose`。
- 14:30 后：只给军师 `sessionClose`。
- 午间：`next30m` 表示下午开盘后 30 分钟，`sessionClose` 表示下午至收盘。
- 盘后：只使用 V2 日终模型。
- UI 必须显示模型版本、信号时间、预测窗口和回退原因。

## 正确率与存储

- V2、V2.1-30m、V2.1-收盘三套统计完全分离。
- V2.1 记录使用独立 OSS 前缀 `shadow/v2.1-intraday/`。
- 正确率按总体、预测头、交易时段和日期展示。
- 30 分钟标签在未来 6 根 K 线完成后结算。
- 收盘标签在当日 15:00 后结算。
- 盘中执行参考不计入模型正确率。

## 项目结构

- `qlib-service/build_intraday_v21_dataset.py`：部分时段双头数据集。
- `qlib-service/intraday_v21_features.py`：训练与推理共用的 12 维因果特征。
- `qlib-service/train_intraday_v21.py`：双头 Transformer 训练。
- `qlib-service/intraday_v21_contract.py`：请求边界。
- `qlib-service/intraday_v21_runtime.py`：CPU 推理与双头输出。
- `qlib-service/intraday_shadow_app.py`：新增独立 V2.1 路由。
- `qlib-service/contracts/predict-v2.1-intraday.schema.json`：JSON Schema。
- `api/_v2_quant.js`：盘中请求与 V2/V2.1 路由。
- `api/_ta.js`：军师量化结果适配。
- `shared/`：V2.1 输出与正确率契约。
- `test/`、`qlib-service/tests/`：JS/Python 回归测试。

## 代码风格

Python 保持纯函数式数据构建和显式边界校验：

```python
def make_intraday_samples(panel, *, sequence_length=60):
    if sequence_length < 2:
        raise ValueError("sequence_length 必须至少为 2")
    return samples
```

JS 适配器只接受结构化结果，不从文案反推概率：

```js
if (!isValidProbabilityHead(response.heads?.next30m)) {
  throw new Error('V2.1未来30分钟概率无效')

```

## 测试策略

- 数据集单测：因果窗口、午间跨时段、14:30 截止、双头标签和无未来泄漏。
- 训练单测：日期净化切分、双头损失、检查点元数据和指标输出。
- 契约单测：合法时点、非法时间、OHLCV、概率守恒和模型哈希。
- 路由单测：盘中 V2.1、盘后 V2、14:30 后单头、故障回退。
- 集成验证：真实 5 分钟数据请求 EAS，确认模型版本、`asOf` 和双头窗口。

## 边界

### 始终执行

- 测试先行。
- 训练/推理共用特征和标签定义。
- 所有模型文件做 SHA-256 固定。
- 指标未达门槛时拒绝上线。
- 后端改动部署阿里云 FC。

### 实施前需要具备

- 阿里云实验 DSW 工作区 `/mnt/workspace/quant-lab`。
- 已验证的 `minute-cache/5min-v1` 分钟缓存。
- 实验 RAM/OSS 环境变量和隔离护栏。
- GPU PyTorch 训练环境。

### 绝不执行

- 不修改现有 36 维日线生产模型口径。
- 不把部分交易日数据送入现有 V2 日终模型。
- 不混合 V2 与 V2.1 的概率或正确率。
- 不使用生产 OSS 训练候选模型。
- 不提交 Token、AccessKey、模型密钥或本地训练数据。

## 验收标准

1. 数据集测试证明所有输入都截至 `asOf`，无未来泄漏。
2. 双头模型在净化留出集分别通过全部上线门槛。
3. `/predict-v2-intraday` 对真实盘中数据返回合法双头概率。
4. 盘中军师显示 V2.1、信号时间和预测窗口。
5. 盘后仍显示 V2，且现有 V2 结果完全不变。
6. V2.1 故障时明确回退 V2，不出现空白建议。
7. V2/V2.1 正确率分别统计。
8. FC、EAS、Vercel 生产冒烟通过。
