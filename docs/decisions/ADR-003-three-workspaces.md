# ADR-003: 三工作区与同源风险预算

状态：Accepted
日期：2026-09-08

## 背景

用户要求围绕选股、买卖与仓位管理升级整个系统。已有军师、执行队列、
量化、预警和复盘，不宜再增加平行决策链或重写生产模型。
代码检查证实选股来源在加入自选时丢失，雷达未接入本账号持仓，
未知概率和研究评分的用途标识存在放行漏洞。

## 决策

- 保持 React/Vite、FC 和 OSS 架构，复用既有组件与决策编译器。
- 主导航使用市场与选股、交易与持仓、复盘与改进三个入口。
- 加入自选采用有界的 `selection-origin.v1` 元数据，并随真实成交保留。
- 元数据不属于真实交易事实，不因新增来源文字重跑模型或令执行计划失效。
- 使用共享纯函数统一持仓、待买预留、现金储备和风险预算计算。
- 外部机会评分必须显式声明非研究用途并允许生产使用，才参与执行依据。
- 单次结果残差 P10 与均值置信下界分开，避免将尾部可能亏损等同于负期望。
- 无对应价格合同的可靠成功概率时只提供观察，不伪造正期望。
- 不连接券商，不把用户确认、计划完成、剩余持仓归零混为一谈。

## 备选与取舍

不采用重写 Next.js、新数据库、第二套策略路由或增加模型调用次数的方案。
现有系统的主要问题是接口语义和关联缺失，重写增加迁移及并发风险。
采用增量字段与兼容入口，原账本和旧建议继续可读。

## 后果与回滚

部分旧建议因缺可靠概率会降为观察，这是明确的安全行为变化。
新来源字段不能补造旧成交的选股理由。历史统计明确当前账本覆盖范围。
回滚使用发布前部署或 FC 运行包，保留 OSS 账本和新增元数据；
不得通过回退账号快照撤销用户在发布后的真实交易。

验证与发布记录见 [升级规格](../system-upgrade-20260908.md)。
