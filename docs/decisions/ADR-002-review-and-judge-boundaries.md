# ADR-002: 快速复核与 LLM Judge 分层并共享结构化输入

## 状态

Accepted

## 日期

2026-08-30

## 背景

系统存在两类临盘动作：

- 观察价到达后，需要重新判断原方向是否仍成立，并形成可人工确认的执行方案。
- 已有可执行计划到达买入、加仓、减仓、止盈或止损价后，需要在价格窗口内
  快速判断此刻是否执行。

两类动作都需要读取原军师计划、实时资金和分时走势，因此容易被误解为重复调用
两个 LLM。旧实现已经按预警类型分流，但两条路径分别组装上下文；上一轮
“放量/缩量、站上/跌破 VWAP、主力与小单关系”等结论主要以自然语言传递，
无法稳定比较前后变化。Judge 也只有触价后窗口原语，没有显式的开盘至今走势
合同。

## 决策

1. 快速复核和 Judge 继续使用不同角色端点，且同一价格触发只能进入其中一条：
   - `reviewOnly` 观察价进入快速复核。
   - 已有可执行计划进入 Judge。
   - Judge `confirm` 只推进执行状态，不再调用快速复核；只有 `invalid` 或实质
     计划冲突才允许创建一次新计划。
2. 快速复核负责计划重评：
   - 在 2 分钟总期限内完成一次 LLM 生成，模型预算最多 45 秒。
   - 可以确认或否定原方向，并给出本轮成交区间、手数、止损、目标和后续计划。
   - 不得创建新的观察价或围绕同一触发继续循环。
3. Judge 只负责执行闸门：
   - 在 10 秒内用 LLM 判断 `confirm` / `wait` / `invalid`。
   - 不改变原方向，不重写止损、目标或后续计划。
   - 成交区间和手数受原价格契约、持仓、T+1 和服务端风控约束。
   - 后续计划直接继承原军师计划，不再让 Judge 生成第二套计划。
4. 硬止损和账户、价格契约等硬约束先由确定性规则处理。LLM 超时、不可用或
   输出不完整时，回退到确定性结果；证据不足默认不执行。
5. 两条路径统一消费 `review-decision-packet.v1`，包含：
   - 原计划价格、结论、执行条件、失效条件、仓位上限和后续计划。
   - 当前报价、主力与小单资金、开盘至今分时摘要、触价后结构、日线技术和账户。
   - 上一轮与本轮量能、VWAP 位置和资金关系的结构化差分。
   - 当前角色允许的结论和禁止修改的边界。
6. 每轮军师或快速复核输出 `advice-review-memory.v1`：
   - 量能使用 `EXPANDING` / `CONTRACTING` / `NORMAL` / `UNKNOWN`。
   - VWAP 位置使用 `ABOVE` / `BELOW` / `AROUND` / `UNKNOWN`。
   - 资金关系使用吸筹、派发、同向流入、同向流出、混合或未知对应的稳定枚举。
   - 同时保留原始数值、观察时间、来源和执行条件。
   - 旧建议没有该结构时，可从自然语言降级解析，并标记 `LEGACY_TEXT`。
7. `intraday-open-summary.v1` 对开盘至今分钟数据做有界压缩：保留开盘、现价、
   高低点、VWAP、开盘涨跌、区间位置、量能比、高低点结构和最多 8 个路径采样点，
   不把数百根分钟线原样发送给模型。
8. 所有交易动作仍必须由用户人工确认；结构化复核结论不代表券商报单或成交。

## 备选方案

### 所有触价先快速复核，再调用 Judge

拒绝。相同实时证据会被两个模型重复读取，延迟和费用翻倍；两个模型还可能给出
互相冲突的终局结论。

### 完全取消 LLM，只用确定性规则

拒绝。硬规则适合账户、价格契约、T+1 和明显破位，但难以处理资金背离、分时
承接、原计划语义和多证据冲突。LLM 保留在有限、结构化的裁决范围内。

### 只传自然语言摘要

拒绝。模型能理解“放量/缩量”，但不同轮次的措辞、时间和口径不稳定，无法可靠
判断状态是否改变，也不利于测试和事后归因。

## 后果

- 同一触发最多发生一次主要 LLM 决策。
- 快速复核可以形成新的终局执行方案；Judge 只能确认既有计划。
- 上一轮结论可稳定参与下一轮比较，且保留数值和时间以避免语义漂移。
- Judge 输入增加开盘至今结构，但采用有界摘要，网络调用和模型输出预算不增加。
- 新合同为增量字段；旧建议继续通过自然语言降级兼容。
