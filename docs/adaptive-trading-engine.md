# 自适应短线决策引擎

## 目标

系统不再回答“这只股票是否通过一组固定规则”，而是回答：

> 在当前市场、板块、个股和账户状态下，哪一个可执行动作拥有最高费后价值？

搜索机会要宽，资金下注要精确。市场弱、非主线、涨幅偏高、单项资金背离等
不再自动等于禁止交易；它们改变打法、成交概率、风险预算和复核条件。

## 决策权

决策优先级固定为：

1. 账户与交易事实：现金、持仓、真实成交、T+1、可卖手数。
2. 执行合法性：价格来源、涨跌停、整手、止损、费用、滑点、流动性。
3. 动作价值：成交概率、费后净R、悲观净R、尾部损失、机会成本。
4. 市场与打法：决定策略权重和风险预算，不做普通全局开关。
5. LLM：解释证据、反方和失效条件，不决定价格、手数和最终动作。

## 市场机会地图

`shared/marketOpportunityContext.js` 将市场投影为连续状态：

- 机会强度与市场广度
- 炸板和跌停压力
- 机会倍率与基础单笔风险
- 趋势扩张、主线推进、修复、轮动、分歧、高波动、退潮、恐慌

状态标签只用于解释。实际计算使用连续因子和打法权重。

## 六种打法

`shared/opportunityPlaybooks.js` 同时计算：

- 主升突破
- 核心回踩
- 资金潜伏
- 催化先手
- 恐慌修复
- 区间低吸

旧公式命中只作为特征，不再拥有放行或否决权。

## 三路径竞争

`shared/adaptivePricePlans.js` 为未持仓股票同时生成：

- 现价路径
- 回踩路径
- 突破路径

每条路径必须有合法入场价、结构失效价、目标价、有效期和T+1说明。
`shared/adaptiveOpportunity.js` 分别计算：

- `pFill`
- `pWinGivenFill`
- `expectedNetR`
- `lowerNetR`
- 单笔风险率和最大仓位
- 动作价值

统一 `1.8:1` 或 `2.2:1` 门槛已删除。最终硬条件是费后期望为正，
并根据 V3 下置信界、尾部损失和账户容量缩小风险。

## 全市场扫描与反事实学习

`api/_formula_selection_data.js` 每轮物理读取完整市场，按四个互补通道抽取
深度样本：

- 动量
- 资金潜伏
- 超跌修复
- 高流动性

剩余名额使用稳定探索样本，避免只学习旧公式偏好的股票。每只深查股票的
现价、回踩和突破路径都写入 `counterfactualPlans`，离线结算按路径拆开，
而不是只结算最终展示结果。

机会模型特征协议为 `opportunity-score-feature.v3`，新增打法、路径、打法分和
市场机会倍率。以下指标继续作为每日诊断与模型质量报告，不再作为 V3 使用
前置条件：

- 独立 walk-forward 窗口稳定
- Top5 费后净R下置信界大于0
- Top5 费后净R较旧公式提升至少20%或0.05R
- 最大回撤恶化不超过10%
- 正净R命中率不低于旧公式

运行 `npm run opportunity:promote` 执行后置诊断。线上只接受
`usagePolicy=DIRECT` 的有效 V3 结果，不使用影子分、研究先验或灰度排序。

生产 FC 在每个交易日 10:20、13:40、15:10 自动生成反事实账本，17:10
结算可成熟路径。GitHub Actions 每个工作日北京时间 01:15 自动合并云端
历史基线与最近成熟结果、训练当前 V3、发布不可变权重、执行后置晋级诊断并
更新作战台训练状态。

“今日作战”的预催化、盘中公式、收盘公式和尾盘候选统一比较 V3 的现价、
回踩、突破路径。缺少生产 V3 结果时该候选不可执行，禁止用研究先验补概率。

自然前向积累至少需要 60 个独立交易日。需要提前训练时，历史数据范围和
防泄漏要求见 [V3 机会模型历史数据要求](./v3-opportunity-history-data.md)。

## 买入与持仓

`shared/adaptiveAdvicePolicy.js` 接管未持仓建议：

- 现价路径且动作价值足够时输出立即买入或小仓验证。
- 回踩或突破路径输出唯一条件指令，不同时展示多个主动作。
- LLM的模糊或相反结论不能覆盖服务端动作。

`shared/holdingActionValue.js` 同时比较：

- 加仓
- 持有
- 减仓
- 退出

硬止损和T+1优先。固定第5日退出、固定回撤减仓和弱市机械减仓已取消。
计划内第二笔只有在止损不下移、总风险不增加时允许；临时摊平禁止。
V3首次给出普通减仓或退出时只形成条件动作，不直接授权成交。系统在下一笔
有效报价后观察约60秒，再用最新价格路径、分时和资金重跑一次V3；反弹和继续
下跌都必须触发。只有复核仍支持退出才转成可执行动作，账本硬止损不等待。

## 复核与提醒

`monitoring-plan.v2` 支持：

- 价格、涨跌幅、VWAP
- 主力与小单净额
- 量比、换手率
- 日内高点回撤

个股相对强度和板块阶段不进入秒级报价规则，由五分钟事件复核更新。

同一事件只调用一次模型。终局之后只有新的实质价格、资金、板块或账户事件
才能重新进入复核。页面横幅、系统通知、声音和通知中心继续使用同一事件源。

## LLM 的职责与审计

LLM 用在个股建议、持仓解释和到价终局复核，负责：

- 整理公告、检索和催化线索
- 提出最强反方
- 提炼可观测失效条件
- 将服务端动作翻译成可执行中文
- 在触价观察结束后提供一次确认或放弃意见

每次成功建议保存 `llm-trading-contribution.v1`，记录本轮实际使用的能力、
检索/RAG 状态和服务端校验结果。LLM 不进入 V3 数值特征，也不能提高风险
预算、修改价格、手数、费后期望或覆盖硬止损；缺少对应输出时，审计记录
不会伪称该能力已被使用。

## 数据兼容边界

必须继续兼容并保留：

- `account`
- `holding`
- `closed`
- `transactions`
- `executionPlans`
- `executionAttributions`
- T+1批次、费用和真实成交关联

旧公式结果、旧建议正文、旧观察页结构和旧模型影子分不属于兼容边界。

## 验收

上线前至少运行：

```bash
npm test
npm run build
npm run harness
npm run harness:portfolio
npm run harness:execution
npm run harness:lifecycle
```

生产收益是否提升只能由独立时间窗回放和后续真实成交证明，不能用单元测试、
LLM主观评价或个别股票案例替代。
