# 自适应短线决策引擎：持仓与自选后端落地

> 状态：Draft，待确认
> 最后更新：2026-09-09
> 事实基线：`stock-dashboard@9ebfa2d`
> 上位合同：[自适应短线决策引擎](./adaptive-trading-engine.md)
> 配套前端章节：[持仓与自选前端落地](./holding-management-frontend-redesign.md)

## 一、执行摘要

本文不是新的“持仓决策引擎”，而是规定现有自适应总引擎如何接管自选买入、持仓管理、
做 T、复核和提醒。

唯一决策主链保持不变：

```text
全市场完整扫描
  -> 六打法并行竞争
  -> 现价 / 回踩 / 突破三路径竞争
  -> 费后动作价值与动态风险预算
  -> 自选买入或持仓动作
  -> 事件监控与一次复核
  -> 人工真实成交
  -> 反事实与实盘结果学习
```

本次重构的本质是把持仓和自选接到这条主链上，删除它们自己的固定排序、本地口诀、
前端二次风控和独立生成逻辑。系统最终回答的不是“这只股票是否满足若干理论”，而是：

> 当前账户的一单位风险，继续放在现有持仓、投入某只自选，还是暂时保留现金，哪一个费后价值最高？

## 二、问题定义

### 2.1 当前状态与证据

| 已确认事实 | 造成的问题 |
| --- | --- |
| `App.jsx` 已将生产 `TodayTab` 指向 `AdaptiveWorkbench` | 今日作战已切换，但持仓和自选仍未完整消费同一排序与动作价值 |
| `watchlistRanking.js` 仍按量化 55% 和距买点 45% 排序 | 自选脱离六打法、三路径和账户资金竞争 |
| `holdingActionValue.js` 仍以固定权重合成分数 | 持有、加仓、减仓、退出没有统一为费后经济价值 |
| `PlanTab.jsx` 仍包含“踏 5 不破 10”、固定 -8%/+10% 和时段口诀 | 前端与服务端形成双裁决 |
| `buildTodayCommandList` 仍可根据旧市场状态二次阻断买入 | 后端自适应结果可能被旧全局闸门覆盖 |
| 单股 LLM 请求已具备市场、资金、技术和量化数据 | 数据存在，但应先完成服务端动作计算再交给 LLM 解释 |
| 机会雷达已经返回六打法和自适应动作价值 | 应直接复用，不能在持仓模块再建一套评分 |
| 五日主力/小单资金已有完整性语义 | 应进入打法、路径与持仓延续价值，不能只生成说明文字 |

### 2.2 核心差距

当前系统的能力已经存在于多个模块，但持仓、自选和今日作战没有使用同一份决策结果。
这导致：

1. 全市场发现的最佳机会不能稳定进入自选排序；
2. 持仓复核不知道全市场当前最强替代机会；
3. 市场、资金、板块和量化在不同层被重复加分或重复阻断；
4. 用户仍需手动生成、设置预警和在多个按钮中自行选择；
5. 真实成交与漏选结果没有完整反向校准持仓和自选动作。

## 三、目标与非目标

### 3.1 目标

- 六打法和三路径成为自选买入的唯一上游；
- 持仓的加仓、持有、减仓、退出与全市场最佳候选同口径竞争；
- 市场环境改变打法权重、持有窗口和风险预算，不做普通全局否决；
- 当日及五日资金必须与价格、量能、板块地位共同解释；
- 每只股票只有一个服务端最终动作、一个 `decisionId` 和一组有效监控；
- 系统自动观察、复核和提醒，用户只负责人工执行与记录真实成交；
- 真实成交和全市场反事实结果进入同一学习闭环。

### 3.2 非目标

- 不重建第二套机会模型或持仓评分框架；
- 不让 LLM 自行决定动作、路径、价格、手数或费后期望；
- 不改变 `/predict` 的 36 维 OHLCV 口径；
- 不连接券商、不自动下单；
- 不兼容旧建议正文、旧公式结果、旧观察页或旧影子分；
- 不以提高交易次数代替提高费后净 R；
- 不承诺通过工程改造必然获得实盘盈利。

## 四、核心约束

### 4.1 决策权顺序

1. 账户与真实交易事实；
2. 执行合法性；
3. 自适应动作价值；
4. 市场机会地图与六打法；
5. LLM 对既定动作的解释、反方和失效条件。

LLM 不能覆盖服务端动作。它可以解释资金行为、题材阶段和证据冲突，但这些解释不得反向
改写路径、价格、手数、账户风险或费后期望。

### 4.2 必须保留

- `account`、`holding`、`closed`、`transactions`；
- `executionPlans`、`executionAttributions`；
- T+1 批次、费用、FIFO 做 T 和含费成本；
- OSS 原子锁、任务租约、账号隔离和角色端点隔离；
- 显式持续复核白名单；
- 非正期望禁止新增风险；
- 风险减少动作不被新增风险规则阻断。

### 4.3 “不影子、不灰度”的准确边界

- **产品功能**：不同时运行新旧持仓逻辑，不按账号或比例灰度；验收通过后一次性替换。
- **机会模型**：仍必须遵守既有影子评估和 `opportunity:promote` 晋级门禁。该过程只验证
  模型，不能生成用户可执行的影子建议，也不是产品灰度。
- **回滚**：保留完整部署版本回滚，不保留运行时双轨开关。

## 五、目标架构

### 5.1 不新增第二决策核心

继续使用以下唯一链路：

| 总引擎模块 | 在自选和持仓中的职责 |
| --- | --- |
| `marketOpportunityContext.js` | 提供连续市场机会环境和风险倍率 |
| `opportunityPlaybooks.js` | 六打法同时评分，输出当前最适合打法 |
| `adaptivePricePlans.js` | 为未持仓股票比较现价、回踩、突破 |
| `adaptiveOpportunity.js` | 计算成交概率、费后净 R、尾损、仓位和动作价值 |
| `adaptiveAdvicePolicy.js` | 将最优未持仓路径转换为唯一买入或等待动作 |
| `holdingActionValue.js` | 比较加仓、持有、减仓和退出 |
| `decisionPlan.js` | 编译最终价格、手数、风险和有效期 |
| `monitoringPlan.js` | 编译当前决策对应的可监控条件 |
| `executionPlan.js` | 将可执行动作转换成人工执行计划 |

持仓模块只能扩展这些模块的输入和投影，不能再增加一个平行的“持仓评分器”。

### 5.2 完整运行链

```text
机会雷达全市场结果
  ├─ 未持仓 -> 三路径 -> adaptiveAdvicePolicy -> decision-plan.v2
  └─ 已持仓 -> 当前持仓价值 + 最强替代机会 -> holdingActionValue
                                             -> decision-plan.v2

decision-plan.v2
  -> monitoring-plan.v2 / 五分钟事件
  -> reviewJobs
  -> 同源通知
  -> execution-plan.v1
  -> 真实成交
  -> 重新计算账户与动作
```

## 六、自选买入落地

### 6.1 两类来源，同一决策

**机会雷达加入**

- 保留 `selection-origin.v1`；
- 带入六打法结果、三路径、当时市场环境和证据时间；
- 加入自选后不得重新退化为“量化分 + 距买点”排序。

**用户手动搜索加入**

- 先成为普通收藏；
- 用户选择“纳入作战”后，服务端按当前行情补齐同一套市场、板块、资金、技术和量化事实；
- 调用同一个 `chooseAdaptivePricePlan`，不得走旧通用买入建议。

### 6.2 三路径必须完整竞争

每次生成或实质事件复核都计算：

| 路径 | 适用判断 | 必须输出 |
| --- | --- | --- |
| 现价 | 当前承接与动作价值最优 | 入场、止损、目标、手数、有效期 |
| 回踩 | 当前追价价值低，但回踩后价值提高 | 回踩价、重新站稳条件、失效条件 |
| 突破 | 只有突破后优势才成立 | 突破价、量能/承接确认、失效条件 |

每条路径必须使用同口径：

- `pFill`；
- `pWinGivenFill`；
- `expectedNetR`；
- `lowerNetR`；
- `expectedShortfall10R`；
- 费用与滑点；
- 动态最大仓位；
- 有效时段。

最终只发布动作价值最高且合法的一条。其余路径只进入详情中的“未选方案”，不得同时成为
主操作。

### 6.3 自选排序

删除 `watchlistRanking.js` 的固定 55/45 主排序。已纳入作战的自选按以下顺序：

1. 已确认可执行且账户有预算；
2. 到价观察或复核中；
3. 条件路径的动作价值；
4. 距触发距离；
5. 计划有效期。

普通收藏固定排在已纳入作战之后，不使用默认量化分伪装成买入优先级。

### 6.4 市场和资金如何参与

- 弱市降低动量突破权重，但提高独立催化、恐慌修复等打法的相对权重；
- 高位不自动判定追高，需结合板块扩散、剩余空间、量能和资金承接；
- 主力流出、小单流入只有同时出现高位走弱或板块退潮时才强化派发风险；
- 主力流入、小单流出只有价格守住 VWAP、相对强度未走弱时才视为主动承接；
- 五日资金不足时不得判断“持续流入/流出”，也不得填零；
- 市场、板块、资金等软因素只改变打法、动作价值和仓位，不能重复升级为全局禁止。

## 七、持仓管理落地

### 7.1 主要动作只保留四种

`holdingActionValue.js` 是持仓唯一动作核心：

- `ADD`；
- `HOLD`；
- `REDUCE`；
- `EXIT`。

做 T 不是第五套独立持仓方向。只有主动作是 `HOLD`、底仓与可卖数量合法、预期价差覆盖
双边费用和滑点时，才允许附加一个 `tPlan`。若主动作是减仓、退出或硬风险处理，做 T
立即失效。

### 7.2 持仓动作必须与全市场机会竞争

每次持仓评估必须输入：

- 当前持仓的打法、持有窗口和原始失效条件；
- 当前价格、成本、持仓高低点、MFE/MAE；
- 当日及五日主力/小单资金与价格反应；
- 板块阶段、个股角色和相对强弱；
- 当前量化概率与尾部损失；
- 当前账户风险、可卖手数和 T+1；
- 机会雷达中账户可执行的最佳未持仓候选。

持仓比较不再使用抽象固定分，而使用同一经济口径：

```text
继续持有价值
= 当前持仓未来费后净 R
- 尾部损失
- 资金占用机会成本

降低仓位价值
= 避免的尾部损失
+ 释放后的可用风险价值
- 卖出费用和滑点

换仓净增量
= 最强候选费后动作价值
- 当前持仓继续持有价值
- 卖出与再买入成本
- 新仓 T+1 隔夜风险
```

“最强候选”必须来自当前机会雷达，并经过账户预算分配；禁止由 LLM虚构替代股票。

### 7.3 动态持仓状态

持仓只使用以下事实状态，不绑定固定买卖结论：

- 强化：板块、相对强弱、资金和量价继续支持原打法；
- 正常：原逻辑未失效，替代机会优势不足；
- 弱化：延续价值下降，但尚未达到退出条件；
- 派发：高位价格走弱且主力流出、小单承接；
- 失效：硬止损、重大负面或原价格结构被破坏；
- T+1 锁定：应退出但当前不可卖。

动作由这些状态对应的费后价值产生，不能写成“强化必加仓”“弱化必减仓”。

### 7.4 动态退出

删除固定第 5 日退出、固定回撤减仓和固定 -8%/+10% 默认计划。退出按以下优先级：

1. 硬止损或确定性风险；
2. 原打法失效；
3. 板块退潮且个股掉队；
4. 主力派发并伴随价格确认；
5. 目标区域后的分批兑现；
6. 持有价值低于换仓净增量；
7. 催化窗口结束且走势效率不足。

强势延续时允许移动保护和延长持有；亏损时只有预先声明的第二笔、止损不下移且总风险
不增加，才允许加仓。

### 7.5 做 T

`tPlan` 必须同时满足：

- 已有可管理底仓；
- 预计价差覆盖双边费用和滑点；
- 不破坏主持仓硬止损；
- 卖出腿不超过今日可卖；
- 买入腿不会超现金和账户风险；
- 未完成一腿时只允许继续既定下一腿或停止。

系统只发布当前一腿，下一腿由事件监控触发，不再让用户先选“稳健/均衡/激进”。

## 八、LLM 在本章节中的职责

### 8.1 输入

LLM 在服务端已经选定动作后读取：

- `short-horizon-tactical.v1`；
- `adaptiveAction.selected`；
- `decision-plan.v2`；
- 当日与完整五日资金摘要；
- 最强反方证据；
- 账户和 T+1 约束；
- 当前复核事件。

### 8.2 输出

LLM只负责：

- 解释为什么当前动作优于其他合法动作；
- 解释主力与小单资金和价格反应；
- 给出最强反方；
- 将失效条件转换为可观测语义；
- 生成白话执行说明；
- 在到价复核中提供一次确认或放弃意见。

### 8.3 服务端强制覆盖

如果 LLM：

- 输出与 `adaptiveAction.selected` 不同的动作；
- 修改价格、手数或仓位；
- 绕过费后期望、现金、T+1 或硬止损；
- 引用不存在的证据；

则 `adaptiveAdvicePolicy.js` 和 `decisionPlan.js` 必须覆盖模型输出并记录
`serverAdjust`。模型解释失败不能把完整服务端动作变成“保守计划”，也不能伪造成功。

## 九、复核与提醒

### 9.1 复核授权

- 持仓和自选继续使用 `advAuto.holdCodes` / `advAuto.watchCodes` 显式白名单；
- 新增股票不得自动加入；
- 用户在“纳入作战”或记录买入时明确授权；
- 授权后不再要求用户配置技术参数或手动定时刷新。

### 9.2 秒级与五分钟职责

**秒级报价规则**

- 价格；
- 涨跌幅；
- 主力/小单净额；
- VWAP；
- 量比、换手；
- 日内高点回撤。

**五分钟事件**

- 个股相对指数/板块强弱；
- 板块扩散、分化和退潮；
- 资金关系反转；
- 量化高把握状态变化；
- 催化失效；
- 账户成交和风险预算变化。

### 9.3 到价复核

```text
到价
  -> watching 弱提醒
  -> 约 60 秒观察价格路径
  -> 采集价格、VWAP、量能、资金、板块
  -> 确定性分数与动态动作价值差
  -> Judge 一次确认或放弃
  -> 唯一终态通知
```

- 快速深破和硬止损不等待模型；
- 普通到价复核最多 45 秒模型预算且只调用一次；
- 阈值由确定性分数边际、动作价值差和尾部风险动态计算；
- 禁止恢复买入 78、卖出 70、止损 65 的固定阈值；
- 原事件结束后，只有新的价格、资金、板块或账户事件才可再次复核。

## 十、学习闭环

### 10.1 全市场反事实

每只深查股票的现价、回踩和突破路径都写入 `counterfactualPlans`，无论是否展示或加入
自选都必须结算：

- 是否成交；
- 1/3/5 日费后净 R；
- 最大有利/不利波动；
- 目标先到还是止损先到；
- 当时市场阶段、打法、路径和资金状态。

这解决“只学习旧规则选中股票”的选择偏差。

### 10.2 真实持仓结果

只有完整且核验过的真实成交进入实盘学习：

- 真实成交价、费用和滑点；
- 持有时间；
- MFE、MAE 和盈利捕获率；
- 止损执行偏差；
- 做 T 配对结果；
- 换仓前后的增量净 R。

### 10.3 如何反向影响系统

- 反事实结果训练和校准 `opportunity-score-feature.v3`；
- 已晋级模型改变三路径概率、净 R、尾损和排序；
- 真实成交结果只在样本充分时调整风险倍率和置信表达；
- 任何新模型必须先完成内部影子评估和晋级门禁；
- 不允许 LLM、前端或人工直接修改生产概率。

- `execution-plan.v1`；
- 任务运行态。

它不能重新排序、重算动作或持久化第二份决策。错误统一返回：

```js
{
  ok: false,
  error: {
    code: 'POSITION_WORKBENCH_UNAVAILABLE',
    message: '持仓决策暂不可用',
    details: []
  }
}
```

账号未登录返回 `401`；账本版本冲突返回 `409`；输入语义无效返回 `422`；部分数据源失败
仍返回 `200`，但在对应股票上标记 `STALE` 或 `EVIDENCE_INCOMPLETE`。

## 十二、FC 与任务调度

### 12.1 保持现有角色隔离

- `advisor`：用户主动快速/深度研判；
- `review`：定时、到价和 Judge 复核；
- `portfolio`：账户资金诊断；
- 不得借用其他角色端点扩容。

### 12.2 请求顺序

```text
读取最新 OSS 账本
  -> 获取账户相关报价
  -> 获取当前机会雷达最佳候选
  -> 构造市场、打法、路径、资金和账户事实
  -> 服务端先选动作
  -> LLM 解释该动作
  -> 编译 decisionPlan / monitoringPlan / executionPlan
  -> 校验交易事实指纹
  -> 写单股增量对象
  -> 更新聚合读模型
```

### 12.3 性能与成本

- 快速建议只等待价格决策必需证据；
- 五日资金、日线和板块结果按已有缓存复用；
- 无实质变化只写复核回执，不调用模型；
- 到价/Judge 保留两路 `review` 容量；
- 聚合读模型不触发新的模型生成；
- 前端读取失败时保留上一有效计划并明确过期状态。

## 十三、必须删除的旧决策

- `PlanTab.jsx` 中 `tap5break10`；
- `PlanTab.jsx` 中 `intradayPlaybook`；
- 固定 -8% 止损和 +10% 止盈兜底；
- `watchlistRanking.js` 的固定 55/45 主排序；
- `TodayTab` 对服务端动作的旧市场二次阻断；
- 前端根据建议文字重新推导动作；
- 卡片直接编辑系统买入价和计划手数；
- 以定时批量重新生成代替事件复核；
- 旧公式在全市场召回前淘汰股票。

## 十四、备选方案与决策

| 方案 | 结果 | 决策 |
| --- | --- | --- |
| 在当前持仓模块外围再建账户决策器 | 与自适应总引擎形成第二套动作源 | 拒绝 |
| 只改 Prompt 和卡片 | 无法消除旧排序、旧闸门和机会成本缺失 | 拒绝 |
| 让 LLM 在相近方案中选择动作 | 与现行决策权合同冲突，稳定性不可审计 | 拒绝 |
| 直接让总引擎接管持仓和自选 | 单一动作源，可复用已有模型、风险和执行合同 | 采用 |

最强反方是：一次替换范围大，失败影响主交易链。该风险通过离线回放、Harness、测试账号
全链路和整版本回滚控制，不通过生产双轨规避。

## 十五、优先级与里程碑

### M1：自选接入总引擎

Outcome：所有已纳入作战的自选都由六打法和三路径产生唯一买入决策。

退出条件：

- 雷达加入和手动加入最终进入同一 `adaptiveAdvicePolicy`；
- 自选不再使用 55/45 排序；
- 弱市独立催化、恐慌修复等场景不会被旧市场闸门覆盖；
- 三路径的概率、净 R、尾损和仓位均可追溯。

### M2：持仓接入全市场资金竞争

Outcome：持仓动作包含当前持仓价值和最强替代机会。

退出条件：

- 加仓、持有、减仓、退出使用同一经济口径；
- 固定第 5 日、固定回撤和固定止盈止损不再产生动作；
- 卖出收入在真实成交前不进入买入预算；
- 做 T 只能作为合法 `HOLD` 下的附属计划。

### M3：自动复核闭环

Outcome：授权股票无需用户手动刷新即可完成观察、复核和提醒。

退出条件：

- 秒级与五分钟事件边界清楚；
- 同一事件模型调用最多一次；
- 同股建议、监控、通知和执行计划使用同一 `decisionId`；
- 页面离线时 FC Timer 能完成兜底。

### M4：产品一次性切换

Outcome：生产只运行自适应总引擎的持仓与自选链路。

退出条件：

- 旧前端裁决和旧主排序已删除；
- 全量测试、全部离线 Harness、构建和 FC 打包通过；
- 测试账号完成真实股票数据闭环；
- Vercel 与 FC 使用同一前端构建；
- 已准备可恢复的发布前部署版本。

## 十六、验收与指标

### 16.1 必测场景

| 场景 | 预期 |
| --- | --- |
| 弱市独立催化核心 | 缩小仓位但不因弱市直接淘汰 |
| 强市高位主升 | 根据承接和剩余价值继续持有或受控加仓 |
| 五日主力流出、小单流入、高位走弱 | 派发风险进入减仓/退出价值 |
| 主力流入、小单流出、价格守住 VWAP | 识别主动承接，不机械否决 |
| 原持仓正常但出现更强候选 | 只有换仓净增量覆盖成本才轮动 |
| 新仓当日止损 | 标记 T+1 锁定和下一可卖时段优先退出 |
| 做 T 第一腿未完成 | 不生成相反方向的新一轮做 T |
| 到价后重新站回均价线 | 一次复核可继续持有或确认买入 |
| 五日资金仅取得 3 日 | 明确“近 3 日”，不推断五日持续性 |
| LLM 输出相反动作 | 服务端动作不变并记录调整 |

### 16.2 工程门禁

- 非法价格、超现金、超可卖手数、T+1 错误均为 `0`；
- 同股动作冲突、错版监控和重复通知均为 `0`；
- 全市场读取数量严格一致；
- 前端与 FC 对同一 `decisionId` 的动作、价格和手数一致；
- 快速、深度和复核均只有一次完整模型生成；
- `npm test`、`npm run harness`、`harness:portfolio`、`harness:execution`、
  `harness:lifecycle` 和构建全部通过。

### 16.3 效果指标

- Top5 费后净 R 与下置信界；
- 分打法和分路径的成交率、成功率、净 R 与最大回撤；
- 持仓盈利捕获率、MFE、MAE 和退出效率；
- 换仓后的增量净 R；
- 被旧规则排除但后续产生正净 R 的漏选率；
- 提醒后有效动作率和用户实际执行偏差。

工程验收不能证明收益提升；收益必须由独立时间窗回放和后续真实费后成交验证。

## 十七、风险、发布与回滚

- 不做用户侧影子建议、不做账号灰度、不保留旧/新运行时开关；
- 机会模型继续按内部影子评估和晋级门禁运行；
- 发布前只用本地脱敏夹具和测试账号完成有副作用验收；
- 发布后生产个人账号只读检查；
- 前后端必须在同一发布窗口完成 Vercel 与 FC 双部署；
- 回滚使用完整前端部署和 FC 运行包，不回滚用户真实账本；
- 若出现动作冲突、交易事实丢失或负期望放行，立即整版本回滚。

## 二十、决策记录

**决定**：持仓与自选直接落到现有自适应总引擎，不建立第二套账户决策核心。
**主要依据**：总引擎已定义市场、打法、路径、价值和学习；当前缺口是落地断裂。
**最强反方**：直接替换影响范围大。
**接受代价**：以更高的发布前验证成本换取生产单链路，避免长期双轨。
**翻转条件**：若不能保证前端不再裁决、同股唯一动作或账户交易数据不丢失，则停止发布。
**状态**：Proposed。
