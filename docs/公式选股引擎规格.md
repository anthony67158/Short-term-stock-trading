# 公式选股引擎规格

## 一、目标

将“尾盘拾金”升级为覆盖盘中、尾盘、盘后和个股详情的确定性公式引擎：

- 盘中连续竞价期间可随时手动扫描全市场，寻找当下仍可观察的股票。
- 收盘后基于完整日线生成下一交易日关注池。
- 保留原“尾盘拾金”为 `TAIL_REVERSAL` 公式，不修改原 TN6 条件。
- 个股详情根据持仓状态输出唯一主路径：
  - 未持仓：唯一观察/买入参考价，或明确“不适合买”。
  - 已持仓：唯一卖出/减仓边界，或明确“继续持有”。
- 所有公式均为确定性代码，LLM 不参与命中、排序和定价。

成功不等于“每天必须有股票”。没有通过风险闸门的标的时，结果必须为空。
任何未通过样本外回测的公式只允许显示“观察”，不得包装为稳定盈利策略。

## 二、用户流程

### 2.1 今日决策

原“尾盘拾金”面板改名为“公式选股”，使用三个视图：

1. `盘中机会`
   - 连续竞价期间允许手动运行。
   - 使用运行按钮刷新当下快照。
   - 最多展示 5 只，不自动重复调用。
2. `次日关注`
   - 每个交易日 15:05 自动生成，15:10 仅在缺失时重试。
   - 盘后手动运行只生成下一交易日观察池。
3. `尾盘反转`
   - 复用现有 14:50 正式版和手动试算。
   - 原 TN6 严格结果与接近观察结果继续分层展示。

每只候选固定展示：

- 公式名称、当前状态、数据时间。
- 唯一操作：观察、等待买入复核、不买。
- 唯一主价位及其类型。
- 止损、目标和盈亏比；仅当价格合同完整且至少 `1.8:1` 时展示。
- 三条可追溯依据和明确失效条件。
- 公式验证状态：`观察中` 或 `已通过样本外验证`。

### 2.2 个股详情

在行情与量化区之后增加独立的“公式价位”区域。它与军师建议分开请求、
分开加载、分开报错，不能嵌入军师卡片或由军师生成：

- 未持仓：
  - `等待回踩`：显示一个向下观察价。
  - `等待突破`：显示一个向上观察价。
  - `当前不适合买`：不显示伪造价格。
- 已持仓：
  - `继续持有`：显示一个风险卖出边界。
  - `减仓`：显示一个减仓价和今日可卖手数。
  - `退出`：显示硬止损价；受 T+1 锁定时显示下一交易日优先退出。

虽然结构化数据可保留备选锚点，用户首屏只显示一条主路径，禁止使用“回踩或突破任选”。

“公式价位”区域固定展示：

- 公式名称和数据截止时间。
- 当前动作、唯一主价位、止损/目标和失效条件。
- 价位采用的技术锚点。
- 当前验证状态和军师实际参考权重。

军师建议仍是独立区域。公式价位更新失败不得清空最近一次完整军师建议，
军师生成失败也不得影响公式价位的确定性计算。

## 三、公式集合

### 3.1 `TAIL_REVERSAL`：尾盘反转

- 来源：现有 TN6 尾盘拾金原公式。
- 时间：交易日 14:50 正式运行，其他时间允许手动试算。
- 原公式与接近公式规则保持现状。
- 验证状态：`OBSERVE_ONLY`。

### 3.2 `INTRADAY_VWAP_PULLBACK`：盘中回踩承接

用于寻找趋势未破、回踩均价后重新站稳的股票：

- 当前处于连续竞价，分钟数据属于当日且不超过 3 分钟。
- 日线收盘结构位于 MA20 上方，MA20 不向下。
- 近 20 日涨幅不超过 25%，当日涨幅不超过 5%，避免追高。
- 成交额不少于 5000 万元，换手率不少于 2%。
- 最近价格触及 VWAP、MA10 或近期支撑中距离当前最近的有效锚点。
- 最近 3 根完整分钟 K 收在 VWAP 上方，且没有放量跳水。
- 个股属于板块前瞻确认的方向。
- 主力当日或近 5 日净流入为正；主力流出且小单流入时否决。

唯一主路径：

- 观察价取最近的有效支撑锚点。
- 价格已经明显高于锚点超过 1 ATR 时不追，返回“不买”。
- 止损位位于近期分时低点或观察价下方 0.8 ATR。
- 阻力不足以提供 `1.8:1` 盈亏比时不生成买入参考价。

### 3.3 `INTRADAY_ACCUMULATION`：盘中资金先行

用于寻找涨幅温和但资金、量能和板块先转强的股票：

- 当日涨幅在 0.5% 至 4% 之间。
- 换手率在 2% 至 8% 之间，成交额不少于 1 亿元。
- 当前价与 VWAP 距离不超过 1 ATR，最近 5 根分钟 K 不连续走弱。
- 量比大于 1.2，主力净流入为正，小单资金不得明显反向承接。
- 近 20 日涨幅不超过 20%，不得处于涨停、炸板或高位拥挤状态。
- 板块必须是当日可布局或资金改善方向。

唯一主路径取 VWAP、MA10、近期突破回踩位中得分最高且方向合法的一个。

### 3.4 `CLOSE_TREND_PULLBACK`：收盘趋势回踩

用于盘后生成次日低吸观察：

- 收盘价在 MA20 上方，MA20 最近 3 日不下降。
- 近 20 日涨幅在 5% 至 25% 之间。
- 收盘价距离 MA10 或近期支撑不超过 1 ATR。
- 当日成交量不超过 5 日均量的 0.9 倍，回踩缩量。
- 当日收盘不低于开盘，或收盘重新站回 MA10。
- 主力当日或近 5 日净流入为正，板块方向有效。

次日唯一观察价取 MA10、近期支撑和当日低点中最高的合法支撑。

### 3.5 `CLOSE_SQUEEZE`：收盘蓄势突破

用于盘后寻找波动收敛、等待次日确认的股票：

- BOLL 带宽不超过 6%，收盘位于中轨上方。
- ATR/价格处于最近 20 日偏低区间。
- 近 20 日涨幅不超过 20%，当日涨幅不超过 4%。
- 成交量低于 5 日均量，成交额不少于 5000 万元。
- MA20 不向下，板块和资金方向有效。

唯一主路径为近期压力位上方一个最小报价单位的突破观察价。
尚未突破时不把该价格写成买入价。

## 四、个股定价引擎

新增纯函数模块 `shared/formulaPriceEngine.js`，只消费已经验证的行情事实：

```js
export function buildFormulaPriceDecision({
  code,
  quote,
  candles,
  trends,
  technicals,
  fund,
  sectorOpportunity,
  holding,
  t1Status,
  now,
}) {
  return {
    schemaVersion: 'formula-price-decision.v1',
    positionMode: 'UNOWNED',
    action: 'WATCH_BUY',
    formulaId: 'INTRADAY_VWAP_PULLBACK',
    primaryPrice: 12.34,
    priceType: 'PULLBACK_WATCH',
    stopPrice: 11.86,
    targetPrice: 13.21,
    riskReward: 1.81,
    validUntil: 0,
    evidence: [],
    blockers: [],
  }
}
```

### 4.1 未持仓优先级

1. 盘中回踩承接已成立。
2. 盘中资金先行已成立。
3. 收盘趋势回踩等待下一交易日。
4. 收盘蓄势等待突破。
5. 全部不成立时返回 `AVOID`，所有价格为 `null`。

### 4.2 已持仓优先级

1. 跌破硬止损：`EXIT`。
2. 主力流出、小单流入且跌破 VWAP/MA10：`REDUCE`。
3. 达到阻力或至少 `1.8R` 目标：`REDUCE`。
4. 其他情况：`HOLD`，风险卖出边界取 MA10、近期支撑和
   `最高收盘 - 2ATR` 中最高的合法值。

卖出动作必须叠加今日可卖手数。T+1 锁定只延迟执行，不得删除风险边界。

### 4.3 价格合法性

- 全部价格通过现有 `advicePriceContract` 校验。
- 回踩价不得高于当前价；突破价不得低于当前价。
- 止损必须低于入场价，目标必须高于入场价。
- 新增风险的盈亏比不得低于 `1.8:1`。
- 价格必须位于涨跌停合法区间，并在 1–5 个交易日 ATR 可达范围内。
- 任一关键输入缺失时返回 blocker，不猜测价格。

### 4.4 军师参考策略

公式价位只是一项次级证据。新增纯函数
`shared/formulaEvidencePolicy.js`，由服务端计算参考权重，禁止让 LLM 自己决定
公式可信度。

基础权重：

| 验证状态 | 最低要求 | 基础权重 |
| --- | --- | ---: |
| `OBSERVE_ONLY` | 未通过样本外闸门 | 5% |
| `BACKTEST_POSITIVE` | 样本外不少于30笔、期望为正、盈利因子大于1 | 10% |
| `VALIDATED` | 不少于100笔且前后窗口均为正 | 15% |

权重永远不超过 15%。以下情况权重直接归零：

- 关键行情、分钟线、资金或技术锚点缺失。
- 盘中数据超过 3 分钟，或盘后数据不是最近完整交易日。
- 价格合同校验失败。
- 新增风险的盈亏比不足 `1.8:1`。
- 买入方向被市场硬红线、板块资格或账户熔断阻止。

公式证据的作用范围：

- 可以辅助军师选择已通过价格合同的买入观察价、止损、目标和下一复核条件。
- 可以在公式和资金/量化结论冲突时降低军师置信度，并要求写出冲突。
- 不能单独把“观望”升级为“买入/加仓”。
- 不能覆盖实时行情、量化结果、资金流、T+1、现金或账户仓位。
- 不能作为唯一买入依据；新增风险至少还需要资金或量化中的一项确认。

已持仓硬止损不属于不确定性加权：只要确定性价格规则确认止损破位，
继续沿用现有风险退出优先级，可覆盖军师犹豫；公式目标位和减仓位仍按上述
次级证据权重处理。

军师接收的只读投影：

```json
{
  "formulaPriceReference": {
    "schemaVersion": "formula-evidence.v1",
    "formulaId": "INTRADAY_VWAP_PULLBACK",
    "positionMode": "UNOWNED",
    "action": "WATCH_BUY",
    "primaryPrice": 12.34,
    "stopPrice": 11.86,
    "targetPrice": 13.21,
    "riskReward": 1.81,
    "validationState": "OBSERVE_ONLY",
    "effectiveWeight": 0.05,
    "role": "SECONDARY_PRICE_REFERENCE",
    "canUpgradeAction": false,
    "conflicts": []
  }
}
```

该投影只进入军师事实合同和最终展示证据，不进入 LLM 工具规划，也不得携带
内部调试字段或完整全市场扫描结果。

### 5.2 个股价位

```text
GET /api/formula_selection?view=stock&code=600000
```

- 必须校验 6 位股票代码和账号鉴权。
- 服务端读取权威账户持仓，不接受客户端伪造持仓状态。
- 返回独立的 `formula-price-decision.v1`，同时附带只读
  `advisorReference`；不返回内部枚举解释或调试数据。

```json
{
  "schemaVersion": "formula-price-decision.v1",
  "decision": {},
  "advisorReference": {
    "schemaVersion": "formula-evidence.v1",
    "effectiveWeight": 0.05,
    "role": "SECONDARY_PRICE_REFERENCE",
    "canUpgradeAction": false
  }
}
```

军师 API 不接受客户端传入或改写该字段。生成军师建议时由服务端使用同一份
权威行情重新计算或读取未过期的服务端缓存。

### 5.3 错误语义

- `400`：非法 mode、view、股票代码或幂等键。
- `401`：未登录。
- `409`：同一模式已有运行任务。
- `422`：当前时间不允许生成正式结果。
- `503`：关键行情不完整，响应体明确缺失来源。

错误结构沿用项目现有 `{ error: "用户可理解信息" }`。

## 六、数据、存储与调度

### 6.1 扫描性能

1. 完整分页校验全市场实时快照。
2. 使用实时字段进行宽口径预筛，不能因排序提前截断。
3. 只为预筛后的有限候选补日线、分钟、资金和题材。
4. 盘中扫描总预算 45 秒，收盘扫描总预算 90 秒。
5. 任一关键分页不完整时失败关闭，不得伪装成全市场结果。

### 6.2 OSS

```text
market/formula-selection/v1/intraday/latest.json
market/formula-selection/v1/close/latest.json
market/formula-selection/v1/tail/latest.json
market/formula-selection/v1/runs/YYYY-MM-DD/<mode>-<slot>.json
market/formula-selection/v1/tasks/<mode>.json
market/formula-selection/v1/locks/<trade-date>-<mode>.json
```

旧 `market/tail-pick/v1/*` 继续只读兼容，正式迁移后由新接口双读，不删除历史。

### 6.3 调度

- 盘中：第一版只允许连续竞价期间手动运行，不新增高频 Timer。
- 收盘：交易日 15:05 自动生成，15:10 仅在正式结果缺失时重试。
- 尾盘：保留现有 14:50 正式任务和 14:52 缺失重试。

## 八、代码风格

使用纯函数返回可审计结果，所有未知值保持 `null`：

```js
export function evaluateFormulaCandidate(input = {}) {
  const price = Number(input.quote?.price)
  if (!Number.isFinite(price)) {
    return {
      matched: false,
      evidence: [],
      blockers: ['当前价格缺失'],
    }
  }
  return {
    matched: true,
    evidence: ['价格和成交数据完整'],
    blockers: [],
  }
}
```

- 公式 ID 使用 `UPPER_SNAKE_CASE`。
- Schema 使用 `kebab-case.vN`。
- 用户文案使用普通中文，不暴露内部字段名。
- 不把缺失数据转换为 `0`。
- 网络请求必须有超时和降级。

## 九、测试策略

### 9.1 单元与合同

- 每个公式至少包含完整命中、核心条件失败、数据缺失和过热否决样例。
- 定价引擎覆盖未持仓、持仓、T+1、非法价格、盈亏比不足。
- 证据权重覆盖未验证、样本外为正、稳定验证、过期归零、冲突降权和硬止损例外。
- API 覆盖鉴权、非法输入、幂等、任务冲突和降级。
- UI 覆盖三个视图、空态、失败态、桌面和移动端。

### 9.2 回测

- 至少 400 个交易日 point-in-time 数据。
- 盘中公式使用 5 分钟或更细数据，不得拿收盘数据代替盘中快照。
- 计入 5 bps 滑点、佣金最低 5 元、印花税、过户费和 T+1。
- 使用 walk-forward 样本外期望、盈利因子、最大回撤和随机同时间基线。
- 每个公式单独统计，不允许用合并后胜率掩盖失效公式。
- 未满足样本外期望大于 0 且盈利因子大于 1 时，保持 `OBSERVE_ONLY`。

### 9.3 命令

```bash
npm test
npm run harness:ci
node backtest/run-formula-selection.mjs --days 400
npm run build
```

## 十、边界

### Always

- 结果可追溯到具体公式、数据时间、证据和价格锚点。
- 新增风险必须通过市场、板块、流动性、资金、账户和 `1.8:1` 盈亏比闸门。
- 已持仓硬止损优先级高于任何买入公式。
- 公式价位与军师建议必须独立展示、独立失败；军师只消费服务端只读投影。
- 前端改动必须双部署 Vercel 和阿里云 FC。

### Ask first

- 将任何公式从 `OBSERVE_ONLY` 升级为可执行。
- 新增盘中自动 Timer 或增加付费数据源。
- 修改账户仓位上限或 T+1 规则。

### Never

- 为保证每天有结果而降低硬闸门。
- 使用 LLM 补造公式命中或买卖价格。

## 十一、成功标准

- “今日决策”显示“公式选股”而不是仅显示“尾盘拾金”。
- 连续竞价任意时刻可手动运行盘中扫描。
- 收盘后自动生成次日关注池，刷新后仍可恢复。
- 原尾盘结果无损迁移为“尾盘反转”视图。
- 个股详情根据持仓状态输出唯一主路径和可追溯价位。
- “公式价位”作为独立区域展示，军师事实合同能读取同一服务端结果。
- 未验证公式对军师权重为 5%，稳定验证后最高 15%，任何时候都不能单独升级买入。
- 公式价位与其他硬证据冲突时，军师明确展示冲突而不是静默选边。
- 无有效公式时明确返回“不买/持有”，不编造价格。
- 新公式默认观察，不进入自动交易和强预警。
- 全量测试、Harness、构建和双端线上验收通过。
