## 决策链

```text
CanonicalEvidenceSnapshot
  ↓
主军师建议
  ↓
研究员 / 风险官 / 反方（并行影子复核）
  ↓
Decision Compiler
  ↓
账户 / T+1 / 现金 / 仓位 / StrategySpec 晋级硬闸门
  ↓
影子记录（不可执行）
```

委员会的三个角色使用隔离提示词：

- `researcher`：趋势、量价、资金、事件和量化证据。
- `risk_officer`：账户、T+1、价格、仓位、现金和止损，可一票否决。
- `skeptic`：最强反方、时效问题、拥挤交易和失效路径。

任一角色失败不会影响主军师建议，但委员会记录会因角色缺席保守阻断。

## 生产晋级门禁

所有条件必须同时成立：

1. 嵌套 Walk-forward 明确为 `promote`。
2. 至少 4 个外层 fold，至少 67% 为正。
3. 最大回撤不超过 10%。
4. 对沪深 300、中证 1000 的复合超额均为正，且至少 67% fold 超额为正。
5. 至少 30 笔真实费后成交，收缩胜率不低于 55%，Profit Factor 不低于 1.2，期望为正。
6. 至少 20 条委员会影子记录，共识率和硬闸门通过率均不低于 70%。
7. 人工批准的 `specVersion` 必须与待晋级版本完全一致。

当前策略不满足第 1、2、3、4 项，因此即使提供人工批准密钥也会返回
`GATE_BLOCKED`。

## API

登录账号查看治理状态：

```text
GET /api/strategy_governance
X-Account-Nick: <urlencoded nick>
X-Account-Password: <urlencoded password>
```

只有其他门禁全部通过后才允许人工批准：

```text
POST /api/strategy_governance
X-Account-Nick: <urlencoded nick>
X-Account-Password: <urlencoded password>
X-Strategy-Approval-Key: <independent long random key>

{"action":"approve"}
```

## 环境变量

```bash
ADVISOR_COUNCIL_SHADOW=true
STRATEGY_APPROVAL_KEY=
```

- `ADVISOR_COUNCIL_SHADOW=false`：紧急关闭额外委员会 LLM 调用。
- `STRATEGY_APPROVAL_KEY` 为空：人工批准接口不可用。
- 批准密钥不得复用账号密码、LLM Key 或 `CRON_KEY`。
