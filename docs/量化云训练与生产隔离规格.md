# 量化云训练与生产隔离规格

> 状态：已批准。按 `docs/量化云训练实施计划.md` 分阶段执行。
> 更新日期：2026-08-10

## 一、目标

在不影响现有生产量化服务的前提下，建立阿里云量化实验环境，用于：

1. 复现现役 36 因子 LightGBM 基线。
2. 建立无未来泄漏、包含交易费用和 A 股交易约束的评测体系。
3. 训练多周期、多任务和分钟级候选模型。
4. 通过影子流量验证候选模型，但不影响现有 AI 建议和预警。
5. 只有通过评测护栏并经人工确认的模型，才允许晋级生产。

## 二、当前假设

1. 阿里云地域继续使用 `cn-hangzhou`，与现有 FC 和 OSS 同地域。
2. 第一阶段使用 PAI-DSW 做交互开发，后续使用 PAI-DLC 执行训练任务。
3. GPU 只用于深度时序模型和大规模参数搜索；LightGBM、特征构建和在线低频推理优先使用 CPU。
4. 实验环境使用独立 OSS Bucket，不复用生产 Bucket（已确认）。
5. 实验环境使用独立 RAM 用户或 RAM 角色，不复用现有生产 AccessKey。
6. 现有生产 `/predict`、`QUANT_URL`、`QUANT_KEY`、FC 函数 `quant-score` 和 OSS 前缀 `quantmodel/` 保持不变。
7. 第一阶段不创建常驻 GPU 推理服务，不产生 7×24 小时 GPU 费用。

如任一假设不成立，先更新本文档，再实施。

## 三、环境与命名

| 资源 | 生产环境 | 实验环境 |
|---|---|---|
| 主业务 | `stock-dashboard` | 不修改 |
| 量化服务 | `quant-score` | `stock-quant-lab-api` |
| PAI 工作空间 | 无 | `stock-quant-lab` |
| OSS Bucket | 现有生产 Bucket | 新建 `stock-quant-lab-<账号后缀>` |
| 模型前缀 | `quantmodel/` | `models/challengers/` |
| 数据前缀 | 生产业务数据 | `datasets/`、`features/` |
| 训练运行记录 | 当前重训日志 | `runs/<run-id>/` |
| 当前候选清单 | 无 | `registry/candidate.json` |
| 生产清单 | 现役热更新文件 | 实验身份不可读写或只读 |

Bucket 名全局唯一，实际名称创建时确定。代码和文档不得写入真实 AccessKey。

## 四、五层生产隔离

### 4.1 身份隔离

- 新建实验专用 RAM 身份。
- 只授予实验 Bucket 所需的最小读写权限。
- 不授予 FC、Vercel、生产 OSS Bucket、生产 RAM 和生产密钥管理权限。
- 不使用主账号 AccessKey。

### 4.2 存储隔离

- 实验数据、特征、模型、日志全部写入独立 Bucket。
- 实验训练代码启动时校验 Bucket 名和模型前缀。
- 检测到 `quantmodel/`、生产 Bucket 或空前缀时立即拒绝执行。
- 模型产物不可覆盖，路径必须包含唯一 `run-id`。

### 4.3 服务隔离

- 实验服务使用独立名称、地址和 API Key。
- 生产 FC 的 `QUANT_URL` 不指向实验服务。
- 实验服务默认不接收真实用户流量。
- 影子阶段由独立任务复制输入，不能接管生产请求。

### 4.4 发布隔离

- 训练任务只能生成 challenger，不能直接覆盖 champion。
- 自动任务没有生产写权限。
- 生产发布使用独立的人工发布身份和显式命令。
- 发布前必须校验模型校验值、特征版本、数据截止日和评测报告。
- 发布后保留上一冠军，支持一分钟内回滚清单。

### 4.5 成本隔离

- DSW 用完立即停止。
- DLC 优先使用抢占式资源，并保存断点。
- 第一阶段不创建常驻 EAS GPU 服务。
- 设置预算告警；达到预算阈值时停止新训练任务。

## 五、目标架构

```text
生产浏览器
  -> 生产 FC 主服务
      -> 生产 quant-score
          -> 生产 OSS quantmodel/

实验开发者
  -> PAI-DSW
      -> 实验 OSS datasets/ features/ runs/

定时或手动训练
  -> PAI-DLC 抢占式 GPU
      -> 读取实验数据
      -> 写入 models/challengers/<run-id>/
      -> 写入 reports/<run-id>/

影子评估任务
  -> 复制生产输入的脱敏量化字段
      -> stock-quant-lab-api
      -> 只记录预测，不返回给生产决策

人工晋级
  -> 校验评测护栏
  -> 使用独立生产发布身份
  -> 更新生产模型或生产 manifest
```

## 八、代码规范

安全校验必须显式失败，禁止静默回落到生产默认值：

```python
def require_lab_target(environment, bucket, prefix):
    if environment != "lab":
        raise RuntimeError("训练任务只允许在 lab 环境运行")
    if not bucket.startswith("stock-quant-lab-"):
        raise RuntimeError("拒绝写入非实验 Bucket")
    if not prefix.startswith("models/challengers/"):
        raise RuntimeError("拒绝写入非候选模型前缀")
```

环境变量缺失时必须终止任务，不允许默认使用 `quantmodel/`。

## 九、测试策略

### 隔离测试

- 实验 Bucket 和候选前缀可以通过。
- 生产 Bucket、`quantmodel/`、空 Bucket、空前缀全部拒绝。
- 实验身份无法写入生产 Bucket。
- 训练任务无法调用生产发布函数。

### 一致性测试

- 同一数据、同一模型下，云端基线预测与现役模型一致。
- 特征名称、顺序和数量必须写入模型元数据并在推理时校验。
- 模型文件必须记录 SHA-256。

### 量化评测

- 按日期进行 walk-forward 切分。
- 扣除佣金、最低佣金、印花税和过户费。
- 实现 T+1、涨跌停、停牌、滑点和不可成交约束。
- 同时记录 AUC、概率校准、Top-K 精确率、净收益、最大回撤、盈亏比和交易数。

## 十、实施阶段

### 阶段 0：生产冻结与基线快照

- 记录生产量化服务健康状态、模型元数据和模型文件校验值。
- 不修改生产函数、环境变量和 OSS 文件。
- 建立本地隔离规格和任务清单。

验收：生产服务输出未变化，已有模型可追溯。

### 阶段 1：阿里云实验资源隔离

- 创建 PAI 工作空间。
- 创建独立实验 Bucket。
- 创建最小权限 RAM 身份。
- 设置费用预算与告警。
- 创建 DSW，但暂不运行训练。

验收：实验身份可读写实验 Bucket，无法写生产 Bucket。

### 阶段 2：云端复现现役基线

- 将现有训练代码封装为可重复执行的训练镜像。
- 在 DSW 或 DLC 中复现 36 因子 LightGBM。
- 产物只写入 challenger 路径。

验收：预测一致、数据可追溯、训练可重复、无生产写入。

### 阶段 3：标签和交易评测升级

- 增加三重障碍和 1/3/5 日多任务标签。
- 增加完整 A 股成交约束与净收益评测。
- 将冠军晋级改为多指标护栏。

验收：无泄漏，同一保留集完成新旧模型对拍。

### 阶段 4：GPU 时序模型

- 构建分钟级数据集。
- 先训练 TCN，再与 GRU/小型 Transformer 对拍。
- 训练市场状态模型和组合模型。

验收：多个随机种子稳定，样本外收益风险指标优于基线。

### 阶段 5：影子部署

- 部署独立实验推理服务。
- 复制量化输入，不影响生产响应。
- 连续记录至少 2 至 4 周真实前向表现。

验收：服务稳定，样本量达标，真实前向指标通过护栏。

### 阶段 6：人工灰度与晋级

- 先只展示新预测，再逐步影响排序、弱提醒和强提醒。
- 每一步均可关闭并回滚到现役模型。

验收：生产错误率、延迟和交易指标均不过线时自动回滚。

## 十一、边界

### 始终执行

- 所有凭证只放阿里云凭证系统或本地未跟踪环境变量。
- 所有实验产物使用不可变 `run-id`。
- 所有训练和评测保存数据版本、代码版本、随机种子与校验值。
- 每个阶段验收通过后才进入下一阶段。

### 必须先询问

- 创建会产生费用的云资源。
- 修改 CI、生产 FC、生产 OSS、生产环境变量。
- 新增第三方数据源或付费数据接口。
- 将任何候选模型接入生产流量。

### 永远禁止

- 在聊天、代码、文档或日志中发送真实 AccessKey/Secret。
- 使用主账号 AccessKey。
- 让自动训练身份拥有生产模型写权限。
- 直接覆盖生产 `quantmodel/`。
- 在没有影子验证和人工确认时自动晋级生产。

## 十二、成功标准

1. 实验身份技术上无法覆盖生产模型。
2. 生产 `/predict` 和现有 AI 建议在前五个阶段保持不变。
3. 任意实验可由数据版本、代码版本和参数完整复现。
4. 候选模型必须在相同前向保留集上与冠军对拍。
5. GPU 仅在任务运行期间计费，闲置时不保留常驻训练实例。
6. 候选模型失败、抢占或部署异常不会影响生产服务。

## 十三、已确认参数

已确认：

1. 使用独立 OSS Bucket，不在生产 Bucket 内仅靠前缀隔离。
2. PAI 工作空间、OSS 和训练资源统一放在杭州。
3. 阿里云账号从未创建过 DSW、DLC 或 EAS，先检查并领取新用户试用。
4. 第一阶段实验月预算上限为 `300 元`。
5. 已批准本规格并进入实施阶段。
6. 第一版深度模型优先 TCN，再与 GRU 和小型 Transformer 对拍。

## 十四、预算告警暂缓记录

- 发现日期：2026-08-10
- 现象：费用与成本的“预算范围 -> 产品”列表未显示“人工智能平台 PAI”或同义产品。
- 决定：暂不创建产品预算，且不使用“百炼”“函数计算”“对象存储”等产品替代。
- 原因：替代产品会把无关或现有生产服务费用计入实验预算，无法作为实验成本护栏。
- 影响：不阻塞空实验 Bucket、RAM 最小权限身份和 PAI 工作空间的创建；阻塞所有运行中的 GPU 实例和付费推理服务创建。
- 恢复条件：PAI 出现在预算产品范围中，或产生首笔 PAI 账单后重新检查目录。
