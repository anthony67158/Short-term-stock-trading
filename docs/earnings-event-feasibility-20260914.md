# 业绩公告事件策略：首轮证据与数据可行性验证

日期：2026-09-14；状态：`BLOCKED_EVIDENCE`，仅离线研究。

## 结论

**公告路线已经开始验证，但当前尚不能计算可信的策略收益。不是“回测亏损”，也不是“空仓收益0%”，而是首次披露、原始利润口径和公告前预期尚未组成合格事件样本。**

已完成三个半年报期结构化预告的归档、去重审计、36个固定样本的官方原文抽查，以及9个固定样本的卖方预测可用性探测。收益和期末权益字段均为`null`，未模拟交易、未修改生产模型、未部署。

## 1. 本轮范围

- 报告期：2024/2025/2026年6月30日；记录观察截止2026-09-11。
- 数据源：项目现有Tushare网关、巨潮公告与原始PDF；没有购买新权限或数据，也没有调用付费LLM。
- 每期从“主板、归母利润下限为正”的最早记录事件中，按固定SHA-256排序抽12个，共36个。包含业绩预减，不把“利润为正”误当“超预期”。
- 抽样和本轮数据审计完全未使用公告后收益。它是条件化的小样本质量检查，不代表全市场策略胜率。
- 从上述样本每期再取排序最前3个，探测事件前90日卖方预测，共9个；另有一次单股接口初探。未扩大为全市场预测抓取。
- 原始数据、PDF、文本、失败尝试和输出全部保存在忽略目录；源码、规则、测试及本报告纳入版本控制。

不能把7,185条记录当作7,185次独立事件：

- 2024H1有6组同一首次日期、不同利润数值的冲突，隔离不选用。
- 三期合计15组利润区间缺失。
- 2025H1有1组首次公告日缺失。
- 2026H1有2组声明存在更早首次披露，但当前返回记录中没有那个版本。
- 采用按日期排序的最早可见记录，而不是把最新版覆盖到首发日；最早可见记录仍不构成“真实首发”证明。

网关没有提供可核对的全量版本总数，因此记录数小于接口上限并不证明版本完整。2024年3,477条接近文档3,500条上限，更不能凭“未碰上限”就宣称全量；后续须按日期分片与原文索引交叉比对。

**34/36只是“当年1月1日至事件后10日查询范围内”的分页完整，不代表自上市以来完整披露链。** 数字量级匹配也不证明数字位于正确的归母/扣非行，正负、单位和报告期必须继续核验。

28条公告时间都表现为北京时间00:00，即日期精度；不能把午夜占位当作真实发布时间，在公告日开盘前就使用这些信息。当前计划仅允许核实来源日期之后的下一交易日再评估；仍不等于已验证数据在当时可获得。

两个分页未通过样本为`002558.SZ:20260630`和`600711.SH:20260630`，响应出现重复公告ID。没有通过静默去重掩盖抓取不完整。

### 数字匹配的两个例子

- 北大医药2024H1原文为“8,300万元-9,500万元”。初版数字检查把范围连字符误当负号，已改为只检查绝对量级，并明确不核实正负语义。这是抽取器错误，不是财务源数据错误。[原始PDF](https://static.cninfo.com.cn/finalpage/2024-07-13/1220626775.PDF)
- 野马电池2024H1原文归母利润为6,128.21—7,490.03万元，结构化接口给6,128—7,490万元。不能把严格匹配失败直接归因于错误财报；它提示结构化精度损失，应以原文表格为准。[原始PDF](https://static.cninfo.com.cn/finalpage/2024-07-10/1220587612.PDF)

当前不对未读清的表格自动猜值，也不让LLM补数。

## 4. 公告前市场预期：仍未合格

9个固定样本共返回191条卖方预测记录，经证券、日期和数值检查，72条被拒绝：

- 70条属于其他证券。
- 3条报告日期不早于事件日期，与其他错误有重叠。
- 6条净利润为空或无效，与其他错误有重叠。
- 拒绝行数按行去重，错误原因计数不能直接相加。

具体证据：请求`002558.SZ`、区间20260409—20260707，响应混入`600026.SH`、`002246.SZ`等股票及20260712记录。字段过滤与证券校验不能信任响应默认正确。该问题可能位于网关、上游数据或筛选层，本轮未确定根因，不能笼统归罪于官方数据服务。

剔除不合格行后，**九个样本均无有效同报告期Q2净利润预期**：

- 大部分预测是Q4全年数值，不能除以2当作半年预期。
- `601966.SH`有一条2024Q2记录，但净利润为空，不能作为共识。
- 请求的`create_time`没有出现在本轮有效响应中，没有证据确认历史版本与修订情况。
- 仍缺券商研报原文和点时归档；某机构多篇研报不能按多家机构重复计算。

因此没有计算“实际利润减一致预期”、没有把同比增长率用作市场意外程度。报告中的预期共识和收益保持`null`。

接口初探中`express_vip`返回运行时错误、`anns_d`返回HTTP错误，未确认是权限还是其他原因，不将其写成已确定无权限；公告原文已改走现有巨潮渠道，没有绕过访问控制。

## 5. 工程修复和防护

- 巨潮请求每页100时实测返回30条、重复首屏。固定按30条请求后恢复正常分页，再严格检查公告ID唯一、总数稳定和股票代码。
- 搜索股票代码可能命中其他公司的公告；改用已核对的`orgId`绑定发行人。搜索无法解析时，仅用巨潮证券目录解析ID，目录不参与历史股票池选样。
- PDF来源限定巨潮静态域及合法路径，限制8MB/50页，验证PDF签名、SHA-256并保存提取文本。每次失败保留旧尝试，不覆盖原始证据对象。
- 预告利润单位是万元，快报是元；预告统一乘10,000转换，禁止无转换拼接。
- 同日冲突、缺首发、倒置利润区间、非法日期均隔离；之后的修正不能修改先前事件值。
- 接口客户端的`retries`代表总尝试次数，初版设置0导致根本未请求，已修为1并保留失败记录；另对阶段路由加入回归测试，确保预期探测不会误走公告采集。
- 数字量级匹配不会自动解除原文语义和期望证据门禁。

## 7. 下一步裁决

**不能据此淘汰公告策略，但也不能马上宣称有盈利方案。下一步应继续补证据，而不是先回测“预增股”再换名字叫超预期。**

可执行的后续顺序：

1. 按报告期和公告日切片补齐源版本，修复两个重复分页样本，核对更早预告、修正与财报；把原文利润行、单位、归母/扣非、正负及具体期末记录为人工可复查结构。
2. 预期来源二选一后固定合同：有同报告期点时券商预测及原文的子样本走预期差；其余使用更早年份、当时已披露数据拟合季节性统计基线。后者必须称“相对统计基线的意外”，不是市场一致预期。
3. 统计基线训练只使用事件前已成熟数据，并防止财报重述污染。没有历史版本就不训练，也不能把今年修正后的上年利润补回过去。
4. 数据合同通过后，再计算公告后可执行买点的5/10/20日描述性结果和匹配对照；主策略期限仅能在开发段选择，独立验证段锁定。不能把无法买入的涨停或公告前跳涨算进收益。
5. 之后才接10万元资金占用、T+1、公司行为、真实税费和滑点的组合回放。没有完成前，不给“年化多少”的估计。

本轮没有实施第2—5步；原股票完整同源回放缺决策包的问题也没有因此解决。
