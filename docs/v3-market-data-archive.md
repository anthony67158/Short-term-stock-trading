# V3 市场数据云端归档

## 目标

V3 保留两类相互独立的数据：

1. `opportunitymodel/training-data/`：可直接训练的成熟反事实结果。
2. `opportunitymodel/market-data/v1/`：可重新回放的规范化市场原始数据。

每日训练先加载训练基线，再用线上真实成熟结果按 `decisionId` 覆盖同名历史
回放结果。合并结果在训练前重新发布为版本化基线，因此超过实时结果 180 天
扫描窗口的数据也不会丢失。

市场原始数据不能直接当标签。它用于重新执行生产扫描器、三价格路径和统一
费后结算器，只有完成结算的路径才进入训练基线。

## 每日分片

每个完整交易日保存一个 gzip JSON 对象：

```text
opportunitymodel/market-data/v1/
  manifest.json
  dates/YYYYMMDD-<sha256前16位>.json.gz
```

分片内容：

- 全市场日线；
- 换手率、量比和流通股本；
- 主力/小单资金流代理；
- 使用前一交易日可见数据选出的 1,000 股 5 分钟线；
- 请求代码数、完整代码数、覆盖率和行数。

日对象按内容摘要命名，并用 `x-oss-forbid-overwrite` 创建。`manifest.json`
记录完整 SHA-256、大小、日期范围和累计分钟行数。读取时必须校验摘要。
OSS Bucket 必须保持私有；归档不包含账号账本、用户昵称、Token 或 API Key。

## 每日增量

`.github/workflows/daily-retrain.yml` 的 `market-data-archive` job 在工作日
北京时间 01:15 运行：

1. 调用杭州量化 FC 的鉴权端点 `/archive-market-day`，避免 GitHub 海外出口
   直接访问国内行情源；
2. 从东方财富完整分页读取 A 股收盘快照，并校验返回数量与去重数量一致；
3. 使用 OSS 上一交易日分片构建 80% 高流动性 + 20% 稳定探索股票池；
4. 优先从东方财富历史接口获取目标日 5 分钟线，失败时回退腾讯 5 分钟线；
5. 同时保存东方财富 `f62` 主力净额和 `f84` 小单净额；
6. 完整分钟代码覆盖率低于 85% 时失败关闭；
7. 将分片追加到 OSS；重复运行同一内容不会产生重复对象。

公开源归档不需要 Token。Tushare 仅在其临时 Token 仍有效时承担两项辅助工作：

- 公开源整日失败时临时兜底；
- 手工刷新低频变化的申万行业成员档案。

Token 到期后，已有行业成员档案继续从
`opportunitymodel/sector-data/v1/` 读取，V3 每日市场归档和成熟样本训练不受
影响。公开接口没有正式 SLA，因此实现必须坚持多镜像、超时、完整性校验和
失败关闭，不能把空数据或部分分页写入 OSS。

归档步骤的核心数据口径为：

- 全市场收盘快照：东方财富；
- 个股 5 分钟线：东方财富历史镜像，腾讯作为逐股回退；
- 历史行业成员：OSS 中已版本化的申万成员档案；
- 标签：生产反事实账本成熟后生成，原始行情永不直接充当标签。

旧的 Tushare 增量流程仍保留为临时回退：

```bash
npm run opportunity:archive-tushare-daily
```

默认长期入口已经改为：

```bash
npm run opportunity:archive-daily
```

其余不变量：

1. 读取最近完整交易日；
2. 使用前一交易日可见信息选择股票池；
3. 获取目标日全市场日线、资金流和股票池 5 分钟线；
4. 完整分钟代码覆盖率低于 85% 时失败关闭；
5. 将分片追加到 OSS；重复运行同一内容不会产生重复对象。

## 历史基线

本机历史回放完成后可将验证过的日期分片一次性上传：

```bash
set -a; . ./.env; set +a
npm run opportunity:archive-tushare -- \
  --work-dir "$HOME/.tushare-v3-work"
```

上传支持断点重试：同内容对象读回摘要一致时直接复用，manifest 按日期覆盖
指针。上传与读回验证完成后才能删除本机缓存。

## 质量边界

- 日线少于 800 只或资金流少于 500 只时拒绝归档；
- 单股分钟少于 45 根、OHLC 关系异常、负成交量/成交额时拒绝；
- 停牌零值占位整日排除，不填充价格；
- 分钟股票池只使用前一交易日可见信息；
- 原始分片和成熟标签均版本化，不手工修改 manifest；
- 每日压实只增加真实成熟结果，不生成虚假标签。
