# V3 市场数据云端归档

## 目标

V3 保留两类相互独立的数据：

1. `opportunitymodel/training-data/`：可直接训练的成熟反事实结果。
2. `opportunitymodel/market-data/v1/`：可重新回放的规范化市场原始数据。

每日训练先加载训练基线，再用线上真实成熟结果按 `decisionId` 覆盖同名历史
回放结果。合并结果在训练前重新发布为版本化基线，因此超过实时结果 180 天
扫描窗口的数据也不会丢失。

市场原始数据不能直接当标签。它用于重新执行生产扫描器、三价格路径和统一
费后结算器，只有完成结算的路径才进入训练基线。

## 每日分片

每个完整交易日保存一个 gzip JSON 对象：

```text
opportunitymodel/market-data/v1/
  manifest.json
  dates/YYYYMMDD-<sha256前16位>.json.gz
```

分片内容：

- 全市场日线；
- 换手率、量比和流通股本；
- 主力/小单资金流代理；
- 使用前一交易日可见数据选出的 1,000 股 5 分钟线；
- 请求代码数、完整代码数、覆盖率和行数。

日对象按内容摘要命名，并用 `x-oss-forbid-overwrite` 创建。`manifest.json`
记录完整 SHA-256、大小、日期范围和累计分钟行数。读取时必须校验摘要。
OSS Bucket 必须保持私有；归档不包含账号账本、用户昵称、Token 或 API Key。

## 每日增量

`.github/workflows/daily-retrain.yml` 的 `market-data-archive` job 在工作日
北京时间 01:15 运行：

1. 读取最近交易日历，从昨天开始向前探测分钟数据已发布的最近交易日；
2. 使用上一交易日日线构建 80% 高流动性 + 20% 稳定探索股票池；
3. 获取目标日全市场日线、每日指标、资金流和股票池 5 分钟线；
4. 完整分钟代码覆盖率低于 85% 时失败关闭；
5. 将分片追加到 OSS；重复运行同一内容不会产生重复对象。

若网关尚未发布昨日分钟线，任务会回退到最近可用交易日；该日已归档时幂等
结束，下一次运行继续探测昨日数据。显式指定未发布日期时只执行最多 3 个
代表性股票探针，随后明确失败，不发起 1,000 只无效请求。

调用最多 120 次/分钟，低于网关 150 次/分钟限制。`TUSHARE_TOKEN` 只从
GitHub Actions Secret 或本机环境读取。板块训练等待市场归档结束后再启动，
避免两个进程叠加突破同一 Token 的频率限制；归档失败不阻断板块任务。

## 历史基线

本机历史回放完成后可将验证过的日期分片一次性上传：

```bash
set -a; . ./.env; set +a
npm run opportunity:archive-tushare -- \
  --work-dir "$HOME/.tushare-v3-work"
```

上传支持断点重试：同内容对象读回摘要一致时直接复用，manifest 按日期覆盖
指针。上传与读回验证完成后才能删除本机缓存。

## 2026-09-10 实际基线

- 历史元数据：210 个交易日，1,152,471 行日线、1,097,589 行资金流；
- 分钟数据：5,208 只股票、126 个回放/结算日、13,354,992 根 5 分钟线；
- 日期范围：2026-03-10 至 2026-09-08；
- 最低单日完整代码覆盖率：99.6075%；
- 停牌零值排除：19 个股票交易日；
- OSS 压缩分片总量：321,508,798 字节；
- 成熟训练基线：73,004 条样本、37,516 条成交路径、124 个独立日期；
- 126 个 OSS 对象均已全量读回，逐项通过大小、SHA-256、日期和分钟行数校验。

2026-09-09 的全市场日线和资金流已可获取，但两个允许的 Tushare 网关对
抽样高流动性股票均未返回该日分钟线，因此本次没有伪造或发布空分片。自动
任务会在源站分钟数据可用后补齐该日。

## 质量边界

- 日线少于 800 只或资金流少于 500 只时拒绝归档；
- 单股分钟少于 45 根、OHLC 关系异常、负成交量/成交额时拒绝；
- 停牌零值占位整日排除，不填充价格；
- 分钟股票池只使用前一交易日可见信息；
- 原始分片和成熟标签均版本化，不手工修改 manifest；
- 每日压实只增加真实成熟结果，不生成虚假标签。
