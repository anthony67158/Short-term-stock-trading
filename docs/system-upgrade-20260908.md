# 三工作区系统升级

状态：2026-09-08 用户确认实施，交付状态见文末。

## 目标

服务个人 A 股投资者的完整决策链：市场环境与选股 -> 自选等待条件 ->
人工买入 -> 持仓和资金管理 -> 人工卖出 -> 费后复盘。
优化目标为费后正期望、风险可控、条件可执行和系统可靠性，不承诺盈利。

## 现状与升级理由

基于 `784a330` 及工作区现有生成调度修复完成主链路检查。
基线为 1993 项 Node 测试、52 个离线 Harness 场景全部通过。
测试通过不代表实际投资收益得到验证。

| 已核实的断点 | 本轮交付 |
| --- | --- |
| 四个入口，市场研究与选股分开，账户仓位与持仓分开 | 三个主工作区；旧链接兼容跳转 |
| 今日精选池仍按涨停、涨速等另行排序 | 从主决策页撤下重复推荐，保留原始盘面研究 |
| 雷达加入自选只传备注 | 结构化保留发现依据、价格合同、时效和来源，并随真实成交传递 |
| 雷达接口未给组合计算传账户持仓 | 在鉴权后读取本账号账本、报价及执行预留，提供账号级容量 |
| 风险占用主要统计未完成买入 | 纳入已有持仓到止损的剩余损失；未知止损单列，不能算零风险 |
| 概率缺失被期望模块放行 | 明确未知、估计与已校准；无可靠正期望不发布新增风险指令 |
| 机会模型的 shadowOnly 在 JS 归一化中丢失 | 研究标识全链保留，不冒充生产校准结果 |
| 残差 P10 被称为净期望下界 | 区分单次结果尾部估计与均值置信下界，不混用 |
| 减仓计划完成可把剩余持仓标记结束 | 计划完成不等于持仓归零 |
| 换仓计划预演含未完成卖出收入 | 明确当前可执行和卖出成交后再评估，不预支现金 |
| 来源、模拟结果、真实收益分散 | 汇总来源和执行复盘，分开模拟命中率与真实费后收益 |

## 三个工作区

### 市场与选股

先展示市场风险、交易时段和证据状态，再展示唯一机会雷达。
板块资金、概念走势、异动、龙虎榜及宏观信息收进同工作区的研究子页，
不再并列提供第二套买入结论。

每个候选回答：为什么关注、核心风险、回踩或突破条件、止损目标、
有效时段、账户最多能配置多少。没有账户或价格证据时只允许加入观察，
不得将公共信号的“价格接近”展示成账号已经可以执行。

预催化、盘中公式、尾盘和次日计划沿用现有召回算法与全市场完整读取。
规则分不是概率；机构调研、公告和同题材关联不等于已证实供应链关系。

### 交易与持仓

账户资产、仓位与预留资金和持仓、自选放在同一主入口。
保留人工执行队列、持续复核、买卖记录、做 T 和个股详情。
账户诊断成为该工作区的资金视角，避免用户来回寻找。

每只股票保留：

- 选股时的原始依据与独立时效，不能被新建议覆盖成“当时就知道”。
- 当前唯一决策、入场价格、量价确认、退出价格、失效条件。
- 持仓数量、今日可卖数量、未完成计划与真实成交。
- 仓位上限、含费支出、止损参考损失、压力情景损失及阻断原因。

加入自选不自动生成付费研判、不自动加入持续复核白名单、不预留资金、
不写入虚假成交。记录已发生的真实成交与是否推荐该交易是不同语义。

### 复盘与改进

保留交易记录、预警历史和已有图表。增加按发现来源汇总的已实现费后表现，
并指出未关联来源、样本不足和统计覆盖范围。
不把单次命中、模拟撮合或少量盈利记录描述成已验证的赚钱能力。

## 决策与风险合同

沿用 `decision-plan.v2`、`execution-plan.v1`、证据快照与交易账本；
采用增量字段，不建立第二套建议引擎，不恢复策略委员会或策略晋级闸门。

概率必须与当前股票、价格合同和持有窗口一致：

```text
成交后净期望 = 成功概率 * 费后盈利 - 失败概率 * 费后亏损
候选净期望 = 候选可成交概率 * 成交后净期望
```

已有 expectedNetR 是成交后的均值估计，不再重复乘成功概率。
研究模型、分布外结果、无概率和过期结果不能冒充校准依据。
残差 P10 是单次结果的尾部估计，不是平均收益的置信下界。
已有同价合同量化信号的正期望估计继续保留其“估计”标识，不升级为已校准。
确定性负期望禁止新增风险；减仓、退出和硬止损不受新增风险门槛阻断。

账户容量同时受现金储备、未完成买入、单票、行业/主题、总仓位、
止损损失预算及 T+1 约束。持仓和计划风险不能重复计算已成交部分。
止损价不是保证成交价，压力损失必须独立显示。
公共候选容量仅为预算参考，最终执行仍需最新军师计划与人工确认。

## 技术与兼容

- 保持 React 18、Vite 8、ES modules、Node 内置测试和 FC 单后端。
- 前端改 `src/`、公共纯函数放 `shared/`，API 复用 `api/` 既有鉴权与超时。
- 不新增数据库、状态管理框架、券商连接或付费数据源。
- 不改变 `/predict` 的 36 维 OHLCV 训练/推理口径。
- 不回退当前深度模型 510 秒、任务 540 秒的运行预算；不同步恢复旧文档的 150 秒限制。
- 旧自选和持仓无来源时明确“手动关注/来源未记录”，不能编造历史依据。
- 旧 `research` 和 `hub/account` 入口映射到新工作区；预警深链接仍可用。
- 账号关键交易字段、OSS 原子锁、幂等、角色隔离和测试账号约束保持。

代码保持现有小写驼峰、具名导出、纯函数可注入时间/外部依赖的风格：

```js
export function normalizeSelectionOrigin(value, now = Date.now()) {
  if (!value || typeof value !== 'object') return null
  return { schemaVersion: 'selection-origin.v1', capturedAt: now }
}
```

## 验证与发布

执行顺序：风险合同与回归 -> 账户预算 -> 来源闭环 -> 三工作区 ->
浏览器与全量验证 -> Vercel + FC 同版本部署。

```bash
npm run test:ci
node harness/run.mjs --no-write
npm run build
npm run dev -- --host 127.0.0.1
npm run package:fc
```

部署遵循 `CLAUDE.md`：Vercel 稳定域名和 FC 自定义域名都更新。
FC 部署前必须加载 `.env`，不打印任何密钥。个人生产账号只读，
有副作用的验收优先本地固定假数据，不读取或复制生产账本。

必须通过：

1. 未知概率、研究模型、负期望、部分退出和并发资金占用有独立回归。
2. 雷达 -> 自选 -> 买入 -> 部分卖出 -> 清仓可追溯且不篡改交易数量与成本。
3. 三个主入口与旧链接、移动返回和预警跳转全部可达。
4. 320、768、1024、1440 宽度无页面横向溢出，控件与正文不互相遮挡。
5. 全量测试、Harness、构建通过；两端线上资源和 API 冒烟成功。

## 效果验证边界

本轮交付工程与决策闭环，不把训练完成等同于有超额收益。
实际能力使用独立时间段的 Top-K、可成交率、Brier、费后净 R、回撤和
执行损耗持续验证，区分模拟撮合与人工已确认成交。
不伪造成熟样本，不为通过门槛改动基线，也不扩大仓位追求展示收益。
新增公告正文模型、真实供应链数据源和新模型训练不在本轮自动上线范围内，
避免未经数据验证引入新的事实与概率承诺。
