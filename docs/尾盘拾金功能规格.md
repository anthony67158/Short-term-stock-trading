# 尾盘拾金功能规格

> 状态：Implemented，TN6 源码已恢复；分钟级样本外回测仍待完成
> 日期：2026-08-28
> 目标版本：`tail-pick.v1`
> 原始资料：`尾盘选股/使用说明及案例.docx.pdf`、`尾盘选股/尾盘公式一键导入.tn6`

## 一、前置结论与假设

1. “尾盘拾金”是固定规则选股策略，不是让用户上传任意通达信公式的通用平台。
2. 交易日 14:50 由 FC Timer 自动生成当天唯一正式版；用户平时可手动试算，但不覆盖正式版。
3. 不自动下单，不自动写入持仓。
4. 每次扫描最多给 3 只结果，并明确 1 只首选；没有合格标的时直接输出“今日不开仓”。
5. 公式命中只是第一层，只有继续通过大盘、板块、流动性、位置、分时和账户风控后，前台才显示“可小仓执行”。
6. 选股公式、主图和副图必须按原源码等价实现，不根据案例截图猜测。
7. 每只新开仓默认不超过总资产 5%；同一尾盘批次默认只执行首选股，候补股不同时建仓。
8. 该策略必须先完成含手续费、滑点和 T+1 的样本外回测；净期望未转正时只能作为“公式观察”，不能展示“可买”。

## 二、已确认的原策略规则

### 2.1 使用时间

- 交易日 `14:50` 由云端定时任务自动运行，生成当天唯一正式结果。
- `14:50` 前不提前给出正式结果。
- 盘中其他时间允许用户手动试算，但必须标记为“非正式、可能随未完成日K变化”，不得覆盖正式结果。
- `14:55` 后如果价格突然直线拉升，不追买。

### 2.2 适用市场

- 上证、深证等核心指数的 5/10/20 日均线总体多头排列时，进入标准档，单股最多 5%。
- 均线尚未全面多头，但指数处于震荡/切换且至少一个核心指数守住 20 日线，或上涨家数明显占优时，进入谨慎档，单股最多 3%。
- 市场成交额稳定，存在持续轮动的主线板块。
- 指数横盘时，20 日均线有支撑且未持续创新低。

### 2.3 禁止使用

- 大盘连续放量下跌并跌破 60 日均线。
- 市场持续缩量阴跌且没有明确主线。
- 当日出现重大系统性利空或外围市场暴跌。

### 2.4 个股人工过滤

- 排除近 20 个交易日涨幅超过 35% 的高位股。
- 排除当日成交额低于 5000 万元的低流动性股票。
- 排除冷门、弱势板块股票。
- 系统继续沿用项目现有标准：排除 ST、退市整理、停牌、上市不足 20 个交易日和不可正常交易标的。

### 2.5 买入与退出纪律

- `14:50` 开始观察分时，价格应持续位于分时均价线上方，且没有放量跳水。
- 分两笔建仓：第一笔建立底仓，走势稳定后再补剩余计划仓位。
- 次日冲高 1%-3% 时减半；达到 7%-8% 时全部清仓。
- 持仓满 3 个交易日仍未上涨或持续横盘时离场。
- 买入当日最低价作为次日起可执行的硬止损价；次日跌破时立即卖出。
- 所有卖出遵守 A 股 T+1 和现有账户手续费口径。

## 三、产品位置

放在“今日决策”页面，顺序固定为：

```text
大盘盘面
→ 市场情绪
→ 板块前瞻
→ 尾盘拾金
→ 普通行情候选池
```

理由：

- “板块前瞻”继续是唯一方向决策入口。
- “尾盘拾金”只负责在已确定的市场和板块方向下找执行标的，不另起一套方向判断。
- 不放到“盘面研究”，因为它是交易时点明确的行动流程，不是研究工具。
- 不恢复已删除的泛化 AI 选股；本功能是有固定时间、固定公式和固定退出纪律的独立策略。

## 四、核心体验

### 4.1 面板默认态

面板标题为“尾盘拾金”，右侧只有一个主按钮。

| 时间 | 主按钮 | 面板状态 |
| --- | --- | --- |
| 交易日 14:50 前 | `手动试算` | 可试算未完成日K；14:50自动任务生成正式版 |
| 14:50-14:55 | `立即试算` | 自动正式版优先；手动结果不覆盖正式版 |
| 14:55-15:00 | `手动复盘` | 可重新计算，但只读复盘、不产生买入指令 |
| 收盘后/非交易日 | `手动复盘` | 按最近行情试算并展示最近正式结果 |
| 大盘闸门未通过 | `今日不开仓` | 禁用运行，并给出唯一原因和操作结论 |

手动试算与正式版使用相同公式和纪律闸门，但保存路径、标识和执行权限严格隔离。

### 4.2 一键运行流程

14:50 自动任务和手动试算共用同一条计算链：

```text
运行尾盘选股
  1. 检查交易日、时间窗和数据时间
  2. 检查大盘是否允许新增风险
  3. 合并前一交易日历史特征与 14:50 实时日内数据
  4. 对全市场执行原始“尾盘拾金”公式
  5. 排除高位、低流动性、弱板块和不可交易股票
  6. 使用板块、主力/小单资金、分时和量化做确定性复排
  7. 输出 0-3 只，其中最多 1 只为首选
```

进度文案只呈现用户能理解的四段：

1. `正在确认今天是否适合尾盘开仓`
2. `正在扫描全市场公式信号`
3. `正在排除高位、弱势和流动性风险`
4. `正在生成最终执行顺序`

### 4.3 结果层级

结果只允许三种状态：

- `首选，可小仓执行`：公式命中且所有硬闸门通过。
- `候补，暂不买`：公式命中，但首选仍有效或存在一项待确认条件。
- `今日不开仓`：市场闸门未通过，或没有股票通过全部条件。

禁止使用“都可以”“自行选择”“回踩或突破任选”等模糊表达。

### 4.4 结果卡

每张卡固定展示以下信息，字段顺序不得变化：

1. 股票名称、代码、首选/候补状态。
2. 当前价、分时均价、数据截至时间。
3. 唯一动作，例如：`14:50-14:52 不高于 12.36 元买入第一笔 2% 仓位`。
4. 第二笔条件，例如：`14:53-14:55 仍站稳均价线且未放量跳水，再补 3%`。
5. 止损价：买入当日最低价，标明“次日起生效”。
6. 止盈纪律：次日 `+1%-3%` 减半，`+7%-8%` 清仓。
7. 最晚退出日：买入后第 3 个交易日。
8. 入选依据：公式命中、板块强度、主力与小单资金关系、量化方向。
9. 最大风险：只显示最重要的一条。

首选卡只有一个主要按钮：`加入尾盘计划`。点击后先显示资金和仓位确认，再写入现有交易计划；不会代表已经向券商报单。

候补卡只有 `加入自选`，不提供建仓按钮。点击股票名称继续复用现有个股详情。

### 4.5 14:50-14:55 动态确认

正式扫描结果不重排，但卡片状态可随分时变化：

```text
等待第一笔
→ 第一笔可执行
→ 等待第二笔确认
→ 第二笔可执行
```

任何时刻出现以下情况，立即切为 `放弃买入`：

- 跌回分时均价线下方且未快速收回。
- 出现公式定义的放量跳水。
- `14:55` 后出现公式定义的直线拉升。
- 板块或大盘进入禁止新增风险状态。
- 账户现金、仓位或纪律熔断不允许开仓。

被放弃的股票不得在同一场次重新生成新买价拖延决策。

## 五、确定性决策链

### 5.1 公式层

新增纯函数模块 `shared/tailPickFormula.js`：

```js
evaluateTailPickSignal({
  candles,
  intraday,
  quote,
  asOf,
}) => {
  matched,
  score,
  signals,
  failedRules,
  sourceVersion,
}
```

要求：

- 只使用信号时点之前的数据。
- 公式源码中的 `REF`、`MA`、`EMA`、`HHV`、`LLV`、`CROSS` 等函数逐项等价实现。
- 当前交易日使用截至 `14:50` 的开、高、低、现价、成交量和成交额构造未收盘日 K。
- 主图、副图和选股公式共享同一套中间变量，避免三个版本漂移。
- 每条命中原因必须能映射回明确公式条件，不能由 LLM补写。

### 5.2 市场闸门

新增 `shared/tailPickMarketGate.js`，输入现有市场快照与指数历史，输出：

```js
{
  allowed: Boolean,
  label: '允许小仓' | '今日不开仓',
  reasons: String[],
  dataAsOf: Number,
}
```

市场闸门分为标准档、谨慎档和禁止档。5/10/20 日均线多头是标准档条件，
不是唯一放行条件；真正的硬否决是风险状态、连续放量跌破 60 日线、
市场无结构性承接或没有可识别主线。LLM、个股强度或公式分数都不能覆盖
“今日不开仓”。

### 5.3 候选复排

只在公式命中池内排序，不向池外新增股票。排序信息依次为：

1. 所属板块是否与当日板块前瞻方向一致。
2. 近 5 日主力与小单资金是否支持承接，数据不足 5 日必须标明实际天数。
3. `14:50` 分时是否站稳均价线、是否存在放量跳水。
4. 20 日位置、成交额和拥挤风险。
5. 现有量化方向；量化强烈看空可否决，量化缺失不得伪造。
6. 账户当前持仓、现金、当日已开仓次数和纪律熔断状态。

LLM 不参与公式计算、过滤、排序或是否可买的最终决定。可选的 LLM 解释只能压缩已存在的结构化证据，失败时不影响确定性结果。

## 六、数据与性能

### 6.1 为什么不能临时逐股抓 K 线

全市场约数千只股票。用户点击后再逐只请求 60 日 K 线，会超过 FC 执行时间并触发行情源限流，不能作为生产方案。

### 6.2 推荐数据链

1. 每个交易日收盘后生成全市场最近 60 个交易日的前复权 OHLCV 特征包。
2. 特征包保存到 OSS：
   `market/tail-pick/v1/features/YYYY-MM-DD.json.gz`。
3. `14:50` 运行时只拉一次全市场实时快照。
4. 服务端把实时未收盘日 K 合并进历史特征，内存中批量执行公式。
5. 只对公式命中的少量股票补抓分时、资金、标签和量化。

目标性能：

- 全市场快照与公式扫描：15 秒内。
- 候选复核：额外 20 秒内。
- 总体 P95：35 秒内。
- 任何阶段数据不完整时宁可返回“数据不足，今日不开仓”，不使用旧价冒充实时结果。

## 七、API 合同

复用单个 FC 路由 `api/tail_pick.js`。

### 7.1 读取当前场次

```http
GET /api/tail_pick
```

返回当前时间窗、最近正式结果和任务状态。

### 7.2 启动本场扫描

```http
POST /api/tail_pick
Content-Type: application/json

{
  "action": "run",
  "mode": "manual",
  "idempotencyKey": "tail-pick:2026-08-28:manual:1787909400000"
}
```

受理响应：

```json
{
  "ok": true,
  "schemaVersion": "tail-pick.v1",
  "task": {
    "id": "tp_20260828_1450",
    "status": "RUNNING",
    "stage": "FORMULA_SCAN",
    "progress": 35
  }
}
```

结果响应核心结构：

```json
{
  "ok": true,
  "schemaVersion": "tail-pick.v1",
  "session": {
    "tradeDate": "2026-08-28",
    "dataAsOf": 1787909400000,
    "isLive": true
  },
  "marketGate": {
    "allowed": true,
    "label": "允许小仓",
    "reasons": ["指数结构未破坏", "市场仍有可识别主线"]
```

所有外部输入、行情响应和存储快照必须在 API 边界校验。错误统一返回：

```json
{
  "ok": false,
  "error": {
    "code": "DATA_INCOMPLETE",
    "message": "14:50 行情数据不完整，今日不开仓"
  }
}
```

### 7.3 幂等与存储

- FC Timer `tail-pick-1450-timer` 在工作日北京时间 14:50 自动运行，14:52 仅在正式结果缺失时重试。
- 同一交易日 `14:50` 场次只有一个全局正式任务。
- 重复点击返回同一任务，不重复抓数、不重复运行。
- 正式结果保存在：
  `market/tail-pick/v1/runs/YYYY-MM-DD/1450.json`。
- 手动试算保存在 `market/tail-pick/v1/manual-latest.json`，不得覆盖正式结果。
- 市场结果全账号共享；账户现金和仓位限制在前端或账号鉴权层叠加。
- 只有用户点击“加入尾盘计划”后才写个人账户。

## 九、回测与上线闸门

上线前必须使用 point-in-time 数据还原 `14:50` 信号，禁止用收盘数据代替：

- 至少覆盖 400 个交易日。
- 使用 5 分钟或更细数据还原 `14:50-14:55` 买入和放量跳水。
- 计入佣金最低 5 元、印花税、过户费、滑点和 T+1。
- 严格模拟次日减半、7%-8% 清仓、次日跌破买入日低点、3 日到期离场。
- 分别测试：原公式、公式加市场闸门、再加板块/资金/量化复排。
- 使用 walk-forward 样本外结果，不允许拿同一段数据调参并验收。

只有同时满足以下条件才显示“可小仓执行”：

- 样本外扣费后期望收益大于 0。
- 样本外 Profit Factor 大于 1。
- 相比“随机同时间买入”基线有稳定提升。
- 最大回撤不超过账户允许范围。
- 近期窗口没有出现显著策略失效。

若未通过，功能仍可上线为“公式观察”，但按钮和结果不得使用“可买”或“执行”。

### 10.2 核心验收

- `14:49` 不能生成正式结果，`14:50-14:55` 可运行，`14:55` 后不能追涨式重选。
- 同一场次连续点击只创建一个任务。
- 原公式的固定样例逐条与通达信输出一致。
- 大盘闸门失败时，即使个股公式命中也只显示“今日不开仓”。
- 输出最多 3 只且只有 1 只首选。
- 每只结果都有唯一动作、仓位、止损、止盈和最晚退出日。
- 资金历史不足 5 日时显示实际天数，不得声称“最近 5 日”。
- 任一关键行情过期或缺失时不输出可执行建议。
- 手机和桌面端无横向溢出，按钮、价格和时间列对齐。
- 前端改动完成后必须部署并验收 Vercel 与阿里云 FC；后端改动必须部署并验收 FC。

## 十一、边界

### Always

- 公式计算使用确定性代码并记录公式版本、数据时间和逐项命中证据。
- 账户动作继续走现有手工执行、T+1、手续费和熔断规则。
- 使用测试账号或本地数据完成有副作用验收。
- 回测不通过时明确显示策略无有效优势。

### Ask first

- 改变原公式任一条件或参数。
- 放宽单股 5% 仓位上限。
- 从手动运行升级为 14:50 自动运行或主动推送。

### Never

- 从 `.tn6` 案例图猜公式后直接上线。
- 用 LLM 补造公式命中、行情、资金或买卖价格。
- 盘中反复重跑并用更晚价格覆盖 14:50 正式结果。
- 自动下单或把“加入计划”当成券商成交。
- 使用生产个人账号执行写入型验收。
