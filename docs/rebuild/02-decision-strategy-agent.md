# 联合决策内核：量化模型 × Agent × 账户约束

> 隶属 `a-share-platform-rebuild.v1.0`。本册负责数值、策略、Agent 协作和模型评估语义。  
> 核心合同：生产选股与持仓管理必须有合格的量化预测和有效的 Agent 研判共同参与。

## 1. 四种能力各自做什么

| 能力 | 解决的问题 | 产物 | 不承担的职责 |
|---|---|---|---|
| 量化模型 | 在当前条件与行动下，结果的概率分布如何？ | 成交概率、收益分布、排序、动作增量价值、尾部风险 | 编造事件事实、直接改账本 |
| Agent | 发生了什么，为什么重要，投资论点是否成立，还有什么反证？ | 结构化研判、事件关联、研究论点、待验证假设 | 自造收益概率、绕过账户限制 |
| 公式 | 如何把数据转换为特征、成本和指标？ | 技术指标、财务比率、费用、风险计算 | 独立冒充完整生产决策 |
| 规则与优化器 | 哪些动作合法，如何综合并形成唯一账户计划？ | 约束结果、目标数量、执行与复核条件 | 用固定打分替代预测和研究 |

“Agent 不能改手数”不等于“Agent 不参与决策”。它通过被验证的事件事实、研究状态、策略适配与复核触发影响模型输入和候选空间，其作用必须能在消融中测量。

## 2. 决策的共同单位

生产决策单位为：

`账户 × 股票 × 决策时点 × 投资周期 × 联合发布版本`

同一股票可有短线和中期观点，但实盘持仓是可替代的同一证券资产。策略归因使用虚拟子仓位，组合层按真实证券数量聚合；不能让两个策略同时出售同一批股票。

量化、Agent、价格和账户必须引用同一个不可变 DecisionContext。数据准备允许异步，发布前必须核对所有输入版本。

## 3. 联合选股链路

### 3.1 第一步：建立因果股票池

按当时存在的证券、上市状态、交易权限和数据可用性建立股票池。研究池可包含不可交易证券；执行池必须满足账户权限和证券规则。

历史股票池包含当时上市而后来退市的股票，行业成员关系也使用历史版本。不得使用今天的存续股票列表回测过去。

### 3.2 第二步：双路召回

**量化召回**：横截面排序模型及多个特征方向产生宽候选池，覆盖趋势、质量、估值、波动修复等机会，记录每条召回原因。

**Agent 事件召回**：行业/市场 Agent 从公告、政策、财报和产业链变化形成事件对象，关联直接受影响与间接受影响公司。直接事实和产业链推断标记不同置信来源。

合并后按证券与策略去重，保留来源集合。不能只让 Agent 解释模型排出的 Top5，否则事件发现能力被架空。也不能让 Agent 自由编名单而跳过证券实体核对。

### 3.3 第三步：有预算的候选研究

先做低成本已有证据复用和结构化核验，再对有价值或信息缺口大的候选做深入研究。预算示例：全市场初筛数千只、深度候选数十只；真实数量由供应商限流、延迟及研究成本实验决定。

Research Agent 输出：

- 收益逻辑与适用周期；
- 已证实催化及预计验证节点；
- 事件已兑现/尚未兑现/时间不确定；
- 支持证据、反证、重要缺失；
- 当前价格是否已反映事件的研究判断；
- 推荐继续评估的策略类别及理由；
- 研判有效期与哪些新事件使其失效。

不输出没有模型依据的“上涨概率 85%”。“证据充分”与“赚钱概率高”是不同概念。

### 3.4 第四步：联合特征与再估值

将通过合同校验的事件类型、方向、时间、证据状态和论点状态编码为有来源的特征，连同行情及财务特征进入联合模型。训练与推理必须使用相同的 Agent 输出协议和编码版本。

对不能历史重建的 Agent 特征，先积累前瞻样本并进行受限验证，不伪造十年同等证据。在没有充分支持时只能作为显式不确定性/研究条件，不能宣称已校准的收益提升。

模型重新计算候选排序、当前/回踩/突破等已注册执行路径的成交及收益风险。三路径只是首期模板，后续策略可注册日终调仓等路径，但必须定义成交和标签合同。

### 3.5 第五步：账户决策

将候选与现有持仓、现金方案一并比较。最终输出：

- 现在可按条件执行；
- 需要等待触发；
- 仅研究，当前条件不支持执行；
- 证据或联合能力不足，无法完成评估。

排序和展示截断不删除研究日志与反事实样本。未被深查、未成交、失败候选必须留在样本分母。

## 4. 联合持仓管理链路

### 4.1 持仓记忆是有版本的论点，不是聊天摘要

每次建仓记录最初理由、催化、周期、失效条件、引用证据及模型快照。后续 Agent 维护新的 ThesisRevision，旧版本仍属于原决策。

新买入可能是同一论点加仓，也可能属于另一个策略。必须记录原因，不能通过覆盖持仓备注抹掉历史。

### 4.2 持仓 Agent 的核心判断

| 检查项 | 例子 | 对联合链路的影响 |
|---|---|---|
| 原论点是否成立 | 原预期订单未兑现或业绩质量变差 | 更新论点状态和事件特征 |
| 催化是否兑现 | 新产品发布已发生，后续增长未验证 | 更新剩余周期与观察节点 |
| 是否出现反证 | 重大股东减持、财务修正、行业需求反转 | 触发新评估，增加证据不确定性 |
| 价格与逻辑是否脱节 | 股价上涨但盈利预期未改善 | 请求估值/拥挤风险模型复算 |
| 组合是否重复暴露 | 多只股票都依赖同一上游景气 | 提交主题关系和组合风险研判 |

“论点失效”可触发紧急复核；它不是 Agent 直接下达强制卖出。证据冲突、行情合法性、持仓价值及可卖数量仍进入统一流程。

### 4.3 持仓模型

模型估计在同一未来评估范围下、相对“保留当前数量”的增量价值：

`ΔV(action, quantity) = V(action, quantity) − V(HOLD, currentQuantity)`

动作包含 HOLD、ADD、REDUCE、EXIT。EXIT 的价值不是买入收益取负；它含现在出售的费用、未来价格机会与现金再配置价值。ADD 不是复制原买入模型分数；必须考虑当前价格、已有暴露与新增成本。

持有的浮盈亏是状态特征，但不因“回本”心理自动成为目标。成本影响账务和用户约束，决策比较应针对未来可得结果。

### 4.4 目标仓位与再配置

候选目标数量先从证券交易规则生成合法离散集合，再评估收益、风险、成本和资金占用。较大账户可先粗粒度搜索再细化，不逐股暴力枚举无限组合。

组合层至少考虑：真实可用现金、未完成计划预留、可卖批次、单股与行业风险、主题共同暴露、流动性、费用和用户授权风险。用户风险上限由用户设置或明确接受默认档位，Agent 无权扩大。

## 5. Agent 服务角色

角色是任务协议，不等于必须部署六个服务或配置六个供应商。

| 角色 | 输入 | 工具 | 产物 | 触发 |
|---|---|---|---|---|
| Market Agent | 市场状态、行业数据、公开事件 | 事件检索、行业查询、资料引用 | MarketAssessment | 盘前、重要市场事件 |
| Research Agent | 公司资料、财报、候选与研究问题 | 原文读取、财务查询、同业对比 | ResearchAssessment、ThesisRevision | 新候选、用户深研 |
| Position Agent | 当前论点、持仓上下文、新事件、模型摘要 | 论点比较、事件验证、历史研判读取 | PositionAssessment | 论点相关事件、定时复核 |
| Portfolio Agent | 聚合持仓、主题关系、候选、风险摘要 | 暴露查询、情景计算 | PortfolioAssessment | 组合评估、重大暴露变化 |
| Review Agent | 决策与结果、执行偏差、失败簇 | episode 查询、指标查询 | ReviewReport、ImprovementProposal | 收盘后 |
| Strategy Agent | 研究假设、失败簇、可用特征/策略注册表 | 有限实验配置生成、实验结果读取 | ExperimentProposal | 用户发起、夜间受限任务 |

对话助手是这些服务的交互入口，负责把问题路由到明确任务，不另建一个拥有全部权限的自由 Agent。解释文本可由已产出的结构化研判与决策模板生成，必要时追加低成本解释任务。

## 6. Agent 运行协议

每次任务冻结：任务类型、输入快照、工具白名单、Prompt revision、供应商模型标识、预算、截止时间、输出 schema、产物归属。

推荐初始运行预算，须经实测调整并版本化：

| 任务 | 单轮工具上限 | 模型调用上限 | 总墙钟预算 | 超时结果 |
|---|---:|---:|---:|---|
| 事件归类/证据抽取 | 4 | 2 | 30 秒 | 部分事实或失败 |
| 候选/持仓研判 | 8 | 3 | 90 秒 | 评估不完整，不发布新风险动作 |
| 用户深度研究 | 16 | 6 | 5 分钟 | 保存部分证据与待续步骤 |
| 复盘/实验提案 | 12 | 4 | 5 分钟 | 保存草案，不能发布 |

单一任务不允许无限 self-reflection、无限委派或失败后换模型不断重试。工具读取可限次重试；模型超时需区分“未发出”和“上游可能已执行”，记录重复调用风险与费用。

### 6.1 结构化研判合同

至少包含 `assessmentId`、`subjectId`、`taskType`、`asOf`、`inputSnapshotId`、`evidenceIds`、`claims`、`counterClaims`、`thesisStatus`、`strategyFit`、`uncertainties`、`validUntil`、`agentVersion`。

每条 claim 必须包含类型：

- `OBSERVED`：原文或结构化数据直接支持；
- `INFERRED`：从事实推导的判断；
- `HYPOTHESIS`：等待验证的解释。

校验器能核验来源、数值、引用、时间与格式，**不能保证产业链因果推断为真**。推断只能作为有不确定性的特征或研究条件，并接受后续结果评估。

### 6.2 缓存与失效

缓存键包含股票、任务、证据指纹、策略周期和 Agent 协议版本。公共公司研究可跨账户复用；包含现金、成本、持仓偏好的研判必须账户隔离。

报价变动不默认触发重新检索全文。新公告、财报、重要事件、论点验证节点、已登记的重要价格变化可使研判失效。有效期是上限；材料事件出现时即使尚未到期也失效。

## 7. 联合融合与冲突处理

### 7.1 禁止简单平均两个不等价分数

不采用“模型 70 分 × 60% + Agent 80 分 × 40%”这种未经校准的总分。两者输入的统计含义不同。

采用三层融合：

1. **事实融合**：Agent 核验后的事实进入标准特征；来源和缺失状态保留。
2. **研究状态融合**：论点、事件阶段、策略适配作为类别/有序特征或预注册的情景分支；权重由训练及时间外实验决定。
3. **账户融合**：对联合模型产生的动作分布施加账户约束，比较净效用；冲突和证据支持不足反映在不确定性及可执行状态。

未训练过的字段不能上线临时加权。新增判断方式必须更换联合版本并评估。

### 7.2 冲突矩阵

| 量化 | Agent | 处理 |
|---|---|---|
| 有正向机会 | 论点支持、证据充分 | 进入联合再估值和账户检查 |
| 有正向机会 | 有重大反证 | 先核验反证；更新联合特征，必要时等待 |
| 缺少正向机会 | 研究看好 | 保留研究候选，不凭叙事生成买入 |
| 建议持有 | 论点失效 | 启动优先复核并做事件情景评估，不沿用旧建议 |
| 建议退出 | 论点保持 | 比较短期价格风险与中期逻辑，形成同周期动作；不能自由投票 |
| 任一不可用/过期 | 任意 | 未完成联合评估，禁止冒充完整生产建议 |

结论可能仍是 HOLD 或 WAIT，但必须说明这是完整评估后的结果，还是能力不足导致暂无法评估。两者产品状态不同。

## 8. 模型体系与顺序

| 模型 | 预测对象 | 初始候选方法 | 验收指标 |
|---|---|---|---|
| 市场/行业状态 | 趋势、宽度、波动、流动性 | 统计状态模型或树模型 | 状态稳定性、下游消融 |
| 横截面机会排序 | 同一时点候选相对价值 | LightGBM/CatBoost 排序 | RankIC、分桶收益、账户增益 |
| 成交模型 | 指定价格路径在有效期内能否成交及比例 | 分类 + 条件回归 | Brier、校准、部分成交误差 |
| 条件收益模型 | 成交后费后结果分布 | 分位数树模型/分布模型 | 分位数损失、覆盖率、校准 |
| 持仓动作模型 | ADD/REDUCE/EXIT 相对 HOLD 的价值 | 配对反事实回归、排序 | 动作 regret、组合回放 |
| 组合风险模型 | 相关风险、压力损失、流动性 | 收缩协方差 + 场景估计 | 风险覆盖、压力误差 |

初期从可解释的树模型和校准器开始。深度学习或强化学习需证明较简单联合版本的增益，不能因“更先进”直接替换。

核心字段：

- `pFill`：有效期内的成交概率；
- `pWinGivenFill`：在指定退出/持有政策下，成交后的费后盈利概率；
- `q10/q50/q90`：同一费后收益随机变量的条件分位数；
- `expectedNetReturnGivenFill`：条件期望，不能由三个分位数简单平均；
- `stopHazard`：指定期间/步长的止损事件风险，必须说明定义；
- `support`：训练分布覆盖与样本支持，不能等同于盈利概率。

只有 Q10 不能推出 CVaR；如果产品展示 CVaR，必须另有经验证的尾部分布估计。

## 9. 数值与效用口径

候选比较必须对齐单位、期限、可成交概率和成本。无成交时收益为零，但可能存在预约资金的机会成本，单独记录。

对于某行动：

`ExpectedProfit = pFill × ExpectedNetProfitGivenFill + (1 − pFill) × NoFillProfit`

若条件净收益已经包含佣金、税费和滑点，不得再次扣除。模型同时输出费用假设与数量适用范围，手数变化造成最低佣金和冲击非线性时应重算。

账户效用采用期望利润减去版本化风险代价、资本占用代价和不确定性准备。各项单位为人民币且来源独立。回撤/尾损约束优先检查，再在合法集合比较效用。

不同投资周期不直接混排原始收益率。短线与中期先使用各自周期模型及资本时间假设，再在组合层比较；模型期限缺失时不得折算虚构年化。

R 只用于存在明确初始风险定义的策略，保存分母与冻结时点。无固定止损的中期策略主要报告收益率、金额与风险分布，不硬套 R。

## 10. 复核与监控

监控由服务端拥有，浏览器展示和通知不决定触发是否成立。

触发分为行情条件、新证据、论点节点、账户变化、计划到期、模型健康六类。触发去重键至少包含当前决策、触发类型及触发周期。

观察策略必须是版本配置：

- 事件确认型可在证据核验后立即复核；
- 日内价格型可使用持续观察窗口；
- 日终策略只在日终快照复核；
- 硬止损风险提示不等待 Agent 或模型。

首个短线模板建议以 60 秒观察、120 秒任务截止作为实验起点，**不是全平台固定真理**。若数据源只提供 5 分钟数据，不能声称完成秒级观察；应采用匹配频率的模板。旧 10 分钟窗口也不自动继承。

总截止从触发时刻计算，包含观察、证据更新、Agent及模型执行。所有子任务预算取“角色上限”和“总剩余时间”两者较小值；观察60秒后不能再完整追加90秒Agent预算。剩余时间不足且没有有效研判时明确结束为评估不可用，不能无提示延长时限。

每次触发只创建一个复核 episode。需要重新研究时使用事件已更新的研判；若无法在有效期内完成，终态为能力/证据不足，不能无限挂起。新独立事件可创建新的 episode。

## 11. 数据、标签与训练

### 11.1 五类数据严格分开

市场事实、Agent 研判、当时预测、模拟反事实结果、真实成交结果分别保存。训练选择明确数据来源、权重及适用范围。

### 11.2 标签生成

候选在真实可见时点生成，价格路径和退出政策事先冻结。标签包含未成交、部分成交、停牌、涨跌停不可达、费用与滑点；不能只留成功买入和盈利股票。

持仓样本来自可执行策略产生的持仓状态和用户实际持仓，明确两类分布。配对动作应从同一状态、同一未来环境模拟，后续管理政策一致；不能把未来最优操作当生产可实现的确定答案。

数据被截断的持仓标记删失，不假定在样本末尾完美退出。日线内同时触发止盈止损时使用事先声明的保守规则或更细粒度数据，不选择有利顺序。

### 11.3 Agent 历史回放的边界

历史文档必须使用当时可用版本，且防止现代 LLM 从训练记忆中泄漏后续事件。隔离工具检索、明确时点提示、证据限制和结果核验只能降低风险，不能证明完全消除模型预训练泄漏。

因此区分：

1. 当时在线保存的 Agent 研判回放：最强证据；
2. 有历史原文的事后重建：标记 retrospective，开展敏感性评估；
3. 无原文、只凭模型记忆生成：不得作为有效历史 Agent 证据。

无法可信重建时开展前瞻模拟采集，在研究模式积累，不把不可信历史收益当发布依据。

### 11.4 验证方法

时间顺序训练/验证/确认；标签重叠 purge 与 embargo；按事件和日期分组；跨行情阶段 walk-forward；剔除未来可见数据的截断回放；纳入退市与历史成分股。

联合系统至少做四组消融：完整联合、去 Agent、去量化、公式基线。相同交易日、资金、股票池、执行政策和风险约束比较，报告被排除候选和未交易日期。

## 12. 发布与持续学习

发布包同时包含模型、校准器、特征、Agent 协议与提示词、策略配置、风险政策、数据与标签版本、评估报告。供应商不能固定底层模型时记录其版本不确定性，运行金样监测，必要时暂停新风险。

上线门禁包括：账本正确、无时间泄漏、模型校准可接受、Agent 证据质量通过、时间外费后收益有证据、压力成本可承受、账户风险不越权、服务预算可满足、包可回滚。

净收益下界和风险容忍参数在实验开始前登记。可以采用单侧置信界与配对块重采样，但置信水平、块长、最少有效样本和允许回撤需要预先冻结，不能用“动态门槛”掩盖试验失败。

每日过程：归档 → 结算已成熟结果 → 数据质量检查 → 失败簇与 Agent 提案 → 受限候选训练 → 冻结比较 → 保留或发布。每日积累不意味着每日强制升级。

用户偏好离线验证后直接替换生产，本方案不设置长期双生产指令。前瞻模拟用于缺失的证据验证；合格后一次切换，失败则保留当前联合版本。首次无合格联合版本时保持研究/账本模式。

## 13. 如何证明两者都起了作用

每个 Decision 保存：

- 原始模型召回与 Agent 召回；
- Agent 产物被接受、拒绝及未使用的字段；
- 联合模型实际消费的 Agent 特征与版本；
- 使用研判前后的候选/路径差异；
- 量化预测及账户约束如何决定最终动作；
- 最强反证、未解决冲突和降级状态。

工程验收证明数据实际进入生产路径；消融评估证明是否有收益、风险或研究效率增益。修改 Agent 文案而决策输入完全不变不能宣称联合决策完成。

## 14. 失败边界

| 失败 | 允许继续 | 必须停止或标记 |
|---|---|---|
| Agent 服务暂时不可用 | 有效且未被新事件失效的研判可复用 | 必要研判缺失的新风险建议 |
| 模型不可用 | 研究、账本、硬风险提示 | 模型驱动动作；不切公式 |
| Agent 与模型冲突 | 保留事实、补证据、优先复核 | 虚构共识或静默忽略一方 |
| 数据严重过期 | 历史查看和真实成交录入 | 新执行建议 |
| 账本版本冲突 | 保存历史评估记录 | 发布基于旧现金/持仓的数量 |
| 自动训练失败 | 当前健康联合版本 | 伪造升级成功 |

持仓无法完成联合评估时显示“评估不可用，保留现有仓位事实与已授权风险提醒”，不把这种状态包装为模型推荐 HOLD。
