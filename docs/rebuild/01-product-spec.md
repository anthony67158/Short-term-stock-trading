# 产品规格：研究、选股、持仓与策略闭环

> 隶属 `a-share-platform-rebuild.v1.0`。状态：设计提案。  
> 已确认：生产选股和持仓管理由量化模型与 Agent 联合完成；公式不是独立决策替代品。

## 1. 定位与用户任务

产品名称暂定“A 股投资工作台”，名称可改，领域语义保持稳定。服务自主做投资判断、愿意记录实际成交、希望通过研究与验证持续改进方法的个人投资者。

平台的主要交互不是“问 AI 明天买什么”，而是围绕可积累的对象工作：

- 今天有哪些可验证的机会，为什么被发现？
- 一家公司赚钱的逻辑是什么，有什么证据和风险？
- 我的持仓逻辑仍然成立吗，继续持有的价值是多少？
- 当前账户是否应该把资金从一个机会转向另一个机会？
- 我实际执行后赚亏在哪里，如何验证改进有效？

用户可以自由研究或手动成交；系统不会因为用户偏离建议而拒绝记录事实。建议是否采纳、真实成交是否符合计划，分别记录。

## 2. 产品结构与路由

| 工作区 | 路由 | 二级内容 | 默认视图 |
|---|---|---|---|
| 今日工作台 | `/today` | 待处理、今日计划、盘前/盘中/盘后简报 | 按优先级排列的待处理列表 |
| 市场与选股 | `/market` | 全市场、行业主题、候选池、我的筛选 | 当前扫描的联合候选池 |
| 股票研究 | `/research` | 研究清单、论点、证据、事件 | 最近关注与待更新研究 |
| 组合与执行 | `/portfolio` | 总览、持仓、计划、成交、现金 | 当前账户持仓 |
| 策略实验室 | `/strategies` | 策略、实验、模型、发布 | 策略列表及运行状态 |
| 复盘与洞察 | `/review` | 日复盘、绩效、归因、改进提案 | 最近交易日复盘 |
| 收件箱 | `/inbox` | 风险、计划到期、研究变化、系统事项 | 未处理 |
| 设置 | `/settings` | 账户、风险、数据源、模型服务、通知、系统 | 账户设置 |

全局股票档案路由为 `/stocks/{instrumentId}`。列表内打开右侧预览，选择“展开”进入完整档案；同一数据和标签在所有入口一致。候选详情 `/opportunities/{id}`、决策详情 `/decisions/{id}`、实验详情 `/experiments/{id}` 都可直达。

“我的筛选”与“自选”分开：前者是查询规则，后者是用户明确关注的股票集合。自选不意味着已被系统推荐，也不自动启用持续监控。

## 3. 关键产品对象

| 对象 | 含义 | 与下游关联 |
|---|---|---|
| 股票档案 | 企业、证券、市场数据和研究的统一入口 | 研究、候选、持仓 |
| 证据 | 可追溯的公告、财报、行情事实或新闻来源 | 支持/反对研究论点 |
| 研究论点 | 对未来收益来源的解释及可证伪条件 | Agent 评估、策略适配 |
| Agent 研判 | 基于指定证据版本的结构化分析 | 选股/持仓联合输入 |
| 策略版本 | 周期、股票池、模型、Agent 协议和规则的完整合同 | 扫描、回测、生产运行 |
| 候选机会 | 股票与策略在某时点的机会快照 | 联合评估和决策 |
| 决策 | 特定账户、股票及快照下的唯一当前建议 | 执行计划与监控 |
| 执行计划 | 用户打算怎样落实决策 | 预留、成交、偏差 |
| 成交 | 已经发生的券商买卖事实 | 账本、持仓、绩效 |
| 复核 | 特定新事件对当前计划的重新评估 | 新决策或关闭触发 |
| 实验 | 对冻结假设、数据和参数的一次验证 | 提案、发布 |
| 发布包 | 被允许影响生产的联合能力版本 | 所有生产决策 |

同股可有多个研究论点与策略候选，但一个账户只有一个当前有效决策入口。用户看到候选冲突时，应能查看不同策略理由及组合仲裁结果，不需自行在多张互相矛盾的建议卡中做合并。

## 4. 用户场景

### S01：盘前准备

前置：账户已设置，市场数据有最近完整交易日。进入今日工作台后，先看到未处理持仓风险、当日计划、昨日研究变化，再看市场方向。

市场 Agent 汇总有来源的政策/行业/公告变化，市场状态模型提供趋势、波动、流动性与行业扩散判断。简报显示“发生了什么 → 与我有什么关系 → 哪些标的需要检查”。Agent 观点与模型判断不同则并列说明，不能把差异抹成一个虚构共识。

完成证据：用户可把一项研究变化直接打开到对应持仓或候选，且保留原始证据和时间。没有新信息时明确“暂无新增变化”，不每天生成重复长文。

### S02：模型与 Agent 联合选股

触发：用户运行某策略，或策略按日程扫描。

1. 系统构建符合当前交易权限的证券池，同时保留研究可见股票。
2. 模型根据价格、量能、基本面、资金等特征广泛召回；事件 Agent 也可根据新事件召回股票。
3. 合并召回来源，去重；Agent 对预算内候选检查逻辑、催化时间、事件真实性及反证。
4. 联合模型在更新的证据快照下给出概率、条件收益分布和路径可成交性。
5. 账户约束与组合决策器生成可执行、等待条件或仅研究状态。

列表首先展示股票、策略/周期、联合判断、收益风险、触发条件、研究变化、数据时间。可展开“为何选中”“最强反证”“为何暂不能操作”。

深度研究数量受预算约束。未被深查者标记“待研究”，不能冒充完成联合评估。扫描缺页、部分股票行情失败、Agent 超时时，以完成数/总数及原因呈现；不把部分成功说成全市场扫描完成。

### S03：股票深度研究

用户从候选、持仓、全局搜索进入同一个股票档案。档案包含：

- 公司业务与收入构成；财务趋势与质量；估值及可比公司。
- 行业与产业链关系；主要驱动因素；市场预期变化。
- 日线/分钟行情、流动性、资金行为及相对表现。
- 公告与事件时间线；来源发布时间和平台首次获知时间。
- 当前研究论点：支持、反证、验证节点、失效条件。
- 量化判断：适用模型、样本支持、条件收益分布与关键风险。
- 本账户关联：持仓成本、持仓理由、历史决策、当前计划。

研究 Agent 可执行“分析业绩质量”“比较两家公司”“检查论点变化”等任务。输出保存为研究产物，带证据引用及不确定性，不只有不可复用聊天记录。

估值输入缺少财务数据时只展示缺口；禁止生成看似精确的目标价。LLM 自行编造的利润预测不能与已披露业绩放在同一事实表中。

### S04：持仓持续管理

每次真实成交建立或更新持仓；买入时关联当时论点、策略、周期和决策。手动买入可补写用户自己的理由，来源标记为“用户”，不能伪造成系统当时推荐。

持仓 Agent 维护论点状态：保持、增强、削弱、失效或证据不足。它检查业绩/公告/行业变化、原催化是否兑现、反证是否出现，而不是仅复述当前浮盈亏。

持仓模型比较继续持有、增加、减少及全部退出的未来费后价值，使用当前状态、剩余周期、路径和合法数量。组合决策器再考虑资金替代机会、相关暴露及账户风险。

界面每只持仓回答：

1. 当前建议及目标股数是什么？
2. 为什么现在需要或不需要变化？
3. 量化与 Agent 分别贡献了什么判断？
4. 什么新事实会改变建议？
5. 哪些条件限制执行，下一次何时复核？

硬止损命中立即产生风险事项；仍需用户实际交易。T+1 无法卖出的部分显示锁定数量及最早可卖日。不得把提醒发出显示为“已清仓”。

### S05：组合再配置

用户请求“检查组合”，系统读取所有持仓及已完成联合研究的候选。组合 Agent 检查隐含主题集中、重复产业链暴露和研究逻辑冲突；风险模型估计相关性与共同尾部风险；优化器形成一个组合计划。

计划列出各标的变化、依赖的卖出资金、预计费用、调整前后暴露。尚未成交的卖出不能为买入释放真实可用资金；需要先卖后买时明确执行顺序。

用户可接受部分计划，系统按接受后的真实预留重新检查剩余动作。接受计划不改变真实持仓。

### S06：人工执行与成交记录

可从决策创建计划，也可直接录入真实成交。表单至少包含账户、证券、买卖方向、时间、数量、价格、费用及来源。

保存后显示真实结果：现金变化、持仓数量、今日新增锁定量、关联计划完成比例。重复导入同一交割单不重复记账。错误记录通过冲正及更正处理，保留审计；删除 UI 记录不能悄悄改历史净值。

计划失效后实际发生的成交仍应如实保存，标记偏离计划并重新评估持仓。若历史事实与当前账本冲突，进入对账流程，不能为了让表单成功而改掉历史。

### S07：盘后复盘

复盘 Agent 读取当日决策、证据、模拟结果、真实成交和归因结果，回答：

- 当时哪些判断正确或错误？
- 错在信息、预测、策略选择、仓位还是执行？
- 有哪些机会没交易，原因是否合理？
- 哪个假设值得做实验，而非凭单笔输赢改规则？

模型计算结果与 Agent 归因分层显示；“归因假设”不能包装成已证实因果。所有数字从结构化结果引用。用户可把一项改进转成实验草案，保留来源 episode。

### S08：策略研究与发布

用户或策略 Agent 提出假设，选择数据区间、市场范围、模型与 Agent 协议、费用、执行与风险约束。系统登记实验后冻结确认区间。

用户对比联合系统、去掉 Agent、去掉量化、公式基线及当前生产版本。检查整体费后绩效、模型校准、Agent 证据质量、延迟与成本，不能只看胜率。

发布的是完整联合版本。若未通过，保存失败原因，生产保持当前有效版本；首次上线没有合格版本时保留研究与账本能力，不制造“临时公式推荐”。

## 5. 页面详细要求

### 5.1 今日工作台

从上到下：交易日/数据状态 → 账户风险摘要 → 待处理事项 → 今日计划 → 市场与研究变化。

优先级由风险和时效决定：账本异常/硬风险、即将失效的执行、论点变化、研究任务、一般资讯。收益数字不能挤占关键待办位置。

每条事项有股票/账户、发生原因、截止时间、当前状态与唯一主要操作。无待办时提供“查看持仓”“研究候选”，不填充无依据的机会。

### 5.2 市场与选股

顶部为策略、周期、股票范围、扫描时间和更新操作；下方为筛选条和候选表。

保存视图包含过滤条件、排序、列顺序，不复制候选数据。排序分为研究优先级和账户执行优先级，明确标签，禁止将 Agent 研究信心当作收益概率。

行业页展示热度、宽度、趋势、事件和成分股。热度不直接表示值得买；点击行业进入同一个候选查询上下文。

### 5.3 股票研究

完整页面采用概览、行情、财务与估值、研究论点、事件、历史决策六个标签页。右侧研究上下文区展示任务、证据和备注。

研究论点可手动编辑形成新 revision；旧 revision 仍属于过去决策。文本的“当前版本”不能覆盖历史证据链。

### 5.4 组合与执行

总览聚焦现金、净值、风险预算和暴露，持仓表聚焦当前动作及理由。盈亏、建议、计划状态三列分开。

“做 T”是持仓执行子场景，复用数量、费用、T+1、动作评估与成交归因，不建设另一套独立推荐引擎。

### 5.5 策略实验室

策略详情包含投资假设、适用范围、联合流程、版本、绩效、数据支持与发布记录。模型详情包含目标、样本、校准和依赖，不把超参数堆在首屏。

编辑器首版采用受限表单和结构化配置。复杂 Python 扩展走仓库评审，不允许页面提交任意代码在生产执行。

### 5.6 复盘与洞察

区分真实账户绩效、策略模拟绩效与研究覆盖。默认看真实账户，切换时始终显示数据来源。

个人入金出金使用时间加权/资金加权等明确口径处理；原始资产增加不能直接算为投资收益。报表支持导出但默认排除凭证与敏感配置。

## 6. 权限与隔离

| 角色 | 可做 | 不可做 |
|---|---|---|
| 所有者 | 管理自己的账户、研究、策略启用、风险偏好 | 跨账户越权读取 |
| 只读成员 | 查看被授权账户与研究 | 写成交、改风险、发版 |
| 系统作业 | 按任务权限采集、推理、研究和结算 | 使用管理员身份任意写对象 |
| Agent | 使用白名单工具，写指定研判/提案对象 | 写真实成交、转账、改风险授权、直接发生产版本 |

个人使用也需要将“研究资料可共享”和“账户现金/交易私有”分开。公共股票研究缓存必须剥离账户信息。

## 7. 状态、异常与恢复

| 情况 | 用户看到什么 | 可执行操作 |
|---|---|---|
| 行情正在更新 | 上次有效值、时间、更新状态 | 继续研究，过期计划不可新增风险 |
| Agent 尚未完成 | 量化初筛 + “联合研判待完成” | 查看初筛、取消或等待，不创建有效买入 |
| 模型失败 | 研究仍可读，决策不可用 | 重试任务、查看原因、记录真实成交 |
| 双方明显冲突 | 具体冲突与缺失证据 | 查看反证、进一步研究、等待 |
| 无机会 | 完整扫描覆盖、无机会原因 | 保存观察或调整研究范围 |
| 批量部分成功 | 每项成功/失败，已完成结果即时出现 | 只重试失败项 |
| 账户已变化 | 原结果保留历史、当前计划需更新 | 获取新版本 |
| 刷新或换设备 | 从服务端恢复真实任务与计划 | 不重新启动相同任务 |
| 取消研究 | 已保存事实可读，任务为已取消 | 新任务显式重开 |
| 收盘时仍在观察 | 当日触发终止或按策略明确跨日 | 不静默延长有效期 |

详细状态枚举和合法迁移只在 04 定义，前端不可另造类似含义的状态。

## 8. 产品指标与验收

主要指标：完成一轮研究/决策的时间；候选联合研判覆盖；持仓论点更新及时率；可追溯决策比例；成交对账成功率；策略费后绩效和回撤；每个有效研究产物成本。

不用聊天次数、Agent 数量、报告篇数和强制交易次数作为核心成功指标。

验收至少包含：一个正常联合选股案例、一个双方冲突案例、一个持仓论点失效案例、一个 T+1 无法退出案例、一个真实成交偏离案例、一个失败实验、一次发布回滚。具体 Given/When/Then 在 08。

## 9. UI 与实施交接

视觉方向按 05；本文规定信息优先级、用户对象与操作结果。界面可以改变排版，不能把“研究完成”改成“可以买入”，不能把“计划确认”改成“已成交”。

首期研究、账户、联合决策都可按独立阶段验收；“完整生产平台”必须完成联合选股与联合持仓管理，不能以仅有公式扫描、LLM 聊天或只读行情页面代替。
