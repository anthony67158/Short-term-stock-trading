# 实施计划：按可运行的投资闭环重建

> 隶属 `a-share-platform-rebuild.v1.0`。本册为待执行任务，不代表已完成开发。  
> 默认顺序：恢复点与合同 → 研究 → 账户 → 模型与Agent联合决策 → 实验 → 持续学习 → 正式切换。

## 1. 实施规则

每个任务必须交付代码、对应合同变化、可运行验证和简短证据。涉及页面的任务包含实际用户结果，不能仅以接口200或静态截图结项。

任务一般控制在一次集中实施内；下表路径表示目标范围，不要求所有文件都在同一任务创建。单任务若超过约5个实质业务文件或存在两个独立目标，继续拆子任务并保留父验收。

每个切片在新平台独立完成；旧实现只能作为人工理解和迁移证据，不允许import或HTTP调用旧服务来冒充重建完成。

**模型与 Agent 不延期为装饰性增强。M3 的退出条件明确要求两者共同参与选股与持仓管理。** M1/M2可独立交付研究与账本，但不称为完整决策平台。

## 11. 任务完成定义

每项交付记录：

```text
任务：T编号与标题
依据：设计revision、章节、AC编号
实现：最终行为、变更范围
验证：实际命令/环境、结果、证据路径
限制：尚未覆盖的市场/数据/错误情况
状态：已实现 / 已离线验证 / 已部署 / 已线上验收
```

以下不能结项：只有函数存在；只打印“成功”；只比较源码字符串；替换测试预期让CI通过；把模拟接口当真实集成；把Agent摘要展示出来但未进入决策。

## 12. 验证命令规划

新工程应提供以下稳定入口，由对应任务建立。**这些命令当前尚未存在，不能在本轮报告为已通过。**

| 入口 | 用途 |

默认CI离线且用假数据。付费LLM、正式数据商和云训练使用单独workflow与预算，不能在每次PR默认调用。

部分并行后的基础平台可按约10～16周规划；可信Agent历史证据缺失、数据采购或模型未通过验证可能显著延长交易能力启用时间。不能通过删除验收压缩这部分不确定性。

资源预算拆为行情/财务/公告数据、LLM研究、常驻服务、数据库、对象存储、批训练六项。先记录实际调用量和单价，再设月度预算，不在未询价时填写虚构云费用。

## 14. 停止、改向与延期规则

- 历史分钟数据不足：继续日线研究与账本，限制依赖分钟成交的策略范围。
- 无法可信重建Agent历史输出：积累前瞻模拟研判，不能将后见信息当历史能力。
- 联合模型不优于消融基线：保留研究与账本，改进融合或数据，不偷换成纯公式生产。
- 新架构在线延迟不满足：优化具体热点，不重新创建第二套决策内核。
- 账户迁移不对平：停止切流，保留旧运行；先修迁移。
- 新增功能没有目标、对象所有者或AC：先补规格，不直接追加到大组件。

## 15. 第一批立即可执行任务

实施启动后先完成T00/T01，创建重建分支与可验证恢复点；随后T02清理新开发树、T03冻结基础合同、T04设计组件、T05验证运行形态。

第一阶段演示应是“搜一只股票→查看有来源的数据→Agent生成可追溯论点→保存研究”，第二阶段演示真实账本，第三阶段才将已验证的模型与Agent联合建议连接到执行计划。每一步都有用户价值，并最终组成完整平台。
