# 新模型数据准备核查

日期：2026-09-16。范围为现存本地归档发现，不是训练验收或生产收益证明。

## 实测资产

- `.tushare-v4-history-2016-2021`与`.tushare-v4-5y`共19个日线分片，
  2016-01-04至2026-09-11，合计10,114,448行，包含跨分片重叠。
- 每个分片的压缩文件均计算SHA-256；逐行检查代码、日期长度、有限数值、
  OHLC范围、非负量额和片内重复。本次这些检查无违规。
- 分片日线证券数从2,099至3,051；最近分片代码前缀仅
  000/001/002/003/600/601/603/605，不能称为全A股。
- 分片有只读SQLite分钟库。完成表记录2,077～3,032只下载证券；
  这只证明下载状态，尚未核验每日股票池、逐分钟覆盖及未选中股票。
- 独立保留证券档案5,901条，其中339条有退市日期，包含上市/退市日及交易所
  代码。最新日线分片的3,051只股票与该档案均匹配，其中已退市数为0。
  各历史分片仅0～1只匹配退市证券，尚不能证明包含当时完整股票池。

## 阻止直接复用的缺口

1. 日线行没有availableAt、历史上市/退市状态、复权因子字段。证券档案可以用于
   后续交叉核验，但其历史可用性、是否完整包含所有当时证券尚未证明。
2. 行内name/isSt可能来自后补元数据，不能当作历史风险警示身份事实。
3. 分片之间有重叠，必须按证券+日期比较原始行情冲突后去重；不可直接拼接训练。
4. 分钟股票池是旧流程产物。下载成功不等于因果召回覆盖，不能沿用其选择分母。
5. 旧NPZ含旧策略候选、标签、模型特征和已多次查看的确认段，只能作研究参考。
   新标签必须由新撮合政策重建；旧确认窗口需标记为开发数据。
6. 没有已核验的当时Agent研判；当前供应商推理仍401。历史重建必须标记
   retrospective，不能声称等同当时在线证据，不能无证据宣称联合收益提升。

## 可复跑入口

```sh
cd backend
uv run platform-cli audit-market-archive \
  --archive-root /Users/bytedance/.tushare-v4-history-2016-2021 \
  --archive-root /Users/bytedance/.tushare-v4-5y \
  --securities-file /Users/bytedance/.tushare-prehistory-work/tushare-metadata/securities.json.gz \
  --output /tmp/platform-market-archive-audit.json
```

入口只读日线、证券元数据和SQLite下载表，不import旧代码、不加载模型、不联网。
报告明确`productionEligible=false`；片内格式通过不解除上述门禁。

下一步先建立有历史证券范围和单位证据的新规范化数据集，再实现同源撮合、
成交/收益分布与持仓配对标签；数据补齐和Agent恢复前继续研究/账本模式。

## 2026-09-16 新数据源能力探测

- 仓库外既有 Tushare 兼容凭据可通过受限 HTTPS 网关使用；官方
  `api.tushare.pro` 对该凭据返回业务鉴权失败，因此当前不能标记为官方直连。
- 脱敏实测取得当前上市5,562只、退市339只；2026-09-15取得日线5,548行、
  复权因子5,562行及停牌17行。
- 主板`000001.SZ`、创业板`300001.SZ`、科创板`688001.SH`、北交所
  `920000.BJ`均取得09:35至15:00的48根5分钟K线。
- 新 Adapter 将日线成交量从手转换为股、成交额从千元转换为元；历史分钟接口
  已是股和元，不重复换算。价格和金额按十进制字符串进入规范层。
- 上述只证明接口与四类样本可取，不证明全历史完整或数值正确。生产门禁仍要求：
  按交易日全市场下载、上市/退市因果范围、北交所新旧代码映射、停牌解释、
  复权因子、分片哈希，以及独立数据源逐板块抽样比对全部通过。
