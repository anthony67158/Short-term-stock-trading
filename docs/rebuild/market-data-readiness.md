# 新模型数据准备核查

日期：2026-09-16。范围为现存本地归档发现，不是训练验收或生产收益证明。

## 实测资产

- `.tushare-v4-history-2016-2021`与`.tushare-v4-5y`共19个日线分片，
  2016-01-04至2026-09-11，合计10,114,448行，包含跨分片重叠。
- 每个分片的压缩文件均计算SHA-256；逐行检查代码、日期长度、有限数值、
  OHLC范围、非负量额和片内重复。本次这些检查无违规。
- 分片日线证券数从2,099至3,051；最近分片代码前缀仅
  000/001/002/003/600/601/603/605，不能称为全A股。
- 分片有只读SQLite分钟库。完成表记录2,077～3,032只下载证券；
  这只证明下载状态，尚未核验每日股票池、逐分钟覆盖及未选中股票。
- 独立保留证券档案5,901条，其中339条有退市日期，包含上市/退市日及交易所
  代码。最新日线分片的3,051只股票与该档案均匹配，其中已退市数为0。
  各历史分片仅0～1只匹配退市证券，尚不能证明包含当时完整股票池。

## 阻止直接复用的缺口

1. 日线行没有availableAt、历史上市/退市状态、复权因子字段。证券档案可以用于
   后续交叉核验，但其历史可用性、是否完整包含所有当时证券尚未证明。
2. 行内name/isSt可能来自后补元数据，不能当作历史风险警示身份事实。
3. 分片之间有重叠，必须按证券+日期比较原始行情冲突后去重；不可直接拼接训练。
4. 分钟股票池是旧流程产物。下载成功不等于因果召回覆盖，不能沿用其选择分母。
5. 旧NPZ含旧策略候选、标签、模型特征和已多次查看的确认段，只能作研究参考。
   新标签必须由新撮合政策重建；旧确认窗口需标记为开发数据。
6. 没有已核验的当时Agent研判；当前供应商推理仍401。历史重建必须标记
   retrospective，不能声称等同当时在线证据，不能无证据宣称联合收益提升。

报告明确`productionEligible=false`；片内格式通过不解除上述门禁。

## 规范数据集构建器

- 新增仓库外SQLite数据集与独立manifest，证券、别名、交易日历、未复权日线、
  复权因子、停复牌、曾用名和5分钟K线分表保存。业务键完全相同可恢复重放，
  内容变化时报冲突；封存后拒绝写入。
- 每个分区checkpoint保存源、首次获取时间、`availableAt`、可用时间重建方法和
  规范化载荷SHA-256。日线按官方15～16点入库说明保守取16:30，复权因子按
  官方盘前9:15～9:20说明取9:20；均标记为供应商时刻表重建，不冒充历史实测。
- 股票池按上市/退市区间生成，当前已退市证券不会被排除，未来上市证券不会
  提前进入。北交所旧代码映射到稳定920身份并保留源代码；北交所A股资格最早
  从2021-11-15开市日起算，同时保留供应商原始上市日。
- 2026-09-15真实探测数据集已封存于仓库外：5,562只证券（主板3,195、
  创业板1,407、科创板617、北交所343）、5,548条日线、5,562条复权因子、
  17条停复牌记录。SQLite完整性检查为`ok`，manifest数据库SHA-256经独立命令
  重算一致。17条记录含14条停牌和3条复牌。
- 构建器拒绝单次达到接口6000行上限的响应，拒绝重复键、越界证券、日线缺少
  复权因子，以及无法由停牌解释的股票池缺口。一次探测曾因日期区间外退市股
  的全量映射被错误要求闭合而失败，现仅保留与数据集区间相交证券的别名并有
  回归测试；没有放宽证券代码校验。
- `market-dataset.v3`进一步保存交易所公告佐证的暂停上市期间和代码迁移别名。
  日线、复权因子、停牌分区必须严格等于请求日期；同一证券的新旧代码仅在值
  完全一致时按当日有效代码去重，否则硬失败。供应商返回的北交所上市资格前
  新三板历史行、退市后的累计复权因子可按证券生命周期精确丢弃；其他沪深
  日线越界和无法分类的复权因子仍硬失败。每类丢弃均保存数量和源行SHA-256。
- 真实边界数据集
  `/Users/bytedance/.local/share/stock-platform/a-share-20160101-20260915-v4`
  已完成reference及2016-01-04、2020-01-02、2021-11-15三个开放日：
  5,812只证券、251个别名、3,911个日历日、12段暂停上市事实；累计10,895条
  日线、11,189条复权因子、323条停牌记录。三个分区均通过全市场覆盖门禁，
  SQLite `integrity_check=ok`。
