# 系统架构：单一领域内核、独立运行进程、清晰数据所有权

> 隶属 `a-share-platform-rebuild.v1.0`。技术选型为推荐方案，版本在 M0 验证后锁定。

## 1. 架构目标

系统必须让同一业务事实只有一个写入责任方，同一决策逻辑只有一个实现，让新增策略、Agent 或页面不需要修改所有已有模块。

三项关键决定：

1. 后端采用模块化单体代码结构，API、实时监控、Agent 作业、批量计算以独立进程运行。
2. Python 领域内核同时服务在线决策和离线回测；浏览器只消费合同和结果。
3. PostgreSQL 管理可变业务事实和事务；OSS 管理不可变大对象。缓存不作为权威账本。

## 2. 技术选型与理由

| 范围 | 推荐 | 原因与边界 |
|---|---|---|
| Web | React、TypeScript、Vite | 适合密集交互工作台，不需要 SSR 承担主要价值 |
| 路由 | React Router | URL 表达页面、账户、筛选和对象上下文 |
| 服务端状态 | TanStack Query | 缓存、失效、取消、重试有统一入口 |
| 本地界面状态 | 组件状态；跨区域少量 Zustand | 不把账户和决策复制成第二账本 |
| 表格 | TanStack Table + Virtual | 列管理、筛选与大列表 |
| 样式与无障碍组件 | CSS variables + Tailwind + Radix 基础组件 | 以本项目 token 收敛外观，不照搬默认样式 |
| 图表 | ECharts | K 线、分布、净值、暴露使用统一封装 |
| API | FastAPI + Pydantic | 类型合同、OpenAPI，与量化语言统一 |
| 业务数据库 | PostgreSQL | 事务、行锁、约束、JSONB、任务及审计 |
| 持久层 | SQLAlchemy + Alembic | 显式模型、迁移和事务边界 |
| 数据计算 | NumPy、Pandas/Polars、PyArrow、DuckDB | 分工明确；DuckDB 用于离线 Parquet 查询，不替代业务数据库 |
| 模型 | LightGBM / CatBoost 起步 | 概率、排序、分位数可建立透明基线 |
| 大对象 | 阿里云 OSS、Parquet | 延用可用云资产，不继承旧路径语义 |
| 任务 | PostgreSQL jobs/outbox + 进程 worker | 当前规模减少 Redis/Celery 运维；不自行实现通用 DAG 平台 |
| 包管理 | Web：pnpm；Python：uv | 分别锁定依赖，明确开发/推理/训练依赖 |
| 验证 | Vitest、Playwright、pytest、Hypothesis | 组件行为、浏览器闭环、领域与性质测试 |

以上不是要求一次性安装全部依赖。每项在实际切片需要时引入，锁文件记录兼容版本。禁止从旧 package.json 整体继承依赖。

## 3. 逻辑模块与所有权

| 模块 | 拥有的数据/状态 | 对外能力 | 禁止承担 |
|---|---|---|---|
| identity | 用户、会话、授权 | 认证与账户范围检查 | 交易规则 |
| market | 证券、交易日历、数据集、市场快照 | 标准行情和因果数据读取 | 写账户 |
| research | 文档、证据、论点、研判 | 研究更新与证据版本 | 创建真实成交 |
| strategies | 策略定义、版本、联合配置 | 注册、验证、运行合同 | 随意加载用户代码 |
| portfolio | 成交、现金分录、批次、预留、账户版本 | 记账、余额、合法数量 | 模型预测 |
| decisions | 决策上下文、候选、联合结果 | 联合编排与唯一建议发布 | 维护第二份账户事实 |
| monitoring | 监控订阅、触发、复核生命周期 | 发现事件、排队复核 | 浏览器状态同步算法 |
| experiments | 数据划分、实验、评估、标签索引 | 训练、回测、消融 | 未经发布更改生产 |
| registry | 发布包、当前生产指针、回滚记录 | 完整版本加载与切换 | 修改已发布包 |
| agents | AgentRun、工具调用审计、预算 | 按协议产出指定研判 | 任意数据库写入 |
| notifications | 通知事件、接收偏好、送达状态 | 收件箱/推送同源投递 | 自己判断买卖信号 |
| operations | 作业、系统配置、健康与审计 | 调度和运维查询 | 吞掉失败并伪造成功 |

模块间通过公开应用服务和不可变 DTO 交互，不直接访问另一个模块的 ORM 表。为查询页面可建立受控 read model；read model 永远不是写入事实源。

## 4. 依赖方向

领域类型及纯计算位于最底层，不 import FastAPI、SQLAlchemy、OSS、LLM SDK 或前端代码。

应用用例依赖领域类型和抽象端口。Adapter 实现数据库、行情、LLM、通知等端口。HTTP 路由与 Worker 都调用同一应用用例，不能在路由和定时任务中各写一套动作逻辑。

跨模块循环依赖由用例编排解决。例如：

- decisions 通过 PortfolioReader 获取账户快照；
- portfolio 成交事务只发出 `portfolio.changed`，不同步反调 decisions；
- monitoring 或应用订阅者消费事件并排队新评估；
- 前端接收事件后刷新相应查询。

不创建万能 `utils`、`sharedBusiness`、`globalStore`。共享内容限于 Money、Quantity、Clock、ID、错误和合同等真正稳定的基础概念。

## 6. 运行拓扑

| 进程 | 承担任务 | 资源边界 | 故障影响 |
|---|---|---|---|
| Web 静态站 | 页面、脚本、静态资源 | CDN | 不控制后台监控 |
| API | 查询、命令校验、任务提交、事件读取 | 轻量常驻 | 界面暂不可用，任务可继续 |
| Monitor | 行情更新、计划触发、硬风险提示 | 独立轻量常驻 | 提醒延迟，需健康告警 |
| Agent Worker | 证据获取、研究与持仓研判 | 网络并发和预算 | 新联合研究延迟 |
| Compute Worker | 批量推理、组合计算、复核 | 有限 CPU/内存并发 | 决策延迟，不影响账本 API |
| Batch Job | 日数据、训练、回测、结算 | 按需较大资源 | 保留当前生产包 |

这些进程来自同一后端版本，部署清单记录各自 image digest。推理工件与训练依赖隔离；API 进程不加载训练数据。

### 6.1 部署推荐

默认采用同一阿里云地域的应用容器、托管 PostgreSQL、OSS 和静态站托管。已有域名、备案和可用网络资源可以保留。Vercel 可作为可选镜像，不是新架构必须维护的第二生产面。

常驻 API/Monitor 适合容器服务或常驻实例；短时批作业可用 FC；大训练使用按需计算。具体 SKU 在 M0 压测和成本评估后选择，不能假定原 FC 配置天然适合所有长任务。

如果保留 FC 承载 API，必须实测连接保持、任务寿命、数据库连接上限、冷启动及后台进程保证；后台工作不能依赖 HTTP 响应结束后继续执行的偶然行为。

## 7. 数据架构

PostgreSQL 是账户、当前对象指针、任务状态、发布指针与配置的权威源。业务命令在事务内更新事实和 outbox。

OSS 对象按内容哈希或不可变版本寻址，包含历史行情分片、原文、模型、完整回放和训练产物。数据库保存 URI、SHA-256、schema、范围、行数及质量报告。

市场数据采用“原始获取 → 标准化 → 可用数据集”三层，不覆盖原始记录。供应商修订写新 revision。实时报价可缓存；用于发布决策的快照必须固化。

Redis、向量搜索服务、专门时序库仅在确有瓶颈时引入。首版研究检索可用元数据、全文检索与可选 pgvector；中文分词及召回质量先做小样本验证。

## 8. 账户事务与并发

每个账户有递增 `accountVersion`。真实成交、现金流、预留和冲正锁定该账户，按确定顺序锁行，提交后版本加一。

联合评估开始时读取版本；发布时在短事务中核对版本、当前 decision pointer、市场/研判有效期和 releaseId。冲突后最多进行一次有预算的重新评估；再次冲突则明确 `SUPERSEDED`，由新事实事件另起任务，禁止无穷重算。

用户成交事实具有更高事实优先级。旧计划或建议不能阻止记入已发生的合法真实成交，但账务矛盾必须进入对账，不能无验证强制覆盖。

## 9. 持久任务与事件

jobs 表至少有任务类型、业务键、状态、优先级、输入哈希、尝试次数、可执行时间、租约到期、heartbeat、fencingToken 和取消标志。

Worker 用短事务领取任务并增加 fencingToken，执行期间不持有数据库长事务。完成时必须带相同 fencingToken 条件写入；旧 Worker 即使恢复也不能覆盖新 Worker 结果。

采用至少一次交付：靠业务唯一键及幂等消费实现“一次业务效果”，不声称网络端到端恰好一次。

outbox 与业务事实同事务提交。投递 Worker 负责重试、死信和送达审计。任务优先级为硬风险记录/关键复核、账户评估、普通研究、夜间实验；每类有独立并发额度，研究不能占满交易评估资源。

取消是协作式：取消未领取任务，运行任务在边界检查；已经发生的外部调用无法保证撤回。产物发布前再次检查取消标志，防止 UI 已取消仍发布新决策。

## 10. 前端数据流

URL 保存账户选择、当前页面、筛选、对象 ID 和可分享视图。TanStack Query 保存服务端查询缓存；Zustand 只保存抽屉、快捷键、布局偏好等 UI 状态。

每次命令返回任务或新对象版本。前端不乐观修改真实现金和成交；可显示“提交中”，收到权威结果后更新。收藏、列顺序等低影响行为可以乐观更新并回滚。

首屏读取分工作区聚合接口，避免 App 全局预取所有页面。数据订阅按可见模块/当前关注列表启停，不在每个组件创建独立轮询。

服务端事件通过可恢复 SSE 提供，事件 ID 作为游标。重连无法补齐事件时返回 resync，前端重取相关快照。轮询作为后备，不能依赖事件流永不断线。

所有缓存键包含用户/账户范围；登出或切换用户清空私有缓存和后台请求。股票快速切换时取消前一请求，旧响应不能覆盖新股票。

## 11. 性能与容量目标

以下在相应里程碑压测，不是既有成绩：

| 场景 | 初始目标 | 超过后处理 |
|---|---|---|
| 缓存后的账户/持仓查询 | API P95 300ms 内 | 查询计划、索引、聚合快照 |
| 简单写命令 | API P95 500ms 内，不含外部研究 | 缩短事务和异步化 |
| 任务提交 | 1 秒内返回持久 taskId | 禁止同步等 LLM |
| 有效 Agent 快照下单股联合评估 | P95 3 秒内 | 批量特征、模型驻留、计算进程 |
| 需新 Agent 研究的联合评估 | 显示阶段；按 02 的90秒预算 | 明确过期/失败，不假进度 |
| 100只重点股监控 | 使用共享批量行情订阅/轮询 | 扩实例前先验证源端额度 |
| 通知进入应用收件箱 | 触发提交后 P95 2 秒内 | outbox积压告警；不保证外部系统推送时延 |
| 5000行候选列表 | 虚拟化，交互P95 100ms内 | 服务端分页与列裁剪 |
| 常用工作区首屏 | 标准网络 LCP目标2.5秒内 | 分包与按需图表 |

行情源更新频率是延迟下界；不得以内部轮询频率宣传真实行情频率。显示 sourceAsOf 与 receivedAt。

## 12. 安全与可观测性

会话采用 HttpOnly/Secure cookie 或同源代理会话；CSRF 防护、来源检查、限流和失效策略统一实现。账号密码不继续作为每次请求的业务参数传输。

密钥存在云密钥服务或服务端安全注入，配置 API 只返回 secretRef/hasSecret，浏览器不接触明文。自定义 LLM URL需防 SSRF、DNS 重绑定和重定向到内网。

每条关键链路贯穿 requestId、taskId、accountId脱敏标识、decisionId、assessmentId、releaseId。记录耗时、调用预算、证据拒绝原因、任务重试及发布结果。日志中不保留密码、token和不必要的账户原文。

运营页展示数据新鲜度、研究积压、联合决策成功率、模型加载、任务租约失效、发布版本和成本；交易页面只显示影响用户当前操作的状态。

## 13. 可靠性与恢复

数据库不可用：停止业务写入与新决策发布；界面可显示已缓存历史但明确不可同步。不能临时在 localStorage 建立可回写账本。

对象存储不可用：依赖未加载工件的决策停止；已验证驻留工件可以在政策有效期内继续，仍需数据库健康。

Agent 不可用：允许复用有效、输入指纹一致的研判；不可生成缺研判的新风险建议。模型不可用：研究、硬风险提示和事实记账继续。

备份：数据库连续日志/PITR按供应商能力配置，业务演练目标 RPO≤5分钟、RTO≤60分钟；任务与研究报告可重建，真实成交不得靠重跑 Agent 恢复。正式上线前证明实际恢复能力，未验证时不得声称达到目标。

## 14. 避免再次形成冗余系统

- 新领域行为必须声明唯一所有者，不允许“先放 App 里”。
- 应用层只编排，领域层只计算，Adapter只转换外部格式。
- 每个策略实现同一生命周期协议，不复制端到端路由。
- 每个 Agent 使用同一任务执行框架，不单独实现任务、缓存、重试和权限。
- 状态机由后端合同定义，前端仅映射；禁止页面修正错误动作。
- 大量逻辑文件超过约400行触发职责检查，不用机械拆文件规避检查。
- 循环依赖、跨模块 ORM访问、前端业务计算及旧目录 import 纳入 CI。
- 每个临时兼容点包含负责人、退出条件和到期里程碑；没有退出条件的不合入主链路。
