# UI 设计规范：Linear 风格的 A 股投资工作台

> 隶属 `a-share-platform-rebuild.v1.0`。本册是新界面的视觉与交互基线。  
> 借鉴 Linear 的应用结构与操作方式；以下色值、尺寸和组件是本项目设计提案，不宣称是 Linear 官方 token。  
> 本轮交付设计规格，未制作或验收真实渲染原型。

## 1. 设计方向

关键词：安静、紧凑、稳定、可追溯、操作直接。

界面首先帮助用户判断对象和状态，随后理解量化与研究依据，最后执行操作。深色默认，同时提供完整浅色主题；不是把整个页面染成黑色再堆发光卡片。

视觉语言：

- 稳定的左侧导航，顶部提供当前上下文和操作；
- 列表与表格是主要工作表面，细分隔线代替大量容器；
- 详情在右侧就近展开，长研究进入完整页面；
- 少量强调色指向选中项和主动作；
- 状态有语义、数据有单位、更新有时间；
- 键盘与鼠标能力一致，移动端保留核心任务。

参考范围为 Linear 的列表、保存视图、属性编辑、详情和收件箱。不复制其品牌、文案、图标商标，也不照搬项目管理状态成交易状态。

## 2. 信息层级

每个页面遵循四层：

| 层 | 内容 | 表达 |
|---|---|---|
| 上下文 | 工作区、账户、交易日、当前视图 | 固定头部，低噪声 |
| 当前判断 | 待处理、建议、研究变化、风险 | 主列表或详情首区 |
| 判断依据 | 模型、Agent、行情、账户约束 | 同层并列摘要，按需展开 |
| 深入细节 | 原文、模型版本、完整候选、审计 | 标签页/次级区域 |

不能用大幅净值数字压过紧急风险事项。不能用“综合分92”代替概率含义和证据。不能将模型/Agent名字变成页面上最大的标题。

## 3. 页面骨架

### 3.1 桌面尺寸

| 区域 | 初始尺寸 | 行为 |
|---|---:|---|
| 左侧导航 | 224px，可在200～280px调整 | 稳定，不随内容跳动 |
| 折叠导航 | 56px | 图标有提示与无障碍名称 |
| 工作区顶栏 | 48px | 标题、账户、上下文操作 |
| 视图/筛选工具栏 | 44px起 | 筛选多时允许换行或收起 |
| 主要内容内边距 | 24px | 数据表可边到边，保留统一列边距 |
| 右侧对象预览 | 400～480px | 可关闭、展开成完整页面 |
| 完整研究正文 | 最高约960px阅读宽度 | 图表/大表允许更宽 |

1280px以下若主表被挤压，详情使用覆盖式抽屉。1440px及以上可并排显示。禁止固定三栏导致主表剩余几百像素。

### 3.2 导航

侧栏上部：工作区名称、全局搜索、收件箱。中部：六个业务工作区。下部：收藏的筛选/研究、设置与账户入口。

菜单不显示技术模块名。当前项同时使用背景、文字权重和语义标识，不依赖左侧彩条。子视图在页面内展示，避免三层展开树。

### 3.3 右侧上下文

股票预览与研究助手共享一个上下文区域，通过标签切换；不允许股票抽屉、助手抽屉、证据抽屉三个同时叠加挤压主内容。证据可在同区逐级进入并返回。

## 4. Token 体系

三层结构：原始值 → 语义 → 组件。业务组件只使用语义/组件 token。

### 4.1 颜色

| 语义 token | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `surface.canvas` | `#101114` | `#FFFFFF` | 主背景 |
| `surface.navigation` | `#0D0E11` | `#F7F7F9` | 侧栏 |
| `surface.raised` | `#17181C` | `#F6F6F8` | 弹层、必要分区 |
| `surface.hover` | `#202127` | `#EEEEF2` | 悬停 |
| `surface.selected` | `#292B40` | `#ECECFC` | 选中 |
| `border.subtle` | `#2B2D34` | `#E2E3E8` | 非交互细分隔 |
| `border.control` | `#6F727D` | `#7B7D87` | 必要控件边界 |
| `text.primary` | `#EDEDEF` | `#202127` | 正文、数据 |
| `text.secondary` | `#A0A1A8` | `#626470` | 辅助信息 |
| `text.disabled` | `#686A75` | `#9A9CA7` | 不可用状态，需文字解释 |
| `accent.text` | `#A5A8FF` | `#5155BE` | 链接、选中项 |
| `accent.solid` | `#5B5FDB` | `#5B5FDB` | 主按钮背景，白字 |
| `market.up` | `#EF6B73` | `#B42332` | A股上涨/盈利 |
| `market.down` | `#4BBF91` | `#087B55` | 下跌/亏损 |
| `status.warning` | `#E6B75C` | `#8A5700` | 待处理/不确定 |
| `status.info` | `#7AA8F8` | `#285BAC` | 信息与进行中 |
| `status.success` | `#78C89D` | `#257547` | 保存成功，与行情涨跌分开 |

风险不能只靠红色区分，因为A股红色也代表上涨。风险使用图标、标题和文字；上涨数字不套风险警告底色。后续可提供用户涨跌配色偏好，但默认中国市场习惯。

### 4.2 字体与数字

正文优先系统中文字体，拉丁字符使用系统 sans-serif 或经许可自托管字体。无需额外品牌装饰字体。

| 层级 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| 页面标题 | 20/28px | 600 | 每页一次 |
| 区块标题 | 15/22px | 600 | 详情分节 |
| 正文/控件 | 14/22px | 400/500 | 阅读与操作 |
| 紧凑表格 | 13/20px | 400/500 | 高频数据 |
| 元信息 | 12/18px | 400 | 来源、日期 |
| 核心金额 | 24/32px | 600 | 少量账户关键数字 |

数字使用tabular-nums；金额、数量右对齐。股票代码可使用等宽数字，但中文说明不用整段等宽字体。正文不得低于12px；移动端输入至少16px。

### 4.3 间距、圆角和层级

间距：4、8、12、16、24、32px。组件内部优先8/12px，区块间24px，页面分区32px。

圆角：4px用于小标记、6px控件、8px弹层/必要容器、12px大型对话框。圆角不形成卡片套卡片。

阴影仅用于弹层层级，主内容不靠大阴影区分。层级序列：内容0、粘性表头10、导航20、抽屉40、对话框60、提示80；统一管理。

## 5. 组件规格

### 5.1 按钮与输入

桌面紧凑32px、标准36px、移动44px。一个操作组内下拉、输入、按钮等高；图标按钮宽高相同。

主按钮实色、次按钮边框、低频按钮幽灵样式。每个主要上下文只突出一个主动作。危险操作写具体行为，如“冲正这笔成交”，不写“确定”。

禁用按钮要有邻近原因；不能只在不可点击的按钮tooltip里藏原因。加载保留原按钮宽度与文本语义，不让整组控件跳动。

### 5.2 数据表

标准行40px、舒适行48px、紧凑行36px；默认40px。表头36px，数值右对齐、文本左对齐，状态左对齐保证扫描稳定。

功能：列显隐、排序、过滤、冻结股票列、键盘焦点、行详情、保存视图。长表虚拟化；保留可访问的行/列语义或分页替代。

默认不用斑马纹，使用细分隔和轻悬停。实时价格更新不改变用户正在操作的行顺序；提示“有新结果”，用户应用新排序，或仅在未选中时按明确策略更新。

### 5.3 联合决策区域

详情首区固定顺序：

1. 当前动作、目标股数、适用时间；
2. 执行价格/触发条件、有效期；
3. 量化依据与Agent研判摘要并列；
4. 最强反证、账户限制；
5. 创建计划/查看复核的主要操作。

量化部分显示概率定义、收益区间、成本及样本支持；Agent部分显示论点变化、关键证据和未知。两者不同步时显示各自时间，禁止只显示最近一方时间冒充整体最新。

### 5.4 研究论点

由“论点一句话、当前状态、支持证据、反证、下次验证节点”组成。默认各显示少量摘要，点击进入完整证据。

每条引用可定位原文片段，展示来源和时间。未知值写“未披露”或“暂缺”，不写0。推断增加“研究判断”标签，避免与公告原文混淆。

### 5.5 任务进度

使用实际阶段：“读取公告 → 核对事件 → 评估持仓 → 汇总建议”。展示已完成项和等待项，可展开耗时与失败原因。

只有确知总数的批任务显示百分比。LLM不确定耗时使用阶段和已耗时，不使用自动增长到99%的假进度。不展示模型隐藏推理过程，展示工具活动、证据摘要和可审计产物。

### 5.6 通知

收件箱记录持久事项；toast只用于短确认。硬风险事项不能仅闪现4秒后消失。声音、banner、收件箱同源去重。

通知内容固定为“对象 + 发生了什么 + 需要做什么 + 时间”。禁止“重大利好！速买！”等制造急迫感的语言。

## 6. 六个页面的构图要求

| 页面 | 首屏主内容 | 次要内容 | 不应出现 |
|---|---|---|---|
| 今日工作台 | 风险事项与行动列表 | 市场/研究变化 | 大幅英雄区、营销标语、十几个KPI卡 |
| 市场与选股 | 策略工具栏 + 候选表 | 行业上下文、选中股票预览 | 多个不同名称的重复选股模块 |
| 股票研究 | 股票头部 + 论点/量化摘要 + 当前标签内容 | 上下文证据区 | 默认一屏堆满所有图表 |
| 组合与执行 | 账户简要指标 + 持仓/计划表 | 暴露与资金细节 | 每只持仓一个超大卡片 |
| 策略实验室 | 策略列表/版本对比 | 模型与实验状态 | 演示式神经网络动画 |
| 复盘与洞察 | 收益/回撤图 + 归因表 + 变化结论 | 明细和实验提案 | 仅胜率和好看的收益曲线 |

候选表建议默认列：股票、联合状态、策略/周期、条件收益、风险区间、触发条件、研究变化、更新时点。不要全部字段默认展开；完整变量在详情查看。

持仓表建议默认列：股票、现有/可卖股数、市值与盈亏、当前动作、目标股数、论点变化、待处理。成本、行业等可选显示。

## 7. 图表规范

K线、资金、量能在对齐时间轴上显示；不同量纲不得随意叠加同一坐标轴。复权方式、时间范围、频率、数据缺口与来源必须可查。

收益分布明确横轴是金额、收益率或R；预测区间使用带状范围，不能把Q90画成保证目标。实际价格和预测区域在时间上分隔。

绩效图默认显示净值、基准和回撤；可以切换真实/模拟，但不能同色无标签混画。缺数据时断线，不线性填补成平滑收益曲线。

图表颜色沿用token，tooltip含日期、单位和来源口径。必须提供表格或文本摘要作为可访问替代。

## 8. 键盘与快捷操作

| 快捷键 | 动作 | 限制 |
|---|---|---|
| Cmd/Ctrl+K | 全局搜索/命令入口 | 不直接执行成交或发布 |
| `/` | 当前列表搜索 | 输入框中不拦截 |
| Esc | 关闭最上层弹层 | 未保存表单按明确规则处理 |
| ↑/↓ | 列表导航 | 焦点稳定 |
| Enter | 打开选中详情 | 表单内遵循表单语义 |
| `?` | 查看快捷键 | 非输入状态 |

股票代码、名称、研究、策略和任务在全局搜索中分类显示。命令菜单可以“打开成交录入”，不能仅按一个快捷键提交真实成交。

## 9. 响应式

大屏1440px以上支持列表+详情并排；1024～1439px可折叠导航；768～1023px侧栏可抽屉化；小于768px使用底部或顶部简洁导航与全屏详情。

移动端默认最多保留股票、动作、关键数量/盈亏和状态；其余点开详情。禁止把桌面8列强行缩成6px文字。确需横向表格时冻结对象列并提供可发现滚动提示。

移动端任务重点是查看建议、核对证据、接收提醒、录入成交；复杂实验配置可进入专门页面，不用桌面悬浮窗口堆叠。

## 10. 文案词典

| 内部含义 | 用户文案 |
|---|---|
| READY | 可按计划执行 |
| CONDITIONAL | 等待条件 |
| UNAVAILABLE | 评估暂不可用 |
| thesis weakened | 持仓逻辑减弱 |
| conflicting assessments | 量化与研究存在分歧 |
| insufficient support | 相关样本不足 |
| task queued | 已排队，等待处理 |
| data stale | 数据截至09:42，尚未更新 |
| forecast quantile | 相似条件下的收益区间 |
| release rejected | 本次版本未通过评估 |

用具体原因替代“风险过高”“信心不足”空话。说明“现有资金不足以按该价格新增200股”比暴露blockerCodes更有用。

所有示例数据在原型中注明模拟，不把方案示意中的价格呈现为真实股票报价。

## 11. 动效、无障碍与状态

动效仅用于反馈和空间关系：按钮/悬停100～140ms、菜单/抽屉160～200ms、页面内容切换不超过180ms。避免数字不断跳动、背景闪烁和盈亏庆祝动效。

支持prefers-reduced-motion；关闭非必要位移动效。焦点轮廓清晰，颜色对比以WCAG AA为目标：普通正文4.5:1，大字3:1，必要控件边界/焦点3:1。装饰分隔线不承担唯一可识别性。

弹层有焦点管理、Esc与返回焦点；图标有名称；错误关联输入；状态更新用克制的aria-live；颜色之外还有文字/图标表示涨跌和风险。

覆盖空、加载、部分成功、失败、过期、无权限、取消、数据缺失等状态。骨架只模拟结构，不假造数值；已有数据更新时保留内容并显示更新时间。

## 12. 前端交付与审查

先在隔离组件目录做token、控件和两张关键页：候选表+联合详情、持仓表+论点变化。通过后扩展其他页面。

设计验收矩阵：390×844、768×1024、1280×800、1440×900；深浅主题；键盘；200%缩放；长中文；空数据；错误；5000行；真实任务状态。

验收证据必须来自浏览器渲染截图和操作结果。仅提供CSS、token或静态截图不能证明交互、响应式和任务状态正确。

不得引入：卡片套卡片、巨型渐变标题、荧光边框、无依据综合分、内部字段直出、用AI聊天框代替研究对象、前端另算买卖动作。
