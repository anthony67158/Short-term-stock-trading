# 仓库清理、数据迁移与正式切换

> 隶属 `a-share-platform-rebuild.v1.0`。本轮先交付方案；本文描述实施时执行的清理步骤。  
> 最终结果：当前开发树只保留新系统、新文档、新测试与有效环境资产，旧业务代码不再被加载。

## 1. “彻底重构”的具体含义

产品目标、领域模型、数据库、API、任务体系、前端和测试重新建立，不要求兼容旧建议正文、旧接口、旧模型字段或旧页面。

保留环境资产是保留可用的账号、域名、云资源及密钥引用，不是把旧部署脚本原样搬入新项目。真实交易事实属于用户资产，与待删除代码分别处理。

旧代码和文档可以退出当前工作树；恢复材料放在隔离归档与Git历史中，不作为新开发文档入口，不进入运行依赖。

## 2. 当前风险基线

本轮开始时工作区已有大量未提交修改、删除及未跟踪文件。只打一个HEAD tag不能恢复这些内容。清理前必须同时捕获：

1. Git当前提交与分支；
2. tracked差异及删除清单；
3. untracked文件；
4. ignored但有必要保留的环境资产；
5. 外部运行中的服务、调度与云数据指针。

本轮没有读取或复制生产私密账户内容，也没有证明所有正在运行任务已停止。实施时先盘点，再决定切换窗口。

## 3. 保留与删除矩阵

| 资产 | 新工作树处理 | 历史/恢复处理 | 原因 |
|---|---|---|---|
| `.git/`及远端仓库身份 | 保留 | 原分支/commit引用保留 | 更新同仓库，不强推删除历史 |
| `.env`、`.env.local`、凭据文件 | 仅本地安全保留；新配置重新映射 | 私密备份，不入Git | 保留访问能力 |
| `.env.example` | 重写为新系统键名，无真实值 | 旧键名映射表 | 旧配置可能包含无效依赖 |
| `.gitignore` | 重写/合并覆盖新产物和密钥 | 保留必要规则 | 防止敏感文件或训练数据入库 |
| 云账号、OSS桶、域名、备案 | 保留可用资产 | 记录资源ID和权限，不记录密钥明文 | 不因代码重建销毁资源 |
| `s.yaml`、Vercel配置、Docker/CI | 归档旧版，新建部署模板 | 旧部署恢复档案 | 目标运行形态已变化 |
| `src/`、`api/`、`shared/` | 重建分支删除旧业务树 | 隔离旧快照 | 不保留旧内核 |
| `server.js`、`dev-server.js` | 删除旧入口 | 同上 | 新API/任务进程替代 |
| `qlib-service/` | 旧实现删除，新Python模块重建 | 旧模型/训练证据分开归档 | 不机械继承维度与标签 |
| `test/`、旧`harness/`、旧`backtest/` | 删除旧测试代码，按新合同重建 | 提炼有价值场景文字 | 不让旧断言约束新产品 |
| 旧`scripts/` | 明确清单删除/重写 | 必要迁移逻辑人工参考 | 清除失效维护入口 |
| `docs/`历史方案、旧`design.md` | 旧文档退出开发树 | release/archive引用 | 防止多份“唯一方案”冲突 |
| 本目录`docs/rebuild/` | 保留并成为主入口 | 固定revision | 本次新规格 |
| `AGENTS.md`、`CLAUDE.md`、`README.md` | 重写为简洁新工程说明 | 旧版随归档保留 | 旧硬规则不再自动生效 |
| `.trae/`、`.cursor/`等工具配置 | 逐文件检查，保留有效工具，删除旧业务规则 | 必要配置归档 | 防止隐藏规则继续指向旧系统 |
| `dist/`、`.fc-package/`、deploy_pkg、缓存 | 删除并由新构建再生成 | 不需作为源码保留 | 避免发布旧产物 |
| 真实成交、账户、持仓批次、现金 | 不删除，迁入新数据库 | 私密原始备份 | 真实事实不可重造 |
| 旧建议、旧模拟标签、旧模型 | 不作为新生产资产直接启用 | 研究档案，标记不兼容 | 标签和模型合同已变化 |
| 原始市场数据、原文 | 核验授权/哈希/时间后可重用 | 原始版本保留 | 数据资产与算法分开 |
| 用户提供的公式/PDF资料 | 作为研究资料显式导入或隔离归档 | 保留原始来源 | 不属于随手清理的构建垃圾 |

“只保留配置”适用于重建分支的旧应用代码清理边界；它不意味着只靠配置就能运行完整平台。新代码、文档、测试随后按06重新创建。

## 4. 分支与快照步骤

### 4.1 建立恢复点

生成机器可读manifest：相对路径、类别、是否tracked、文件大小、SHA-256、计划动作、敏感级别。敏感文件只记录存在性和安全存储引用，不把内容或可暴露密钥的差异放入普通报告。

非敏感tracked/untracked工作区保存到隔离快照；秘密配置存独立私密位置。对若干代表文件和一个删除文件做实际恢复验证。

可以创建旧系统归档分支/标记，但不能把整个未跟踪目录无审查 `git add -A`。发布到远端前先排除密钥、真实数据、大训练产物。

### 4.2 创建重建分支

从已记录基线创建`rebuild/platform-v1`类分支，在该分支应用显式删除清单。旧生产部署可继续运行，开发树无需保留旧业务。

清理执行前输出dry-run：删除文件、保留文件、重写文件、无法分类文件。只有清单已覆盖且恢复验证通过才执行对应删除，不使用无目标的全目录通配清空。

### 4.3 新根文档

新的README说明产品定位、开发命令、架构和文档入口。新的AGENTS只保留：

- 阅读本设计revision；
- 模型与Agent联合核心；
- 模块依赖边界；
- 账户/时间/交易事实不变量；
- 当前实际测试与部署命令；
- 禁止秘密入库和旧链路回流。

文档不再列数十条历史补丁。具体规则放schema、测试和对应领域分册。

## 5. 数据迁移

### 5.1 迁移范围

必须迁移：用户/账户身份映射、真实现金流、持仓/批次、真实成交、费用、未完成人工计划、真实执行关联。

可选择迁移：自选、有效研究笔记、通知偏好。模型端点与数据配置通过新密钥引用重新建立，不能把旧明文配置作为普通JSON返回前端。

不直接迁移为生产有效：旧AI建议、旧监控状态、旧动作分数、旧公式排名、旧训练标签、旧模型清单。可作为历史资料查询，明确legacy来源。

### 5.2 映射策略

| 旧事实 | 新对象 | 校验 |
|---|---|---|
| holding/closed | position_lots与期初事实/历史成交投影 | 总股数、可卖日期、成本来源 |
| transactions | executions/cash_entries | 时间、方向、数量、价格、费用、去重 |
| account现金 | 现金分录与期初余额 | 期初+流水=期末 |
| executionPlans | execution_plans及reservations | 已完成与待执行状态，不复活取消计划 |
| executionAttributions | 真实成交关联/历史归因 | 原决策不兼容时保留来源引用 |
| 自选列表 | watchlists | 去重、证券身份、监控不自动启用 |

缺少交易明细时不要倒推出虚假成交来满足新Schema。建立带原始来源的期初持仓；报告“此前绩效不可完整复算”。

### 5.3 幂等与审计

每条迁移记录有migrationRunId、sourceObjectId、sourceHash、targetId、status和错误。重复执行相同快照不重复写入。

迁移分提取、规范化、验证、暂存、提交五步。验证失败的账户整体保持未切换，不能一半持仓迁入、一半现金仍在旧系统。

### 5.4 对账

逐账户验证：

- 期初现金 + 所有现金流水 = 期末现金；
- 每股期初数量 + 买入/转入/送转 − 卖出/转出 = 期末数量；
- 总数量、可卖数量、锁定批次一致；
- 费用合计与原始记录一致；
- 未完成计划与预留不重复占用；
- 实际成交只关联一次；
- 新旧单位和费用口径差异有解释。

金额允许的舍入差必须由规则证明，不能用笼统“误差1%可接受”放过资金问题。

## 6. 生产切换

1. 新平台在隔离环境完成全部关键验收，使用合成账户。
2. 新模型、Agent协议和策略包通过发布门禁。
3. 进入维护窗口，旧账户写接口只读，停旧FC Timer、GitHub计划任务和残留Worker。
4. 记录旧系统最后写入水位，等待/终止在途写任务并核对存储。
5. 提取最终增量，执行幂等迁移与逐账户对账。
6. 激活新账户事实源和新联合版本，切换域名入口。
7. 新前端清理旧Service Worker及旧私有缓存，不自动回写旧localStorage账本。
8. 用测试账户执行联合研究、计划、成交、复盘路径；真实账户仅只读核验。
9. 验证实际数据时间、当前版本、任务健康与通知；记录切换完成。

切流后新系统是唯一写入方。迁移适配器不再被正常请求加载。

## 7. 回滚

| 时间点 | 允许回滚方式 |
|---|---|
| 新系统尚无真实新写入 | 恢复旧入口及旧调度，取消新写权限 |
| 新系统已有新成交 | 回滚兼容新schema的应用/模型版本，保持新账本 |
| 新数据库严重故障 | 使用已演练备份/PITR恢复并对账，不用旧应用快照覆盖 |
| 联合模型/Agent协议异常 | 原子恢复上一完整联合包，不能混用新Agent旧模型 |

需要回到旧应用且存在新成交时，必须先有经验证的反向迁移工具，否则保持维护状态。不能以“可以git回滚”替代数据恢复方案。

## 8. 仓库更新与最终清理

按语义提交：重建规格、旧系统清理、新工程骨架、各纵向切片、迁移切换。大清理与新行为实现分开提交，方便核查遗漏。

正常推送重建分支、通过检查后更新主分支；不需要重写远端历史或强推。最终检查Git树、新构建包和部署产物三者均无旧业务入口。

删除验收：

- 没有对旧src/api/shared/qlib-service的import；
- 没有旧action式接口被新前端使用；
- 没有旧本地账本向云端回写；
- 没有遗留旧定时器继续写数据或训练；
- 没有根规则指向旧设计；
- 新测试只验证新合同，必要历史事故已转成小型新场景；
- 归档资料不出现在新用户导航，不参与生产预测。

恢复点的保留时间由存储成本和回滚窗口决定，默认至少跨过一次完整发布观察周期。真实事实和审计不因代码归档到期而删除。
