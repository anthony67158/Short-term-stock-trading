# 机会雷达技术计划

> 依赖规格：`docs/机会雷达融合规格.md`
> 状态：Approved，进入实施

## 一、架构选择

采用“保留原始生产器，新增确定性聚合层”的方式：

```text
板块前瞻快照 ─┐
盘中/收盘公式 ─┼─> shared/opportunityRadar.js ─> /api/opportunity_radar
尾盘正式结果 ──┘                                  │
                                                   ▼
                                      OpportunityRadar.jsx
```

理由：

1. 三个来源已有独立定时任务、锁、缓存和失败恢复，不应重新实现。
2. 聚合逻辑是纯函数，可离线测试，不需要 LLM。
3. 前端只消费统一合同，避免继续维护两个并列模块的状态和视觉层级。
4. 原接口继续服务个股详情、定时器和兼容路径，迁移可回滚。

## 二、主要模块

### 2.1 `shared/opportunityRadar.js`

职责：

- 判断交易阶段和默认视图。
- 校验各来源新鲜度。
- 按股票代码合并公式、尾盘与板块信息。
- 生成统一 `entryPlan`、`exitPlan`、`sourceSignals`。
- 分配 `READY / WAIT_TRIGGER / SECTOR_WATCH / AVOID`。
- 按确定性优先级排序。
- 输出三个 lane 和摘要。

该模块不得：

- 发网络请求。
- 读取环境变量。
- 调用 LLM。
- 修改输入对象。

### 2.2 `api/opportunity_radar.js`

`GET`：

- 校验账号身份。
- 并行读取 `readSectorForecastBootstrap()` 与
  `readFormulaSelectionState()`。
- 复用公式状态中已有的尾盘结果，避免重复读取 OSS。
- 使用 `Promise.allSettled` 形成局部降级。
- 调用纯函数生成统一快照。

`POST action=refresh`：

- 校验账号与视图。
- 根据交易阶段启动现有来源任务。
- 各来源独立执行并独立返回结果。
- 返回聚合任务状态，不等待其它来源失败后重跑。

第一阶段若直接复用现有同步生成函数导致请求过长，则保留统一 UI，
由前端并行调用已有生成接口；不得为了接口形式牺牲任务可靠性。

### 2.3 `src/opportunityRadarClient.js`

职责：

- 加载统一快照。
- 启动当前视图所需的来源任务。
- 统一超时和错误文本。
- 轮询聚合任务状态。
- 保留最近成功快照，瞬时网络失败不清屏。

### 2.4 `src/components/OpportunityRadar.jsx`

容器职责：

- 管理 `layout / intraday / next` 视图。
- 根据市场阶段选择默认视图。
- 展示统一刷新状态与局部错误。
- 渲染方向带和个股列表。
- 复用 `SectorForecastSettings` 的自动计划配置。

拆分展示组件：

- `OpportunityRadarSummary.jsx`
- `OpportunitySectorStrip.jsx`
- `OpportunityCandidateRow.jsx`
- `OpportunitySourceStatus.jsx`

单个展示组件只接收结构化数据，不自行请求。

## 三、实施顺序

### 阶段 1：纯融合合同

新增 `shared/opportunityRadar.js` 和单元测试。

验证点：

- 跨来源同股去重。
- 三视图归类正确。
- 无完整价格合同时不能进入 `READY`。
- 退出计划完整。
- 旧数据降级。

### 阶段 2：聚合读取 API

新增 `api/opportunity_radar.js`，只做只读聚合。

验证点：

- 三来源并行读取。
- 任一来源失败仍返回 `200` 和部分结果。
- 未登录返回 `401`。
- 不产生 LLM、行情或 OSS 写入。

### 阶段 3：统一前端

新增 `OpportunityRadar` 及展示组件，在 `TodayTab` 中替换两个旧入口。

验证点：

- 页面只保留一个机会模块。
- 三个视图均可切换。
- 每只可操作股票都有完整买卖计划。
- 空态、加载、局部失败和过期状态完整。

### 阶段 4：统一刷新

接入现有板块、公式和尾盘生成接口，按时段并行调度。

验证点：

- 盘中刷新不等待尾盘任务。
- 盘前只复核隔夜证据。
- 收盘后不重复生成已有尾盘正式版。
- 任一路失败不会取消已完成来源。

### 阶段 5：迁移与收口

- 保留旧组件文件但从页面卸载，便于回滚。
- 更新旧 UI 契约测试为统一模块契约。
- 更新 `docs/DESIGN.md` 中“今日决策”的模块说明。
- 稳定后再单独删除死代码，不与首轮上线混在一起。

## 四、风险与处理

| 风险 | 处理 |
| --- | --- |
| 三来源日期不一致 | 每条候选记录来源日期，跨日结果只能复盘，不能执行 |
| 同时刷新导致外部行情压力 | 来源任务独立并发；复用现有缓存、锁和已完成快照 |
| 板块名称映射不稳定 | 优先代码匹配，名称/概念标签只做兼容回退 |
| 尾盘与普通公式重复 | 股票代码去重，保留多个来源标签，按时段选择主计划 |
| 入场有价但退出不完整 | 直接降级为 `WAIT_TRIGGER` 或 `AVOID` |
| T+1 导致止损无法当日执行 | 明确显示下一可卖时段，不伪造可执行动作 |
| 老测试依赖两个模块 | 先新增统一测试，再更新入口测试，保留底层组件测试 |

## 五、验证

每个阶段运行：

```bash
node --test test/opportunity-radar-*.test.js
npm run build
```

最终运行：

```bash
npm test
npm run harness:sector
npm run build
```

浏览器验收：

- 视口：`320x812`、`768x1024`、`1024x768`、`1440x900`
- 主题：浅色、暗色
- 状态：加载、部分失败、空结果、生成中、正常结果、过期结果
- 检查：无横向溢出、无卡片套卡片、无重复标题、无非语义红色。

部署：

```bash
npm run build
npx vercel --prod --yes --token "$VC_TOKEN"
npm run package:fc
set -a; . ./.env; set +a
npx @serverless-devs/s deploy -y
```
